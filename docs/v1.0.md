### 已发现并处理的问题

- **failed → passed**：首次原生移址复查冻结快照时，Git 读取超长 `packed-refs` 失败；在4处 Windows Git 进程入口增加命令级 `core.longpaths=true` 后，实际262字符路径及原生移址通过。没有改全局 Git 或原仓库配置。
- **blocked**：更深路径的仓库发现仍受 Git for Windows 限制，涉及 `.git` 及其内部路径。普通/extended 路径及显式 Git 目录参数的隔离实验尚无可用局部解法。dev.3首次使用更长验收目录时，Git错误向上发现外层仓库，被现有根路径校验拒绝；改用较短全新隔离根后7/7通过。保留两份证据，不声称任意 Windows 深度可用。
- **failed → passed**：界面最初用配置 ID 和展示标题构造执行附件，与真实 reader 的执行 skill ID 不符；现由真实 read policy/catalog/selected reader 验证精确身份。首次无共享授权时的服务商下拉空选项也已修正，未把空授权当成默认共享。
- **测试夹具修正**：首批 group fixture 共用了可变 display 对象，异常值测试污染后续测试；改成各次独立声明后通过。main VM 历史路径断言因跨 realm Array 原型不同失败，改为比较实际路径值；未削弱产品断言。首份原生准备脚本缺真实 Catalog，修复后才启动 Electron；失败目录保留。
- **独审发现后修复**：激活在本地预检失败时也会写入丢回复标记；现先核对实际 tested 状态和来源，真正派发前才记录标记。新项目曾经通过通用 upsert 存在检查/写入竞态；现使用 worker 自身派生最小权限、同 Store 锁下的原子 create-only，既有项目冲突保持原值。独立复验3项 Node和2项实际worker/线程检查通过，原失败材料不改写。
- **独审发现后修复**：旧生成器使用裸文件名，引用读取器无法自动展开完整指导；现使用真实相对Markdown链接并独立验证最终ZIP。合法括号文件名曾被regex静默截断，现采用有界平衡/转义解析；执行 skill 正文原缺输出名和判据，现从绑定事实生成自足正文，真实新任务仅凭该正文成功运行。
