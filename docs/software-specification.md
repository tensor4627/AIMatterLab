# AIMatterLab 软件规范

AIMatterLab 0.1.1 源自 GPU Sampling Studio。用户在同一工作区中与 Agent 准备计算、核对输入和资源、执行作业并追踪结果。第三方开发者可将已有软件按工具包契约交付，为用户增加工具与工作流。

本版沿用原软件自 1.0.1 起确定的前端、后端和 Agent 职责，以及工具声明、中立契约、命令绑定和一致性检查。桌面负责交互与索引，worker 管理运行状态，Agent 在项目授权内调用工具。更改这些约定时须同步更新[代码架构](architecture.md)和版本记录，并保持原有数据与接口兼容。

主要流程：描述目标与委托范围 → 组织计算流程和资源 → 保存实际输入 → 执行并观察 → 根据错误修复和迭代 → 管理进度与产物。人工复核和短试运行是可选的工作方式；用户明确要求只准备、不运行时，必须停在对应阶段。

## 桌面启动与配置

Windows 用户可使用便携包或双击源码仓库根目录的 `Launch-AIMatterLab.cmd`。源码更新后继续读取同一个 profile。Agent 可以用内置 MCP 工具为当前项目保存并读取单文件技能，存储位置见[项目技能工作区](project-skill-workspace.md)。

已交接的 SSH 连接为各个对话保留独立终端，空闲时长可设，默认 60 分钟。退出桌面会关闭终端和连接，调度作业继续运行。集群登记保留实测工作区、作业服务和技能目录，更新服务时按文件哈希增量传输。

## 前端

- 提供会话与项目、计算流程、工具与计算资源、工作空间、任务结果和 Agent 对话的统一入口，支持必要的编辑、预览、终端及布局和外观设置。
- 会话分组支持删除；组内会话移至未分组，保留关联流程、运行记录及计算项目授权。
- 流程和参数可检查、可修改；按重要性和调整频率确定参数优先级，主要参数优先展示，其余放入二级菜单。单位、默认值、来源和实际采用值应明确。
- 缺项可定位，保存、复核、准备和执行有明确反馈。用户或已获委托的 Agent 可连续保存、形成当前输入快照并执行；未做 AI 复核、旧复核过期和建议参数范围以 warning 展示，不统一禁用执行。实际必需的文件、命令、资源及权限仍按操作检查。
- 如实展示工具调用、运行进度、错误、过期和未知状态，区分接入验证、环境配置、程序执行和科学有效性；保留会话及未发送草稿。
- Agent 对话和历史消息支持 Markdown 标题、加粗、表格。工具调用单行显示，连续调用默认折叠，可展开核对细节和操作。
- 渲染进程不直接访问 Node、文件系统、凭据或执行程序；特权操作经过主进程的类型化接口及请求来源校验。
- 桌面宽屏首次启动同时显示导航、内容与 Agent；普通会话也可同时观察终端，窄屏保留显式面板切换。终端提示和状态行不得遮挡最后一行输出。
- 右侧 Agent 默认展开，可调宽和主动收起；记住用户布局偏好。页面切换保留当前对话、草稿、阅读位置和活动，窄屏优先收左导航。会话首次打开进入最新消息，返回时恢复各自消息锚点、偏移及跟随状态；阅读旧消息时新消息不抢滚动位置。
- 实时消息与历史回放使用同一映射，保留命令、文件变更、工具结果的身份和顺序。查看运行名称进入该次运行详情并保留当前聊天；只有明确的“打开关联会话／流程”操作切换工作上下文。
- 消息显示身份同时包含会话、轮次和原始条目身份；提供商重用轮内计数不得覆盖前一轮回复。旧格式历史在读取时兼容，工具原生调用标识、回复匹配和审批身份保持原样。
- 已确认的当前作业服务可读取运行记录，不以当前聊天已绑定计算项目为前提。记录读取单独核对所选连接和服务身份，不恢复或替换流程的执行来源，不授予提交、取消或续算权限。相同来源的旧记录显示观测时间和 warning，仍可核对并打开；切换来源时隔离迟到结果，不能把其他服务的同名运行当作当前记录。
- 同一处问题集中显示简洁摘要，细节可展开；“停止助手”“取消运行”“收起终端”分别命名。运行使用不可变输入，用户可同时编辑下一版草稿；未确认的提交仅限制该次重复副作用，不冻结其他工作。
- 保留石墨灰和淡紫色的视觉体系，以留白、对齐及简洁标题组织信息；避免重复标题栏和嵌套边框。主要操作在深浅主题、1366×768、1024×768 与放大字号下可见、可用，状态不能只依靠颜色。

## 后端

### 工具组

工具组由工具组成。每个工具须具备五项定义：

1. **输入输出资源说明和管理**：明确必需和可选的输入输出、格式及约束，所有可选项具有默认值或明确默认行为；说明须同时包含在人类操作说明和 Agent 接口中。
2. **执行环境声明**：说明 CPU/GPU、依赖、并行支持和运行要求。
3. **最小测试用例**：用最简单配置检查输入输出、安装和环境，明确预期输出及通过标准；其目的是验证用户运行环境可用、声明的计算能够运行，不承担代码正确性验证，代码正确性由原软件发布流程验证。
4. **操作说明与 Agent 接口**：提供人类手册及可实际操作工具的 skill/MCP。
5. **程序代码及其获取方式**：提供实现全部声明功能的程序、代码或完整获取方法。

#### 交付与接入

工具接入面向开发者：满足五项定义，在声明流程中验证安装与功能可用，生成可迁移的交付 skill，说明如何安装、测试和操作工具。五项定义同时约束内部工具与第三方交付包；`engine` 等声明只描述真实实现，不自动创建适配器。

工作空间以 `工具名-package` 保存原软件 Git 仓库、交付 `SKILL.md` 和 `工具名-tests`。接入保留原仓库布局，补充说明和封装写在仓库之外；使用包内相对路径重定向到作者已有的接口、说明和测试。

`工具名-tests` 包含整套测试介绍 Markdown、各功能子目录、最简说明及必要脚本或重定向入口。全部测试资源须随完整交付包存在，可保留在原仓库位置。逐功能记录 `passed / failed / blocked / not_run` 及原因。接入测试只覆盖用户环境可用性和声明计算的可运行性，不纳入无关、重复或低级的原仓库回归测试；代码正确性由原软件发布流程验证。

源码与原有测试按原 Git 仓库同步，交付 skill 和重定向须匹配对应提交；更新后重新验证。已有任务保留原版本，仓库同步成功不代表升级验证通过。

**内部工具（AimLab）**：AimLab 自研工具（例如 GPU-Sampling）不按上述第三方交付包形态接入，而是在自身主工作分支维护 `aimlab-tools/` 声明（机器可读 manifest、交付 skill、精简手册、测试映射），声明随源码 commit 一起提交。AIMatterLab 侧按候选 commit 校验声明、路径闭包和测试映射；登记来源、安装观察和声明测试分别记录，未测试的候选可在已有授权内继续配置和尝试，不能因此标为已验证。AIMatterLab 不自动 pull，不原地替换旧任务依赖的版本。当前实现为只读检查脚本，以及主进程 `tools.aimlab.*` typed 登记路由（只登记来源 commit 与声明身份，不复制工具源码；安装/测试仍为 `not_run`）。详见 [AimLab 内部工具声明与接入检查标准](aimlab-tools-internal.md)。

**联用接口交付责任**：开发者在 `aimlab-tools/` 中提供本工具真实支持的联用接口、调用方式及相关使用 skill，并给出接口/模式版本、运行时依赖、产物约束与可重定位的最小联合测试。预置需考虑的联用类型包括所有已声明支持接口的**力场与 MD 引擎联用**、**增强采样工具与 MD 引擎联用**；按实际接口实例化组合，不推定任意工具或版本两两兼容。开发者不需要预先为用户构建所有联用环境；由 AIMatterLab 在用户配置环节核验并配置。skill 是操作指导，不能替代可核验的接口与实际测试回执，也不提供额外执行或授权权限。

#### 流程组织

多个工具的输入输出构成上下文，按因果和供需关系组织为工具组。工具组须有规范的流程定义，明确各步骤的输入来源和输出去向，按输入输出匹配执行，从最初输入联通到最终产物。

工具组同时表达**阶段间产物交接**与**阶段内部的实时运行依赖**。前者可以分任务、分环境执行，但须在实际消费者中验证同一产物；后者须按接口调用位置形成共同运行单元，例如 PyDyn 每步调用 HotPP 受力计算时，相关运行时组件必须在同一进程及兼容环境中工作。生产者的训练依赖不必进入只读取导出模型的 MD 运行环境；应按实际模型加载模式确定依赖闭包。

AIMatterLab 须核验所选完整组合，而非仅核验各连接对。力场＋MD 与增强采样＋MD 分别可用，不能推定力场＋增强采样＋MD 三者同时可用。由同一进程承载的完整闭包应统一求解约束；阶段可分离的部分可以拥有独立环境。环境以具体组合、模式和版本配置，可复用实际等价且已验证的配置，不要求全部工具共用唯一环境。接口、环境和联合测试要求见 [工具依赖组审查与配置要求](development/tool-dependency-groups.md)。

### 渐进配置与校验原则

- 操作许可、程序执行状态和检查发现分别记录。项目已有授权是持续委托的边界；普通输入修改、重建、会话恢复和明确失败后的新尝试不重新要求相同授权。MCP、模型回复和 skill 均不能授予或扩大项目授权；用户可随时停止或收回使用权。
- 未复核、组合尚未验证、环境变化和科学检查失败是可追踪的诊断。允许在授权范围内尝试、观察真实错误、修复并重新运行；不得把检查改成 `passed` 来获得执行资格。证据过期标注来源及原因，不抹去原始结果。
- 默认允许先接入、讨论和诊断，再由用户与 Agent 逐步配置。工具清单不完整、环境未配置或可修复的兼容性差异以 warning 展示，保留已授权的终端、文件操作和可用接口，不作为连接、交接或讨论配置的前置门槛。
- 按具体操作检查实际必需条件；缺少某项依赖仅限制依赖它的操作。Agent 可在用户已授权的资源和范围内查找已有环境、安装或配置所需工具、修复流程；用户要求改进 AIMatterLab 并授权源码工作区时，可通过受控终端与文件接口准备可审阅的程序修改。
- 界面明确区分“连接已建立”“工具／环境待配置”“可以执行”与“科学验证通过”。warning 不伪造能力或运行结果；身份不匹配、授权已收回、破坏性操作和未知结果不重放仍按其实际边界处理。验证要求逐步收紧或放宽须依据完整流程测试证据。
- 实际无法形成命令、越过已授权路径或资源、输入快照身份冲突及已知不可加载的产物，可以使这次操作失败；错误应带回当前任务供修复。偏置必须加载序列化产物并检查真实目标环境；显式选定的 AOTI 不兼容必须失败，不替换后端。这些执行前提与科学有效性检查分别记录。
- 提交前保存唯一尝试与实际输入；提交回执未知时核对原尝试，不自动重提。取消先持久化用户意图，再发送远端命令；“请求取消”“远端确认”和“观察到终态”分别记录。程序已退出但科学检查失败时，程序终态保持已知。
- 结果列表返回带观察时间的当前文件元数据，不为浏览列表完整读取大型轨迹。需固定证据时另建不可覆盖的内容快照，大小和摘要来自同一份字节；复现导出列明包含、缺失与截断的文件和日志。

### 计算资源

计算资源提供工具所需的硬件和软件环境，包括本地算力和集群，分为连接配置与工具计算环境配置。

- **连接配置**：管理用户提供的本地及集群连接，保存版本化连接配置，维护多个算力管道的可用性。连接是资源入口；共享终端、作业服务和文件访问是该资源可提供的能力，分别核验和展示状态。
- **认证与授权分层**：SSH 登录认证、作业服务登记、当前 Agent 使用权、项目计算授权及单次正式执行批准分别管理。用户完成密码、验证码和主机信任确认；活跃进程、终端提示符或服务登记均不能替代本次认证证据。登记资源具备作业服务能力不增加系统或项目权限，也不自动交接给 Agent。
- **认证终端尺寸变化**：本地启动身份帧以同一随机 nonce 的起止标记限定，允许终端产生物理折行；收到完整有界帧后才解码。帧未完整时保持等待，错误或异源帧拒绝；进程、客户端、目标和控制 socket 的后续身份核验不变。
- **共享终端与服务并存**：资源具备作业服务能力后，仍须保留普通 shell、命令历史、实时输出以及人与 Agent 交接操作的便利性。作业服务是附加能力，不得以占用交互终端、永久只读或要求先断开服务作为正常使用共享终端的前提。用户可在终端操作的同时，由获准的 Agent 通过服务接口管理任务。
- **终端回放与诊断**　用户和 Agent 按游标分段读取长会话，下一页从上一页实际返回的最后一条记录继续。终端读错在原面板显示，只有当前连接、终端和操作权版本的成功读取才能解除对应提示。队列与作业状态继续以原作业服务为准。
- **通信与协议隔离**：交互式登录后的交接默认复用已授权原终端，串行完成服务交换与普通命令，不以网关开放第二 SSH 通道或 exec 为前提。只有确认 shell 就绪后才短暂使用通道；服务协议不得进入普通输出，每次交换完成须确认原 shell 恢复后才释放输入。前台程序未结束或结果未知时，不得注入服务命令、解除协议锁或重放请求。独立通道连接仍可显式使用，不把另开认证、再次登录或切换主机冒充原连接复用。
- **操作权与能力授权**：同一个交互终端的人与 Agent 输入权仍须交接，避免同时输入；终端操作权与作业服务调用权在后端分别核验；正常交互只需一次“交给 Agent”，同时启用此连接的终端和可用作业服务，点击“我来操作”收回本次交接的两项使用权。服务调用权绑定准确的资源、服务连接、提供商和当前对话／任务及项目上下文。收回某项 Agent 使用权、切换上下文或能力失联时，使对应的旧授权和待发操作失效；不因此结束仍有效的共享终端或取消已提交作业。服务登记和 skill 不授予任一能力的操作权。
- **服务首次配置与日常复用**：正常流程为保存主机与用户 → 在终端完成 SSH 登录并保持普通终端 → 用户点击“交给 Agent” → 才开始远端作业服务检查、首次部署并登记或已有缓存复用。未交接时不自动启动远端 Python、探查或传输服务代码。首次完成后保存该连接的服务身份、环境、版本和目录等信息；以后再次交接时优先核验并复用，不重复传输全量 worker 或升级版本。服务确实停止时，可在本次明确交接中启动同一已校验缓存 worker 一次，不重发作业；未知结果不自动重试。服务连接和 Agent 使用权分别核验；身份及健康检查通过即可记录连接并交接。工具清单不完整显示 warning，允许继续讨论和配置，不标记为科学执行已就绪。未确认／未完成持续显示状态，明确失败展示原因，终端继续可供协助修复。维护和调度器设置保留在高级连接设置。
- **版本差异提醒**　桌面比较随包发布的 worker 指纹与本次已核实的远端 worker。版本不同时显示提醒，用户和 Agent 可以继续使用旧版实际提供的工具，打开记录、准备及提交已获准的任务。提醒和该连接的作业服务设置均提供更新入口。用户进入设置可以查看状态，点击更新才触发部署。
- **登记与运行版本核对**　同一认证连接上，另一台桌面可能已更新过远端服务。日常交接优先核对原登记。遇到明确的健康不一致时，可只读核对同一主机、用户、服务根及端口上已运行的本包 worker。仅在规范路径、完整清单、服务角色和实时健康回执吻合后更新该连接的登记。身份或操作结果仍待核对时，保留终端，显示作业服务的具体诊断。
- **明确更新服务**　用户选择更新当前服务时，可复用已经交接的原 shell。主进程从真实服务记录取得原终端身份，核对预期服务尝试、操作权和上下文，在原终端结束旧的服务传输并更新。更新结束后重新核对运行中的 worker。未知停止或启动结果只核对原尝试。既有配置、已提交作业和授权范围保留。更新期间撤销授权立即生效。原终端与服务的组合交接关系随确切的原授权延续，更新后收回原终端仍撤销该组合服务权限，独立授予的服务权限分别管理。
- **身份与可用性观察**：健康检查预算按实际传输区分，并保持有界；迟到结果不能恢复已替换的连接。完整缓存指纹只在同一已测量身份及连接配置上保留，不能从短 ID 推断或沿用到其他服务。服务短暂借用终端进行协议交换时，显示实际操作方与忙状态，不把输入暂不可用误称为操作权归还。
- **断开后的服务维护**：服务已经确认断开或尚未建立时，保留显式更新到当前软件服务的入口；仅使用已经核验的原认证连接，不重新认证或自动授予 Agent 权限。服务连接中、停止中或结果未知时不能走此入口，先核对原尝试。
- **环境配置与 skill**：优先复用目标资源已有的 Python、Conda／Anaconda、venv 或站点 module 环境，实际检查解释器版本及 SQLite 等服务依赖。服务解释器与科学引擎解释器分别登记，不将服务最低版本要求扩展为所有引擎的统一要求。环境激活方法和解释器选择绑定具体连接，按保存的配置准备服务运行环境；配置流程及日常操作写入相应环境配置 skill。可执行激活脚本保存于私有连接配置，派生指引不包含凭据、认证会话或脚本正文，也不自动扩大安装与执行权限。
- **状态与生命周期**：分别维护基础连接、交互终端、服务传输、远端 worker 和作业状态。断开服务传输不关闭共享终端、不停止远端 worker、不取消作业。原终端串行模式结束终端时报告服务传输失联，worker 和作业继续存活；独立通道模式结束终端不停止独立服务通道。明确结束整个 SSH 连接时撤销临时传输和授权，保留服务登记与真实作业状态；再次登录须重新认证和交接。
- **故障与恢复**：单个能力失败时只将对应能力标为不可用或未知；基础 SSH 连接断开时，其上的相关通道分别报告失联。只有独立确认仍可用的终端通道才允许继续交互，不能通过解除协议占用通道的只读锁来恢复终端。已发送但未确认的服务请求须核对原尝试与回执，不自动重放；恢复作业须核对原运行身份，不重新提交未知任务。
- **当前连接实现边界**：交互式登录从 dev.24 起通过原终端串行访问已核验 worker；原始终端身份、操作权、协议恢复锁和未知不重放约束均保留。不另开 SSH 认证。显式独立通道仍可用于支持该能力的连接；Windows／WSL 客户端与凭据命名空间继续明确选择。回环验证、实际学校登录、真实 Agent 工具使用和科学执行须分别报告。
- **工具配置**：由 AIMatterLab 面向用户实施。在其提供可用资源、队列等信息的协助下探测环境，读取工具交付的接口、使用 skill、环境声明和测试，解析所选联用组的完整运行依赖，配置兼容该运行单元全部成员的新版本化环境。核验实际模块与程序来源、版本、设备、模型格式/精度/物种/单位和必要 ABI，完成单工具、产物消费及完整组的最小联合测试后，生成绑定真实组、模式和环境的执行 skill。缺少接口、对应测试或执行能力时保持 `blocked/not_run`，不由文档推定组级可用。
- **当前工具配置实现边界**：上述科学联用组配置是产品要求；现有通用配置与工具组执行器仍限定固定 CPU `installation.check` 工程 reference。现有声明字段与契约须通过兼容的版本化扩展承接这些关系，不能仅修改指导文字或向 v1 添加未知字段就宣称实现。
- **版本与运行保护**：显式登记环境及版本，不自动切换引擎分支；显式选择的 AOTI 不兼容时失败，不降级。worker 维护权威作业状态，桌面维护索引；关闭桌面不取消已提交作业，未知状态不自动重提。
- **启动与恢复**：创建 supervisor 前持久化唯一启动认领；进程尚未确认时保持 `unknown`。恢复必须核对认领、进程身份与回执，已有启动证据的任务不得重新启动。取消请求持久化并与子进程创建排序，旧格式已提交任务继续保留。

### 工作空间

- 管理输入输出上下文，对文件筛选、保留、组织、保管和分类；维护工具交付包、版本、执行 skill 及相关记录。
- 按任务流（workflow，也称计算流程）组织任务；每个流程包含至少一套工具组，组织一个计算任务。
- 引导用户配置工作区，为流程配置的工具组建立主文件夹，并按实际任务阶段或共同运行单元建立执行子文件夹。同进程的 MD、力场或偏置组件属于同一次执行，不为每步实时调用虚构独立提交的作业；独立训练、导出或分析阶段仍可单独组织。
- 维护任务面板和任务进度，关联实际版本、环境、日志及产物。真实环境路径和连接保存在用户私有配置，凭据只使用受控引用。

## Agent

Agent 通过服务商适配接入大模型，提供账户、模型及实际支持的推理参数配置。模型推理资源与科学计算资源分别管理。

- 理解目标、选择工具并组织流程，复用已有结构、模型、数据和中间产物；普通对话不自动建立流程，同一会话通常持续维护一个流程。
- 操作绑定当前会话、项目、流程和计算来源，通过受控接口准备输入、修改参数、准备草稿、查询状态与结果；保留用户修改，阻止迟到请求跨流程生效。
- 遵守项目和服务商授权，MCP 不改变项目权限。在用户已委托的目录、资源和额度内连续读取、修改、构建、检查、执行、取消自己的任务及修复后重试；超出范围才处理新增许可。共享终端仅在用户交接范围内操作，认证凭据不进入模型上下文。用户明确指定的审阅或不执行边界优先。
- 当前任务规划意图逐轮同步，不沿用旧历史状态。规划开关、终端交接、工作流工具与正式执行批准独立；选中终端时如缺少工作流工具，明确说明具体能力限制，不能把它误报为规划开关未开启或自动切换计算资源。
- 用户显式交接终端但尚无真实 Agent 会话时，可以建立并选定真实空会话后交接原终端；此过程不发送模型消息、不重开 SSH，也不自动处理认证。期间接管、关闭或切换上下文使未完成交接失效。
- 以实际文件和回执反馈计划、调用、缺项、失败及结果，不虚构安装、环境、任务或科学结论；缺少条件时引导用户补充。
- Provider 的超时不等于底层轮次结束。同一会话未确认结束前隔离旧轮与迟到消息／工具结果，保留中断和核对入口；不能自动重发消息或作业，独立会话和已提交 worker 作业继续正常管理。
- 历史写入、实时显示、恢复和支持导出采用一致脱敏边界。分片消息、工具结果、错误及旧历史均不得把凭据写回持久化记录；保留正常消息结构和科学数值。单条损坏记录应隔离并留下诊断，不使整个列表失效。
- “交给 Agent 修复”携带任务和运行身份、实际错误、输入版本、相关文件及最近修改。固定表单提供便利，不限制已授权通用终端与文件操作；成功的可复用方法可整理为 recipe 或 skill，并保留其实际验证范围。

### skill 生命周期

| 阶段 | 面向对象与产物 |
| --- | --- |
| 开发者接入 | 验证声明流程中的可用性，交付真实功能与联用接口、约束、最小联合测试及可迁移的使用 skill；不依赖作者机器的私有路径或配置。 |
| 用户配置 | AIMatterLab 在真实资源上解析完整联用依赖、配置兼容各成员的环境并跑完对应测试；执行 skill 绑定已验证的组/运行单元、具体模式、实际入口、环境、版本及产物身份。 |
| 日常执行 | 使用对应环境的执行 skill，包含正常操作所需的输入输出、参数、工作目录、命令和失败处理。 |

执行 skill 生成后，前置的交付、安装和配置指导封存，保留版本和记录，日常不再重复读取。bug 修复、环境变化或软件更新需要时重新读取相关指导，在已有授权内修复并更新实际记录；缺少组合证据标注未验证，不把执行指导当作扩大权限或证明科学有效性的凭证。

开发者接入操作见 [接入指南](../developer/README.md)；当前实现见 [代码架构](architecture.md)，实施依据见 [仓库重组方案](development/repository-reorganization.md) 与 [复审实施和验收清单](development/review-implementation-plan.md)。
