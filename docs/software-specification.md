# GPU Sampling Studio 软件规范

软件由前端、后端和 Agent 三部分组成：前端提供显示与操作界面，后端提供工具组、计算资源和工作空间，Agent 接入大模型推理能力，协助用户操作后端并通过前端展示结果。

自 `1.0.1` 起，本文描述的产品职责、工具接入语义（声明 / 中立契约 / argv 绑定 / conformance 与 parity 检查）及安全边界作为正式规范基线冻结；后续变更必须同步更新本文、[代码架构](architecture.md) 与版本记录，并遵守 1.0 起的向后兼容与版本化迁移约定。

主要流程：描述目标 → 组织计算流程 → 审阅输入与参数 → 配置计算资源及工作区 → 执行 → 管理进度与产物。

## 前端

- 提供会话与项目、计算流程、工具与计算资源、工作空间、任务结果和 Agent 对话的统一入口，支持必要的编辑、预览、终端及布局和外观设置。
- 流程和参数可检查、可修改；按重要性和调整频率确定参数优先级，主要参数优先展示，其余放入二级菜单。单位、默认值、来源和实际采用值应明确。
- 缺项可定位，保存、复核、准备和执行有明确反馈；输入变化后重新核对当前版本，正式计算由用户审阅后执行。
- 如实展示工具调用、运行进度、错误、过期和未知状态，区分接入验证、环境配置、程序执行和科学有效性；保留会话及未发送草稿。
- 渲染进程不直接访问 Node、文件系统、凭据或执行程序；特权操作经过主进程的类型化接口及请求来源校验。
- 桌面宽屏首次启动同时显示导航、内容与 Agent；普通会话也可同时观察终端，窄屏保留显式面板切换。终端提示和状态行不得遮挡最后一行输出。

## 后端

### 工具组

工具组由工具组成。每个工具须具备五项定义：

1. **输入输出资源说明和管理**：明确必需和可选的输入输出、格式及约束，所有可选项具有默认值或明确默认行为；说明须同时包含在人类操作说明和 Agent 接口中。
2. **执行环境声明**：说明 CPU/GPU、依赖、并行支持和运行要求。
3. **最小测试用例**：用最简单配置检查输入输出、安装和环境，明确预期输出及通过标准；其目的是验证用户运行环境可用、声明的计算能够运行，不承担代码正确性验证，代码正确性由原软件发布流程验证。
4. **操作说明与 Agent 接口**：提供人类手册及可实际操作工具的 skill/MCP。
5. **程序代码及其获取方式**：提供实现全部声明功能的程序、代码或完整获取方法。

#### 交付与接入

工具接入面向开发者：满足五项定义，在声明流程中验证安装与功能可用，生成可迁移的交付 skill，说明如何安装、测试和操作工具。五项定义同时约束内部工具与第三方交付包；`engine` 等声明只描述真实实现，不自动创建适配器。

工作空间以 `工具名-package` 保存原软件 Git 仓库、交付 `SKILL.md` 和 `工具名-tests`。接入保留原仓库布局，补充说明和封装写在仓库之外；使用包内相对路径重定向到作者已有的接口、说明和测试。

`工具名-tests` 包含整套测试介绍 Markdown、各功能子目录、最简说明及必要脚本或重定向入口。全部测试资源须随完整交付包存在，可保留在原仓库位置。逐功能记录 `passed / failed / blocked / not_run` 及原因。接入测试只覆盖用户环境可用性和声明计算的可运行性，不纳入无关、重复或低级的原仓库回归测试；代码正确性由原软件发布流程验证。

源码与原有测试按原 Git 仓库同步，交付 skill 和重定向须匹配对应提交；更新后重新验证。已有任务保留原版本，仓库同步成功不代表升级验证通过。

**内部工具（AimLab）**：AimLab 自研工具（例如 GPU-Sampling）不按上述第三方交付包形态接入，而是在自身主工作分支维护 `aimlab-tools/` 声明（机器可读 manifest、交付 skill、精简手册、测试映射），声明随源码 commit 一起提交。Studio 侧按候选 commit 执行接入检查，校验声明、路径闭包和测试映射；检查通过后仍须在候选环境完成真实安装和声明测试，全部通过才放行登记。Studio 不自动 pull，不原地替换旧任务依赖的版本。当前实现为只读检查脚本，以及主进程 `tools.aimlab.*` typed 登记路由（只登记来源 commit 与声明身份，不复制工具源码；安装/测试/放行仍为 `not_run`）。详见 [AimLab 内部工具声明与接入检查标准](aimlab-tools-internal.md)。

**联用接口交付责任**：开发者在 `aimlab-tools/` 中提供本工具真实支持的联用接口、调用方式及相关使用 skill，并给出接口/模式版本、运行时依赖、产物约束与可重定位的最小联合测试。预置需考虑的联用类型包括所有已声明支持接口的**力场与 MD 引擎联用**、**增强采样工具与 MD 引擎联用**；按实际接口实例化组合，不推定任意工具或版本两两兼容。开发者不需要预先为用户构建所有联用环境；由 Studio 在用户配置环节核验并配置。skill 是操作指导，不能替代可核验的接口与实际测试回执，也不提供额外执行或授权权限。

#### 流程组织

多个工具的输入输出构成上下文，按因果和供需关系组织为工具组。工具组须有规范的流程定义，明确各步骤的输入来源和输出去向，按输入输出匹配执行，从最初输入联通到最终产物。

工具组同时表达**阶段间产物交接**与**阶段内部的实时运行依赖**。前者可以分任务、分环境执行，但须在实际消费者中验证同一产物；后者须按接口调用位置形成共同运行单元，例如 PyDyn 每步调用 HotPP 受力计算时，相关运行时组件必须在同一进程及兼容环境中工作。生产者的训练依赖不必进入只读取导出模型的 MD 运行环境；应按实际模型加载模式确定依赖闭包。

Studio 须核验所选完整组合，而非仅核验各连接对。力场＋MD 与增强采样＋MD 分别可用，不能推定力场＋增强采样＋MD 三者同时可用。由同一进程承载的完整闭包应统一求解约束；阶段可分离的部分可以拥有独立环境。环境以具体组合、模式和版本配置，可复用实际等价且已验证的配置，不要求全部工具共用唯一环境。接口、环境和联合测试要求见 [工具依赖组审查与配置要求](development/tool-dependency-groups.md)。

### 计算资源

计算资源提供工具所需的硬件和软件环境，包括本地算力和集群，分为连接配置与工具计算环境配置。

- **连接配置**：管理用户提供的本地及集群连接，保存版本化连接配置，维护多个算力管道的可用性。连接是资源入口；共享终端、作业服务和文件访问是该资源可提供的能力，分别核验和展示状态。
- **认证与授权分层**：SSH 登录认证、作业服务登记、当前 Agent 使用权、项目计算授权及单次正式执行批准分别管理。用户完成密码、验证码和主机信任确认；活跃进程、终端提示符或服务登记均不能替代本次认证证据。登记资源具备作业服务能力不增加系统或项目权限，也不自动交接给 Agent。
- **共享终端与服务并存**：资源具备作业服务能力后，仍须保留普通 shell、命令历史、实时输出以及人与 Agent 交接操作的便利性。作业服务是附加能力，不得以占用交互终端、永久只读或要求先断开服务作为正常使用共享终端的前提。用户可在终端操作的同时，由获准的 Agent 通过服务接口管理任务。
- **通信通道隔离**：交互终端与作业服务使用彼此独立的通信通道，复用同一已认证 SSH 连接所提供的多通道能力。普通输入输出不得混入服务协议，服务启动、检查、停止或更新不得夺取交互终端的输入流。必须以真实传输能力验证认证复用，不能把另开 SSH、再次登录或隐式切换主机当作原连接的复用。
- **操作权与能力授权**：同一个交互终端的人与 Agent 输入权仍须交接，避免同时输入；终端操作权与作业服务调用权在后端分别核验；正常交互只需一次“交给 Agent”，同时启用此连接的终端和可用作业服务，点击“我来操作”收回本次交接的两项使用权。服务调用权绑定准确的资源、服务连接、提供商和当前对话／任务及项目上下文。收回某项 Agent 使用权、切换上下文或能力失联时，使对应的旧授权和待发操作失效；不因此结束仍有效的共享终端或取消已提交作业。服务登记和 skill 不授予任一能力的操作权。
- **服务首次配置与日常复用**：正常流程为保存主机与用户 → 在终端完成 SSH 登录并自动准备作业服务 → 点击“交给 Agent”交接使用权。SSH 登录完成并选中原连接后，立即自动检查缓存、首次传输配置 worker 并核对服务身份、版本、目录、端口、健康和工具，保存该连接的登记；后续登录自动复用已核验的缓存，不重复传输全量 worker 或升级版本。服务确实停止时，可在本次明确登录接入中启动同一已校验缓存 worker 一次，不重发作业；超时或身份未知不触发启动。环境维护和调度器设置留在连接编辑的高级设置，不要求额外服务连接、认证或交接步骤。服务准备失败保留已交接普通终端，便于 Agent 在用户授权内协助配置环境。
- **环境配置与 skill**：优先复用目标资源已有的 Python、Conda／Anaconda、venv 或站点 module 环境，实际检查解释器版本及 SQLite 等服务依赖。服务解释器与科学引擎解释器分别登记，不将服务最低版本要求扩展为所有引擎的统一要求。环境激活方法和解释器选择绑定具体连接，按保存的配置准备服务运行环境；配置流程及日常操作写入相应环境配置 skill。可执行激活脚本保存于私有连接配置，派生指引不包含凭据、认证会话或脚本正文，也不自动扩大安装与执行权限。
- **状态与生命周期**：分别维护基础连接、交互终端、服务通道、远端 worker 和作业状态。断开服务通道不关闭共享终端、不停止远端 worker、不取消作业；单独结束终端通道也不自动取消作业或停止独立服务通道。明确结束整个 SSH 连接时，撤销其上的临时通道及 Agent 授权，保留服务登记与真实作业状态；再次登录须重新确认认证和授权。
- **故障与恢复**：单个能力失败时只将对应能力标为不可用或未知；基础 SSH 连接断开时，其上的相关通道分别报告失联。只有独立确认仍可用的终端通道才允许继续交互，不能通过解除协议占用通道的只读锁来恢复终端。已发送但未确认的服务请求须核对原尝试与回执，不自动重放；恢复作业须核对原运行身份，不重新提交未知任务。
- **当前连接实现边界**：自 `1.0.2-dev.15` 起，受支持的 Linux／WSL OpenSSH 路径使用独立认证 master，并通过其真实多路复用能力分别打开普通 shell 与私有作业服务通道；后端保留独立输入与服务能力校验，界面通过一次“交给 Agent”完成统一交接。缺失 master 时从属通道直接失败，不另开连接认证。未证明支持多路复用的 Windows 原生客户端及历史嵌套路由明确标为受限；保留原配置，由用户明确选择受支持的客户端与路径。真实回环与隔离界面验收覆盖同次认证双通道并行、交接、独立关闭及故障；用户站点 MFA、真实集群、实际模型与科学作业须另行验证，不由本地工程检查推定完成。旧同 PTY 通道保留原有协议锁，不通过解除只读锁冒充新通道。
- **工具配置**：由 Studio 面向用户实施。在其提供可用资源、队列等信息的协助下探测环境，读取工具交付的接口、使用 skill、环境声明和测试，解析所选联用组的完整运行依赖，配置兼容该运行单元全部成员的新版本化环境。核验实际模块与程序来源、版本、设备、模型格式/精度/物种/单位和必要 ABI，完成单工具、产物消费及完整组的最小联合测试后，生成绑定真实组、模式和环境的执行 skill。缺少接口、对应测试或执行能力时保持 `blocked/not_run`，不由文档推定组级可用。
- **当前工具配置实现边界**：上述科学联用组配置是产品要求；现有通用配置与工具组执行器仍限定固定 CPU `installation.check` 工程 reference。现有声明字段与契约须通过兼容的版本化扩展承接这些关系，不能仅修改指导文字或向 v1 添加未知字段就宣称实现。
- **版本与运行保护**：显式登记环境及版本，不自动切换引擎分支；显式选择的 AOTI 不兼容时失败，不降级。worker 维护权威作业状态，桌面维护索引；关闭桌面不取消已提交作业，未知状态不自动重提。
- **启动与恢复**：创建 supervisor 前持久化唯一启动认领；进程尚未确认时保持 `unknown`。恢复必须核对认领、进程身份与回执，已有启动证据的任务不得重新启动。取消请求持久化并与子进程创建排序，旧格式已提交任务继续保留。

### 工作空间

- 管理输入输出上下文，对文件筛选、保留、组织、保管和分类；维护工具交付包、版本、执行 skill 及相关记录。
- 按任务流（workflow，也称计算流程）组织任务；每个流程包含至少一套工具组，组织一个计算任务。
- 引导用户配置工作区，为流程配置的工具组建立主文件夹，并按实际任务阶段或共同运行单元建立执行子文件夹。同进程的 MD、力场或偏置组件属于同一次执行，不为每步实时调用虚构独立提交的作业；独立训练、导出或分析阶段仍可单独组织。
- 维护任务面板和任务进度，关联实际版本、环境、日志及产物。真实环境路径和连接保存在用户私有配置，凭据只使用受控引用。

## Agent

Agent 通过服务商适配接入大模型，提供账户、模型及实际支持的推理参数配置。模型推理资源与科学计算资源分别管理。

- 理解目标、选择工具并组织流程，复用已有结构、模型、数据和中间产物；普通对话不自动建立流程，同一会话通常持续维护一个流程。
- 操作绑定当前会话、项目、流程和计算来源，通过受控接口准备输入、修改参数、准备草稿、查询状态与结果；保留用户修改，阻止迟到请求跨流程生效。
- 遵守项目和服务商授权，MCP 不改变项目权限。正式计算保留人工审阅执行门；共享终端仅在用户交接范围内操作，认证凭据不进入模型上下文。
- 当前任务规划意图逐轮同步，不沿用旧历史状态。规划开关、终端交接、工作流工具与正式执行批准独立；选中终端时如缺少工作流工具，明确说明具体能力限制，不能把它误报为规划开关未开启或自动切换计算资源。
- 用户显式交接终端但尚无真实 Agent 会话时，可以建立并选定真实空会话后交接原终端；此过程不发送模型消息、不重开 SSH，也不自动处理认证。期间接管、关闭或切换上下文使未完成交接失效。
- 以实际文件和回执反馈计划、调用、缺项、失败及结果，不虚构安装、环境、任务或科学结论；缺少条件时引导用户补充。

### skill 生命周期

| 阶段 | 面向对象与产物 |
| --- | --- |
| 开发者接入 | 验证声明流程中的可用性，交付真实功能与联用接口、约束、最小联合测试及可迁移的使用 skill；不依赖作者机器的私有路径或配置。 |
| 用户配置 | Studio 在真实资源上解析完整联用依赖、配置兼容各成员的环境并跑完对应测试；执行 skill 绑定已验证的组/运行单元、具体模式、实际入口、环境、版本及产物身份。 |
| 日常执行 | 使用对应环境的执行 skill，包含正常操作所需的输入输出、参数、工作目录、命令和失败处理。 |

执行 skill 生成后，前置的交付、安装和配置指导封存，保留版本和记录，日常不再读取。仅在 bug 修复或软件更新需要重新安装时，重新读取所需前置指导，完成实际检查与测试后更新执行 skill。

开发者接入操作见 [接入指南](../developer/README.md)；当前实现见 [代码架构](architecture.md)，实施依据见 [仓库重组方案](development/repository-reorganization.md)。
