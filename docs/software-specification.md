# AIMatterLab 软件规范

AIMatterLab 是面向用户的科学工作流桌面框架。用户给出想取得的结果和已有材料，Agent 在委托范围内补齐输入，选择已获准的计算资源，交付可追溯到实际作业的结果。用户可以只讨论、准备或审阅，也可以直接委托一次计算。

**弱校验是首要设计原则。** 用户明确要做什么，Agent 自主决定怎样完成。校验把与当前操作有关的边界、实际观察和缺项告诉 Agent，让它能调整方法并继续。用户要求分析已有材料、推导参数或起草脚本时，Agent 可凭模型本身的能力直接完成。只有在实际读取受保护的数据、写入文件或使用算力时，才核对那一步所需的访问权和资源。

四项契约分别回答在哪里运行、什么工具能运行、产物怎样交接，以及谁能使用哪些数据和能力。各节注明与设计目标有关的 v0.2.2 实现范围。源码分工、通信协议与版本验收另见[代码架构](architecture.md)和[版本记录](releases/README.md)。

## 计算资源

Windows 桌面负责托管计算连接。用户应能在未安装 WSL 的 Windows 电脑上，仅通过 SSH 集群完成从准备输入、提交作业到查看结果的全流程。本地计算通过可选接口接入，由用户按需选择和配置 WSL 或 Windows 原生执行环境。

本地和远程 SSH 集群共用资源、环境、项目授权和作业身份的表达。一次执行绑定实际资源及其版本化环境。本地作业按分配检查 CPU、GPU、并发数和时限，集群作业另绑定实际调度器、队列和配额。CPU 任务可使用没有本地 GPU 配额的项目。用户可复用已有解释器、虚拟环境或站点模块，作业服务的解释器和科学引擎的环境分别登记。平台保留兄弟引擎仓库及其分支，由用户明确选择需要登记的版本。

### 连接、会话与工作目录

- **认证与托管。** 用户在私有终端完成 SSH 登录、验证码和主机信任确认，再将该连接交给桌面。保存配置、本次 SSH 认证、作业服务就绪、会话使用权和项目计算许可分别核对。认证进行中回到原登录请求。凭据由受控存储持有，密码、验证码和私有终端内容仅用于当次认证。
- **按用途取得通道。** 同一托管连接可并行承载人工终端、各会话独立的命令通道及私有作业服务，不再依赖经本地 Worker 中转 SSH 认证或借用人工终端串行传协议的旧路径。用户点名唯一的已托管资源即可选择，同名时按资源标识区分。会话按当前委托申请所需能力。用户明确共享可见终端时，才将该终端交给指定会话。切换页面保留已有工作，收回权限使对应租约和迟到请求失效。
- **绑定实际位置。** 首次托管集群时，用户在已认证的主机和账号上确认总工作区。每个会话在该资源上领取自己的计算目录，后续执行和跨日恢复沿用原绑定。资源级软件目录保存安装及来源记录，已有软件可在原位置登记。资源或目标账号改变时重新核对，历史作业沿原来源查询。
- **分别报告故障。** 连接、终端、作业服务、队列授权和科学环境各显示自己的状态和最近观察时间。服务暂不可用时，已获准的独立终端仍可用于诊断。重连核对原主机、账号、工作区与服务身份。兼容的版本差异提示用户，实际更新由用户选择。断开传输只释放相应通道，已提交作业由原服务或调度器维护。[SSH 使用与恢复](ssh-cluster-management.md) · [工作目录与工具配置](development/cluster-resource-workflows.md)

### 作业归属与恢复

作业服务（worker）持有运行状态、启动认领、输入快照、产物和回执。桌面保存会话、草稿和带来源及观察时间的索引。从可信服务查看历史记录仅授予相应的读取能力。跨资源的同号作业各自绑定原服务。关闭最后一个窗口进入托盘，明确退出会释放本次交互连接并停止桌面的新派发，已提交作业继续运行。

提交前持久化唯一尝试和实际输入。重复请求核对同一次尝试。连接超时或断开时，界面保留最后一次观察及其时间。提交结果或进程身份不能确认时，记录 `unknown`，沿原作业号、启动记录和回执核对，禁止自动重提。取消先持久化意图，再记录原服务的确认和最终观察。用户要求续算时，按引擎实际支持的 checkpoint 创建关联原作业的新运行，并记录输入和恢复来源。[运行、状态与续算](contracts.md)

用户可明确委托有限次巡检、读日志、运行临时脚本或唤醒原会话。每份委托绑定用途、原服务、项目和会话，涉及作业时还要绑定原作业身份。委托有截止时间、轮数上限及单轮时限。恢复时跳过错过的时段，手动核对一次保留独立回执。脚本沿父作业获准的队列执行。唤醒只投递到原会话，新的执行委托须来自用户。停派与子作业取消分别确认，达到上限而作业仍未结束时保留最近观察并提醒用户。[有限次计划与额度](releases/aimatterlab-0.1.13.md)

## 可迁移工具与联用单元

工具来自随源码提交的 `aimlab-tools/` 声明、第三方交付包、已有脚本或程序，也可以是平台随附的引擎预设。同一版本的工具定义可用于不同计算资源。用户只需在选定的资源上绑定实际环境并取得该资源的测试回执。作者提供可重定位的来源和用法。资源登记保存环境所在机器的路径、配置及所需的凭据引用。

### 工具定义的五项要求

| 内容 | 开发者交付什么 |
| --- | --- |
| 输入与输出 | 具名端口、必需或可选、格式、单位、约束，以及省略可选项时的行为。手册与 Agent 使用相同定义。 |
| 执行环境 | 支持的操作模式、CPU/GPU、依赖和版本、设备与并行要求。涉及其他工具时，列明接口和兼容条件。 |
| 最小测试 | 可取得的样例输入、运行方法、预期产物和通过判据。测试要能说明所选环境可以执行哪项声明的功能。 |
| 操作接口 | 人和 Agent 各自可用的操作说明、调用入口、参数及错误处理。交付 skill 说明如何安装、测试和使用。 |
| 程序来源 | 与声明对应的固定源码版本、包、可执行文件或取得方式。来源、测试资源和相对路径在用户机器上可解析。 |

登记时保存声明及其版本。配置时可从零安装、采用已有提交脚本，或绑定已安装的程序。平台按所选目标执行最小测试，记录实际命令、环境、作业、输出和判据。来源登记、安装观察、测试结果、激活版本分别记录。复用旧测试时须能匹配相同脚本、环境和产物。软件更新创建新版本，已有任务保留原引用。[开发者交付](../developer/README.md) · [随源码交付工具声明](aimlab-tools-internal.md)

### 联用与执行 skill

工具组声明可复用的调用、端口连接和最终产物。跨阶段的训练、导出、模拟、分析可以使用不同环境，上下游用真实产物交接。同一次 MD 中每步调用的力场和在线偏置属于一个运行单元，须在实际调用位置共同工作。开发者提供接口版本、运行依赖和最小联合测试，平台核验所选完整组合。力场与 MD、偏置与 MD 的两份测试只能证明各自测试过的组合。[依赖组与联合测试](development/tool-dependency-groups.md)

配置验证完成后，执行 skill 绑定资源、工具或组合版本、实际环境和入口，列明输入输出、命令和失败处理。日常按当前任务读取执行指导，前置安装资料封存并保留来源，在安装、修复或环境变更时按需取用。公开交付、项目技能、个人技能和对话私有技能有各自的读取范围。技能文本提供操作方法，权限和验证结论分别来自用户授权和运行回执。[技能工作区](project-skill-workspace.md) · [可迁移技能](portable-skills.md)

**v0.2.2 的实现范围。** 外层交付包和内部声明已有登记入口。通用配置器及工具组逐步执行以固定 CPU `installation.check` 为工程参考。托管 SSH 的资源工具可在选定项目和队列做最小测试、激活并生成资源级执行 skill。第三方工具与内置引擎按声明统一配置和激活属于后续实现目标，本地执行预留相同接口。各引擎和联用组合的可用范围以对应适配及目标环境证据为准。[工具、配置与流程的实现](architecture.md#工具配置与流程)

## 输入、调用与输出

一张流程图（Roadmap）描述用户要得到什么、由哪次工具调用产生、又需要哪些输入。单步计算同样由左端输入资源、一次工具调用与右端输出产物构成，多步计算则通过产物端口连接多个调用。图可以逐步补全，已有输入和输出不必因更换页面或开启规划而重填。

### 从交付物准备可执行的图

1. **保留目标。** 在原会话记录用户的原始要求、已有材料、已委托的选择和待确认的推测。从每项交付物倒推所需的工具、输入和上游产物。Agent 可推导参数、编写输入并保存实际文件。缺少用户掌握的材料或某个选择会改变科学含义时，说明它影响哪项结果。
2. **明确每条边的含义。** 每次调用和每项资源都有稳定标识。每份产物绑定唯一生产节点及其输出端口，消费者用自己的输入端口引用它。纯先后约束单独记录。同一产物可以同时交付并供多个下游使用。实时力场或偏置标在同一调用内。局部草稿可带缺项保存。执行前核对必需端口、类型、环和与目标无关的节点。参数显示单位、来源、默认值和实际采用值，用户手改内容随修订保留。
3. **核对并冻结。** 用户可在原会话查看输入、定位缺项、编辑科学参数或使用本地人工复核。对整图执行的一次确认覆盖这份快照中的节点。快照固定项目、服务、环境、资源、工具及版本、实际命令、参数和交付判据。初始文件保存不可变副本、字节数和 SHA-256。随机种子或重启状态按需列入。未来输入先绑定生产步骤与端口，生成后再补实际文件身份。
4. **执行并验收。** worker 按依赖调度，在本节点需要输入时核对快照。每次交接记录生产作业、端口、文件位置、大小和摘要。下游是否真正使用了该产物，由消费者对所读或解析的数据提供证据。逐项展示目标、文件、实测值及判定，保留已满足、未达标、产物缺失和待人工判断的区别。一个目标失败时保留其他目标的证据。用户编辑的下一版草稿独立于正在执行的快照。

例如，用户要取得轨迹、热力学序列和逐帧数密度，可以让一次 MD 产生前两项，再让分析程序读取同一份轨迹。验收同时核对轨迹覆盖的时段、热力学记录和数密度单位。即使两次进程都正常退出，用户仍能看出哪项交付要求尚未满足。[流程设计与交接示例](development/workflow-io-roadmap.md)

### 运行证据与结果

- **复现与重跑。** 重复确认同一快照返回同一次执行，服务重启后按原记录恢复。对于修订后的流程，若支持复用已通过的上游节点，应能核对其原作业、输入、工具与环境版本、产物摘要，以及新下游所需的条件。用户可从结果返回原快照、日志和实际目录。复现导出列明已包含、缺失或截断的内容。
- **科学判据。** 调度器接收、程序退出、环境可用和科学验收分别有证据。每项检查保留 `passed / failed / blocked / not_run`、适用范围和原因。偏置必须在实际目标环境加载序列化产物并核对所需接口。显式选择 AOTI 时，不兼容即保留原错误并失败，禁止回退到其他后端。科学有效性或收敛性需要与该结论相应的实测证据。[引擎与 Bias 契约](contracts.md)
- **查看结果。** 运行详情应能区分来源、最后观察时间、日志与真实产物。浏览结果列表只读取所需元数据。对大轨迹，用户应能先看选定帧，再决定是否完整下载，并在界面核对实际取得的范围。

**v0.2.2 的实现范围。** 本地按图执行已接通 GPUMD MD 与轨迹数密度分析。托管 SSH 可在已授权的 Slurm/LSF 队列执行流程节点，并使用已激活的资源私有工具。跨执行复用上游子图和超出当前回收预算的大轨迹按需预览属于扩展目标。具体工具、站点与科学结果以各自的验收记录为准。[流程执行与验证范围](development/workflow-io-roadmap.md)

## Agent 协作与安全边界

### 弱校验与 Agent 自主性

用户有权决定的操作，以当前会话中用户的明确指示作为本次委托。同一目标和影响范围内，改用工具、修正输入或在确认失败后重试，都沿用原委托。项目是否已建立、是否开启规划、是否具备专用适配器或 skill，只影响相应入口。普通聊天可以直接完成模型能做的部分，也可以通过已获准的终端或作业服务查队列、配置环境、提交明确委托的独立作业。内置流程和技能优先复用，由 Agent 按需选择。在原对话开启规划时沿用已确认的目标、资源和工作目录。用户只要求审阅时，工作止于审阅。

| 情况 | 当前操作如何处理 |
| --- | --- |
| 缺少可选工具、兼容版本有差异、AI 未复核或建议参数超出参考范围 | 展示提示、未验证范围和当前可用的操作。在已有授权内可以继续准备、诊断或尝试。 |
| 实际输入、执行命令或所需环境缺失 | 在首次需要它的步骤指出缺项和恢复方式。能从已有材料补齐的，由 Agent 处理。 |
| 科学检查失败或结果未验证 | 保留原结果、证据和适用范围。Agent 可检查原因、修复输入或环境并重新试算。若指定产物确实无法在目标环境加载，暂停依赖它的调用，返回原错误。 |
| 实际目标有歧义、所需访问权尚未取得，或请求超过硬资源限额 | 指明是哪项数据、资源或操作受限。能在委托范围内换用可行方法的，直接继续。确需用户选择目标、登录或由有权者授予访问权时，只请求补齐该项，其余工作继续。 |
| 已发送请求，结果未知 | 保留原请求、会话、服务、作业及观察时间，查原回执。限制该次重复提交，其他独立工作可继续。 |

**一次委托与长期权限。** 对终端提交作业、向总工作区外写入或执行，桌面应把本次操作绑定到实际连接、目标和影响。用户在可信会话中的指示已明确覆盖这些事项，且用户对目标有相应权利时，应直接沿用这次指示。同意一次操作只覆盖该次操作。持久项目权限的授予和撤销由用户通过可信桌面办理，MCP、模型回复与 skill 均不能自行扩大权限。开发模式只适用于用户选定的工作区，可随时撤销。v0.2.2 的普通终端提交和工作区外操作仍有专门的确认入口。

例如，用户要求“在已登录的集群 A 的 short 队列提交这份脚本一次”。若脚本、目标和资源均已确定且实际可用，普通聊天应能直接提交并返回作业号。若队列拒绝，Agent 应带回调度器的原因并检查有哪些可行调整。若提交答复丢失，先沿原尝试查回执。评审新增校验时，要能指出它保护的具体对象，并分别走通推荐流程和用户明确委托的其他可行路径。[项目授权与执行](contracts.md#项目授权) · [开发模式的作用范围](development/developer-compute-access.md)

### 服务商、上下文与隐私

Codex、DeepSeek、Qwen、Kimi 和兼容 API 的共同目标，是让用户能在同一套交互中对话、查看工具调用、作出选择、中断并恢复。账号、模型回复和计算资源各自核验。服务商适配按实际协议和工具隔离能力提供功能，可兼容的版本差异给出非阻塞提示。当前私有定义隔离与显式会话恢复已覆盖全部五类服务商，ACP 连接（Kimi、Qwen）按 ACP v1 能力握手并对兼容版本差异给出提示（受控 CLI 下载安装仍严格核对锁定版本）。开放相应能力时须能核实会话、工具和可见数据的范围。[服务商验收](development/EXTERNAL_PROVIDER_ACCEPTANCE.md)

- 每个会话分别保存轮次、草稿、待处理消息和可撤回的工具租约。上下文绑定当前项目、流程修订、计算来源和用户手工修改。工作流对话已按会话跟踪已确认的快照基线，流程未变化时仅发送紧凑基线引用，在首轮、复核模式、参数或流程图变更、上下文压缩、失败或恢复会话时自动补齐完整权威状态。界面切换只改变查看位置。恢复时重新核对原身份及权限，并隔离旧轮迟到的事件。服务商超时不自动重发消息或作业。
- 已保存历史按原数据范围脱敏读取。继续发送时核对原服务商配置、端点和认证方式。实时流、工具结果、错误、历史和导出使用一致的凭据保护。用户按定义的确切版本和指定服务商授权共享。撤权或更换上下文使旧租约失效。
- 渲染进程运行于沙箱，无法直接访问 Node、文件系统或凭据。特权操作经由主进程的类型化 IPC，主进程核对请求来源，worker 执行项目的计算授权。运行输入与原始验证证据保存在私有运行目录，可分享的报告按需脱敏。[请求与状态归属](architecture.md#请求与状态归属)

### 用户在工作台看见什么

首次使用时可选择语言、外观、模型服务商和算力，也可稍后配置。新手引导使用实际账号设置、计算连接、示例和操作页面，用户可以回到原步骤。日常工作台应让用户看清当前对象、实际状态、下一步操作及其影响。流程页围绕目标与流程图、当前缺项、可编辑参数、部署目标、执行动作与回执组织，不再并列多套重复执行入口；窄屏或有限纵向空间下流程图自适应为紧凑缩略形式，避免挤压参数编辑。出错时从原对象进入修复。

会话、草稿、手工参数和阅读位置在切换页面后保留，阅读历史时新消息不抢滚动位置。连续工具调用默认折叠为摘要，但须外露打开流程、核对连接及异常恢复等关键下一步动作。多服务商需要用户选择方案、队列或资源时，统一在输入区以单卡逐题展示（支持点选、数字键与中文输入法选词保护）。查看作业详情仍可回到原会话。删除会话分组后，其会话回到未分组，关联流程、项目授权和真实作业继续保留。主要操作在深浅主题、放大字号、1366×768 和 1024×768 下应可见、可用，各主工作区、对话与终端面板具备独立的渲染错误隔离。错误和未知提交有文字说明，停止助手、收起终端与取消作业分别呈现。[工作台交互设计](development/frontend-design-review.md)

**升级与数据保护。** 源码更新沿用原工作区配置，分发版在用户选择更新后核对签名清单和下载包。1.0 前允许调整开发期接口和一次性测试草稿格式，必要的破坏性变更须说明影响。除非用户明确要求，升级应保全 SSH 连接、凭据引用、登记环境、项目授权、真实运行记录及其物理产物，并能从原来源重新打开。自 1.0 起要求向后兼容和版本化数据迁移。[分发与证据](architecture.md#分发与证据)
