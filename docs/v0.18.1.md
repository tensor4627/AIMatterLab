# v0.18.1 · 第一轮：入口、默认值与工具反馈

本代是 v0.18.0 后的第一轮有界修复，已完成软件回归、当前真实科学短例、实际桌面及本地包验收；各项范围和限制见下文。第二轮工作区重排尚未实施，其联网调研和设计规则见[交互设计基线](design/interaction-design.md)。

## 交互改进

- 侧栏使用一个带文字的“新对话”，项目切换入口统一打开项目管理；新建项目、项目设置和计算资源进入所属菜单，移除含义不清的授权加号。
- 新项目默认勾选 15 个已实现引擎，建议 GPU 0、并发 1、时长 3600 秒；环境仅建议当前已登记选择或唯一登记项，输入根目录仅使用当前项目范围内的建议。保存前不创建或扩张授权；已有项目保留原设置，手工选择优先于迟到的环境列表。
- 项目表单前置名称、环境、GPU 与输入目录；工具选择、资源限额、多环境、集群和原始数据按组折叠。缺项展开对应组。模块图标区分 MD、增强采样、训练、资产等类别。
- Agent 设置的服务商执行路径及工作目录、作业服务根目录和端口进入高级配置；保留账户、模型、上下文、Effort 和规划模式的现有功能。工具数量从日常主操作区隐藏。
- 工具卡用可读动作名称，区分“待补充”“失败”“状态未确认”和完成。技术结果折叠，并保留适用的下一步说明；读取一个失败作业的状态本身仍可以是成功的工具查询。

## 减少工具链中的可预防失败

桌面和 Python MCP 对缺少参数、错误类型与未知工具返回结构化错误，Agent 能在当前流程内纠正输入。已发出的操作如果结果无法确认，明确标为 unknown，不自动重试。桌面检查 JSON-RPC 版本、请求 ID 与最小响应结构，防止无关或损坏响应被当成工具成功。

WSL 连接失败保留可读的原因类别，清理部分建立的连接，重连成功后清除旧诊断。不会把命令、凭据或原始启动日志直接作为界面诊断。

工具默认可用与计算资源范围分别处理：MCP 仍不能修改项目授权，Renderer 仍无系统权限；人工复核及执行按钮、文件共享范围、取消与撤销检查均保留。没有自动扩大已有项目、切换引擎源码或重复提交未知作业。本代不包含新的模型访问或工具失败率基准，修复范围以具体回归用例为准。

本轮当前真实科学路线为 PyDyn MD、GPUMD MD、PyDyn-pyGAS、GPUMD GPU-Sampling、GPUMD NEB、pyGAS 构建、Bias 验证、WTMetaD 与 OPES 重加权、NEP 训练/评估/分析、HotPP 训练/评估/导出。每条路线均保留当前批次证据，不将历史作业或合成 IPC 计入其中。

科学短例只证明限定集成范围：Ag32 使用合成 ASE-EMT 标签及独立的 6/2/2 数据划分；静态 umbrella 重启仅比较该短例的坐标、动量与盒子；C63 NEB 的 76 步与 fmax 0.009910 eV/Å 是优化器停止证据。部分有限差分仅检查 32 原子中的 8 个，初始空历史或饱和 GaN 短例不证明普遍非零响应。短 WT/OPES 自由能结果不证明热力学收敛或势函数精度。

旧索引中关于 WT 历史首列的误述已追加勘误：该列为 stored bias，初态 `exp(0)=1` 不能解释成 hill weight 或 height 为零。原始数值未修改，未为文案勘误重新运行科学任务；无采样支持的自由能 bin 保留无穷值，不能当作有限物理结果。

首次测试失败和脚本解析错误均保留：旧 HTTP 502 断言已改为 MCP 200 + isError，并继续检查私有内容不外泄、没有额外执行；环境迟到的表单覆盖已复现后修复。Windows 文件 symlink 权限不足的子例为 not_run，不能从 Node 顶层零 skipped 推断已执行。

实际 UI 测试脚本两次未逐层关闭返回的项目管理窗口，已保存原失败并修正观察脚本，继续原测试项目。24 字号、最小字号 18、1100 像素窗口的中心 Agent 布局下，右下队列短说明仍有截断；该视觉限制留给第二轮底部面板重排，不能宣称本代所有布局已完善。
