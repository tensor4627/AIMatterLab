# AIMatterLab 0.1.16

2026-11-19 · Windows x64 · 本地交付 · [更新日志](../../CHANGELOG.md)

在设置右侧点灰底的“检查更新”，可以看到当前版本、发布源和检查结果。发现正式新版后按钮高亮为“更新”。点击一次会下载、校验、退出应用，在原工作区安装并重新打开。启动时的后台检查只读取版本和块索引。收起导航后，相同入口位于设置图标右侧。

下载面板显示目标版本、所需传输量、已下载和已复用的本地数据。缺失基准或差分失败时会显示完整包下载。Windows 安装页默认展开明细，显示文件占用检查、程序解压与写入、快捷方式登记、工作区指南和增量基准缓存。手动运行安装包时也能看到这些步骤。

## 接入发行源

工作区按南大 GitLab、GitHub 的顺序读取最新正式版。主站返回有效清单时以它为准。主站无法访问或没有发布清单时使用备用站。按版本获取的附件也可以切换来源，最终安装包须匹配所选清单的签名和 SHA-512。

私有项目可在更新面板的“私有仓库访问”中为对应站点保存或移除只读令牌。GitLab 需要项目访问及 `read_api`，GitHub 细粒度令牌需要该仓库的 Contents 只读权限。桌面使用系统凭据加密，令牌按站点分别使用。[GitLab 私有发行附件](https://docs.gitlab.com/user/project/releases/release_fields/) · [GitHub 发行附件 API](https://docs.github.com/en/rest/releases/assets)

1. 在发布机执行 `pnpm run pack`，从同一构建取 `latest.yml`、`AIMatterLab-<版本>-win-x64-setup.exe` 和同名 `.exe.blockmap`。安装包和块索引须保留原名。
2. 在南大 GitLab 项目 `Tensor4627/AIMatterLab` 创建 `v<版本>` Release。上传三个附件，例如存入项目的 Generic Package Registry。为每个文件创建 release asset link，将 `direct_asset_path` 设为 `/<文件名>`。客户端使用 `permalink/latest/downloads/latest.yml` 和对应标签的下载路径。[GitLab Release API](https://docs.gitlab.com/api/releases/)
3. 需要备用源时，将**同一次构建**的三个文件上传到 GitHub 对应标签的正式 Release，并设为 latest。两个站点都保留旧版本的块索引，便于跨版本复用数据。签署清单引用完整包的摘要，单独推送 Git 提交或标签不会生成应用更新。

已有 0.1.15 工作区可先退出应用，运行本地 0.1.16 安装包并选择原目录。之后可直接使用新的双源入口。便携 ZIP 和源码检出沿用各自的升级方式。
