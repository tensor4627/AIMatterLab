# 1.0.2-dev.28：持续委托、检查与执行分离

本代依据全量复审和最后的弱校验修订，落实 [软件规格](../software-specification.md) 与 [实施验收清单](../development/review-implementation-plan.md)。软件回归、隔离真实 SSH、真实 DeepSeek 修复迭代和目录成品检查已通过；真实学校集群的网关认证及调度器闭环仍待完成。不能把自有 SSH 验证等同于学校集群验收。

## 实际改动

- 授权、执行与检查分别记录。未复核、过期证据和科学检查失败不再统一锁住任务；已有委托覆盖普通修改、运行、错误分析、修复和新的尝试。`task.execute` 默认不强制执行可选科学检查，调用方可用 `runChecks` 显式请求。序列化 bias 的实际目标加载、显式 AOTI 不降级、输入完整性及权限仍独立检查。
- 旧运行使用固定输入，下一版草稿可以编辑。未知提交仍核对原尝试；不能因为编辑草稿或恢复会话而重提。取消意图先持久化，程序退出与科学结果保持分离；没有真实终态回执时保持 unknown。
- 保留石墨灰／淡紫色三栏与默认右侧 Agent；统一实时和历史消息投影，保持逐会话草稿、阅读位置及工具记录。查看运行不暗中切换会话。错误可把原任务、运行、输入版本和日志摘要带回对应会话，已有输入保留，不自动发送。
- 参数和运行页面减少重复确认，检查按实际结果展示；修正放大字号、错误边界恢复和终端 StrictMode 冷启动。终端卸载立即隔离输入与尺寸回调，再释放 xterm 的排队初始化资源。
- ACP 超时隔离旧轮；Studio 自有事件、持久化与历史读取共用脱敏。损坏 Catalog 记录保留原始字节并单独诊断。只读历史查询不再改更新时间；原生活动查询优先读取元数据。
- 已有修复委托跨普通证据变化与恢复持续有效，权限撤销或对象变化仍拒绝。Codex 不支持的目录查询返回明确错误并保留会话；实际越权原生操作仍受限制。MCP 初始化指引与持续委托规则一致。
- CPU 安装检查不占 GPU；产物列表只观察元数据，选定文件才计算稳定摘要；复现导出列出实际输入、日志、结果及缺失／省略范围。关键编辑、部署与执行 IPC 增加请求和返回类型。
- SSH 首次部署记录完整运行库摘要；后续核对已登记缓存，旧本地源不再存在时可只核验并复用远端固定缓存。旧短摘要不会伪造成已知完整源摘要，实际观测来源单独记录；缓存不符或缺失保留诊断，不清除原作业或自动重提。
- 新增固定势与序列化 bias 的组合指南，只在实际 `sampling.gpumd` 路线按需公开；不自动读取整个指南，也不宣称任意组合已经验证。修正隔离封包的 worker 解包路径，成品启动使用真实磁盘资源。

## 兼容与数据

原 SSH 配置、凭据、登记环境、项目授权和真实作业保持；新增数据字段可选，未执行破坏性迁移。旧的 failed、stale、not_run 不改写为 passed。外部调用方应按授权、执行事实和检查结果分别处理，不能再把 ready 等同于科学验证通过。没有修改兄弟引擎源码或切换其分支。
