# 交互式 SSH 登录开发验收

对照正式 0.1.25 `6b21c5b`，修复基于集群工作流开发快照 `03b4cd1`。交互模式会先尝试服务端提供的键盘交互和密码认证，再尝试可用的密钥等方式。保存的客户端、密钥和跳板参数仍用于原配置。发生确切的登录进程退出时，原登录窗口可以查看最后的只读输出。认证成功或关闭该连接时清除登录输出。

本机核验超时保留原登录请求、连接和已打开的终端。用户可继续原登录。需要核验连接的操作须取得新的有效核验结果。明确的 SSH 进程身份或控制套接字变化会停止使用相应连接。

| 范围 | 结果 |
| --- | --- |
| 0.1.25 对照 | `passed`。同一终端服务中先打开密钥会话 A。测试服务器为交互会话 B 提供键盘交互和公钥，并拒绝错误密钥。Windows OpenSSH 和 WSL OpenSSH 均先投递 B 配置中的密钥，两次请求都返回 `ssh_master_unavailable`，密码提示次数为零。原版隔离的 Electron 界面按正常入口重现两次同样的“SSH 连接需要核对”，A 可回到原终端。 |
| 修复后的同步登录 | `passed`。真实 Windows ConPTY、Windows 及 WSL OpenSSH 客户端连接进程内 SSH2 回环夹具。两种客户端下，A 的原 Shell 保持可用，B 跨不同配置及同一配置的并行请求各用独立登录。支持两步键盘交互，也通过了服务端要求先提交指定密钥、再输入第二因素的场景。服务端明确拒绝时，原 B 的人类登录输出能读回拒绝提示。 |
| 超时与身份 | `passed`。在真实 WSL master 的本地检测路径注入一次有界超时。0.1.25 把原连接判为失效。修复后保留同一登录请求和密码提示，继续完成两步认证。已认证后核验超时保留原 Shell，重新核验后恢复。定向测试确认超时期间不派发新 Shell 和受保护操作、迟到回执无效、真正的身份或套接字变化仍被拒绝。 |
| 原生界面与定向回归 | `passed`。隔离 Electron 普通入口分别完成 Windows 交互登录、WSL 超时后的“继续原登录”和拒绝后查看原登录只读输出。三组均可回切并操作 A 的原 Shell。181 项 Node 回归、10 项本机 WSL Python 检查，以及 TypeScript、源码工具契约和文档链接检查通过。 |
| 现场与版本 | `not_run`。未读取对方机器的日志或连接对方集群。现场提示与回环复现一致，现场具体拒绝原因未确认。这个开发分支未构建或发布安装包，未运行科学任务。 |
