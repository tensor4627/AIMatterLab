# 1.0.2-dev.8：交互 SSH 登录接入作业服务

2026-11-11。用户指出，完成交互登录后应当能够在同一连接编写、审阅和部署任务。此前将交互连接固定为三个终端工具，造成任务规划已开启却仍要求另接工作流服务的死路。本代接通实际服务能力。

## 行为

- 用户在原 SSH 终端完成密码、验证码等登录操作后，点击“登录完成，连接作业服务”。固定且校验过的 Studio worker 资源通过这个已认证会话传输到当前账户的独立目录，不再启动第二次 SSH 登录，不将口令或远端服务凭据放入终端记录、渲染进程或 Agent 上下文。
- 实际服务身份、运行资源指纹、健康状态与工作流工具确认通过后，当前 SSH 资源才能创建任务、读写项目输入和使用工作流工具。单纯进程存活、终端交接或勾选规划不冒充服务就绪；未连接时继续给出准确状态。
- 服务使用当前 SSH 会话期间，终端输入、尺寸变化和交接被阻止，避免用户输入混入机器协议。用户可明确返回交互终端；结果未知时保留原连接，不自动执行第二遍初始化、写入或提交。
- 同一 SSH 服务可由用户保存 Slurm/LSF 调度器、科学可执行文件、运行目录、输入只读目录和资源上限。保存配置不授予项目/队列权限，不提交任务；原有项目授权、文件审阅、提交批准与调度回执继续生效。登录节点禁止直接运行本地科学作业。
- 任务来源使用保存连接 ID/版本、服务器身份、worker 根目录和资源指纹绑定，排除临时终端 ID/端口。重开桌面需要明确新建连接；SSH 来源任务不会静默切换到默认 WSL。
- 正常退出关闭本次桌面的交互连接；远端 worker、持久记录与已提交调度作业独立存活。保留现有保存连接、凭据、计算环境、授权和真实作业。科学引擎仓库未改。
