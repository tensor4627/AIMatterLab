# 1.0.2-dev.33　SSH 作业服务版本提醒与主动更新

桌面根据已连接 worker 的运行指纹与本包 worker 的指纹显示版本差异。已核实的旧服务继续提供其已实现的工具和已授权操作。用户可从提醒中的「更新作业服务…」进入当前连接设置，也可从「连接计算资源」中选择该 SSH 的「作业服务」。在设置内点击「更新作业服务」才开始部署，界面显示后台回报的阶段、传输进度及结果。更新使用当前认证连接及原操作范围。

日常接管优先核对已登记的版本。上次健康检查失败时，先只读核查旧 worker。它已经恢复即可继续使用。若同一服务位置实际运行的是本包 worker，则在主机、用户、根目录、端口、运行路径、服务身份及完整缓存清单核实后更新登记。两项核对均使用原认证连接。未取得明确结果时保留原尝试和终端，由连接设置显示诊断。

Windows 终端在恢复 shell 输出时，可能把当前 shell 自己的提示符标题与下一次服务握手的首帧一起回传。桌面现在识别这一种有界重绘，继续核验同一请求的完整首帧。其他会话、未知控制序列、损坏帧仍按原协议拒绝。

在本地 WSL 连接向导中，用户明确发起新的连接后，旧启动恢复请求的迟到结果不再覆盖当前状态。仅打开向导或查看连接计划仍可继续观察原服务。

## 真实学校连接

在 dev.32 的日常配置中，旧登记指向升级前的 worker。保持原 SSH 登录，通过已验证的原 master 回读了已运行服务的 138 个文件、完整清单、47 个远端 MCP 工具及三条作业记录。以本次实测回执修正这一条日常登记后，用户在原窗口重新交接并确认「作业服务已连接」。桌面持久记录显示同一连接、同一终端、已核验的缓存清单和 Agent 操作权。

此前的 alanine GPUMD + MetaD 作业仍为完成状态。本代的学校检查只读回原作业，本次新增作业数为零。科学结果和首次传输证据见[原作业验收](v1.0.2-dev.31.md)。
