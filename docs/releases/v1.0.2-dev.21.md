# 1.0.2-dev.21：交接后准备服务与接入结果可见

本代以用户最新要求为准：交互登录完成后保持普通终端，不探查、部署或连接远端作业服务；用户点击“交给 Agent”之后才准备服务。首次成功保存登记，以后交接时复用已核验缓存，不增加额外认证步骤。

dev.19／dev.20 的登录激活路径会立即启动 Python，这是提前出现提示的直接原因。旧界面只在 `status=connecting` 显示进度，因此 unknown、通道连接但工具未就绪、服务交接未成功都可能使进度收起，不能据此判断服务已成功。本代分别保留“结果待确认”“通道已连接，工具尚未就绪”或明确错误；当前 Agent 未获得服务使用权时不显示服务可用。

移除登录准备钩子及其等待／失败标记，首次准备回到真实终端交接与真实对话确定之后。还核对到消息入口会刷新对话 serial，可能使正在准备的接入因上下文变化而结束；现在复用已有交接保护，在修改上下文前拒绝准备期间的新消息，既不发送也不重发。准备完成后将临时路由切换到服务通道，绑定完成后释放保护，保留原资源、对话、项目和输入授权核验。
