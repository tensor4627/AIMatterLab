# v0.9.0 · 第三轮：恢复、反馈与完整验收

2026-10-17。承接独立源码迭代 0.7.0、0.8.0，最终便携包为 release/v0.9.0/GPU Sampling Studio 0.9.0.exe。实现审查、参考交互和现有科学模块范围见 [完整审查](../audit-20261017.md)。

## 本轮改进

- 修复自动账户观察请求和工具重连的竞争：观察者等待当前初始化，不再用早先捕获的空 worker 配置重建连接；只读账户请求在明确重建时可安全重试。修复连接按钮重建工具链后继续原 thread。
- 科学工具就绪定期检查；断线提供可操作的修复入口。正在回复时，主进程拒绝重连与上下文修改，防止中途杀死会话。
- 工具结果采用运行中 / 成功 / 失败操作卡。草稿有可打开入口，长 JSON 仅在详情中展示；MCP isError 不会再显示成功勾选。恢复会话也恢复操作卡，并隐藏应用生成的 workspace context 和内部模式指令。
- 修复慢刷新重叠与结果被不断作废：周期刷新及 GPU 查询合并，用户修改后的强制刷新仍获取新快照。元数据请求有界超时，失联状态仍按 unknown 处理。
- validating、submitting、unknown 的持久恢复状态锁定参数并提供核对入口；状态确认不会自动重提计算。
- 普通输入契约检查标记 scientific_status=not_run，序列化 Bias 检查有独立产物结果。界面区分输入检查与计算节点预检，不用 passed 泛指科学计算成功。
- 本机 Python bootstrap / relay 请求显式绕过环境 HTTP 代理，避免回环服务受外部代理干扰。MCP 空资源目录正常响应；主进程启动失败保留本机诊断日志并显示恢复提示。

## 初次失败及证据

最早账户先连接的原生工具目录缺少 gpusampling；0.7 修复生命周期后已实际发现 26 个工具。初次打包版验证又暴露账户观察请求竞争连接；已在本轮修正。第一份验收探针在任务实际保存前取到空记录，改为主控等待真实落盘、逐步断言，并分别完成源码和最终包验收。初次桌面全量配置哈希检查因 Kimi / Qwen 运行时路径自动刷新而不同；从保留的配置记录恢复候选、精确匹配原哈希后确认仅这两项变动，SSH / 授权 / 环境与凭据不变。中途重打包遇到 unpacked 目录 EBUSY；确认旧打包结束且本任务测试进程关闭后重打包通过，没有杀死其他任务的进程。
