# 集群基础工作区设置验证

2026-11-18。本记录对应 0.1.8 之后的源码修复。

首次 SSH 登录后，新流程尚无工作区或服务来源绑定。原来的恢复逻辑直接返回 `binding_missing`，界面据此禁用工作区按钮。现在桌面先核对所选连接、当前对话与实际作业服务，再以只读健康检查恢复可用状态。已有流程继续使用其保存的来源；观察连接不会创建流程或更改绑定。

Agent 按随附的 [基础工作区 skill](../../agent/builtin-skills/studio-compute-workflow/references/base-workspace.md) 调用 `setup_base_workspace`，在普通对话中检查或初始化工作区。默认名称为“基础工作区”，目录名为 `base`，实际目录为作业服务根目录下的 `projects/workspace-base/inputs`。手动名称与目录名位于“集群连接 → 编辑 → 高级：基础工作区”。目录由当前作业服务管理；该入口不迁移服务根目录。配置按连接配置、实际主机身份和服务根目录保存，并在使用时核对远端目录。

新建 SSH 流程在首次准备输入时复用该选择。明确沿用草稿或已有来源的流程保留原目录。初始化沿用桌面现有的首次授权衔接，在填充项目和输入目录后更新当前对话的授权，旧工具调用凭据失效。工作区只用于编写输入，不新增引擎授权。普通对话的工作区设置本身不创建科学流程。
