# v0.18.4 · 已安装算力的发现、登记与配置交接

日期：2026-10-27。修复正常作业服务仅有 CPU 编写环境、已安装 GPU 软件未登记，以及集群连接缺少明确健康状态的问题。原始收据保存在 ignored `.studio/v0184/environment-round/`。

## 功能与边界

- 连接时默认在当前 WSL 发行版内发现已登记解释器、标准 venv/conda、受限常见目录及明确绑定的源码，实际观察 Python、软件模块和 CUDA。新增独立环境登记，保留旧环境、源码分支与项目授权。缓存保留原观察时间，可手动重新发现；非标准程序路径需要明确选择，未发现不代表未安装。
- 桌面连接先完成环境交接再开始 Agent 协作；首次扫描不会阻止工作区显示。设置可关闭自动发现。计算环境页面按本地和集群分组，提供发现、具体路线检查、Agent 协助和结构化登记表单，高级 JSON 与诊断收起。
- `compute_readiness`、`discover_local_environments` 供 Agent 获取真实上下文；`draft_local_environment` 提出可审阅设置。普通对话可处理明确的配置请求，不必生成科学流程。登记仍由桌面执行，MCP 不能更改项目授权。建议保存与 `applied` 状态原子提交，重复保存拒绝，重启后不再待办。
- 为已观察到的 HotPP / pyGAS 公共 Python CLI 建立当前注册专属入口，不修改引擎或全局 PATH。自动环境身份包含派生 CLI，升级可新增登记并保留旧版本。
- SSH 认证、登录节点调度器/队列发现、计算节点科学验证分别记录。显示检查时间；连接失败清除旧成功，超过 15 分钟或配置版本变化显示待复查，并拒绝旧检查覆盖较新的失败。集群页默认打开已有连接，缺失用户名等旧配置明确待完善。
- 安装技能增加同一 launcher/profile/worker root 的交接核对。普通计算复用已保存的运行时收据，安装技能不在每轮重复加载。未增加集群端 Agent CLI。

科学路线包括 PyDyn/GPUMD MD、两条 pyGAS 采样、GPUMD NEB、构建/序列化验证、NEP/HotPP 训练评估导出及已实现分析。Ubuntu 和 Ubuntu-22.04 的证据分别记录；正常实例使用当前 Ubuntu 已实跑的 GPU-Sampling。NEB 短例为 76 步、末步最大力约 0.00991 eV/Å；限定静态续算坐标、动量与盒子误差为零。WT 重加权只有 1/20 个支持 bin，其余保留 `+inf`，不声明自由能收敛。

本轮另在 **v0.18.3 实际解包版**完成两次真实 Codex 模型交互：新建 Cu32 流程，关闭重开后保留同一 thread/task，续聊将 300 K 改为 350 K、参数版本 1→2；仍只有一个流程。只生成未执行结构脚本，没有动力学驱动或作业；这不证明温度已写入可执行输入，也不冒充 v0.18.4 的新模型回放。

## 保留的失败及限制

最初人工候选把另一个 WSL 发行版的路径登记到当前发行版，实际探测失败；仅本轮新增、未经授权使用且无作业引用的错误候选已移除，改为当前发行版实际短例通过的程序。原失败记录保留。初次桌面重启检查的文本定位器同时命中建议与环境名称，未计通过；后续使用明确标题定位器，并修复产品已保存建议仍显示待办的问题。旧自动环境新增 CLI 时的身份冲突已加入回归。

首次便携包观察器把正常关闭窗口导致的 `Target closed` 计作失败；记录保留。后续实际重跑以同一隔离 profile、实际加载 ASAR 和进程退出共同确认通过。封装期间的旧快照不作为最终包；冻结源码后重封装并逐项核对。`package.json` 按名称、版本、入口及模块类型核对，其他程序/技能按字节核对，因为 electron-builder 会裁剪开发元数据。

自动发现与依赖通过不代表模型、bias、CUDA ABI、输入语义、重启或生产结果已验证；执行前仍使用现有的目标及输入审阅门。新注册不会自动扩展已有项目的 GPU/环境授权。跨 WSL 发行版不共享 Linux 私有路径，也没有新增跨发行版作业传输适配。

本代未做新机器下载/安装、集群计算节点安装/提交、AOTI、全新账户登录或 v0.18.4 新模型推理。未实现的 PyDyn NEB、TorchNEP/主动学习/外部 DFT 适配继续 not_run。原科学引擎仓库未修改，版本只在本地 Git 管理，不推送。
