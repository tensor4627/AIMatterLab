# 1.0.2-dev.19：登录后自动准备服务与终端尺寸修复

本代只处理用户报告的两项问题：交互登录完成即自然接入作业服务，以及交接后窗口重排误报终端操作权变化。没有增加新操作步骤。

## 已定位原因

用户的 dev.18 堆栈 `index-CcZksPDW.js:418:7904` 对应真实包内 `ResizeObserver` 的 `sharedTerminal.resize` 错误回调；`422:2351` 是上报包装。界面按窗口大小调整终端尺寸时，主进程使用 human 身份，而 broker 的 resize 错用输入写权限检查。终端已交给 Agent 时返回 `agent_owns_session`，被映射为 `terminal_human_owned`，显示为“终端操作权已变化”。这条报错证明的是尺寸操作被错误拒绝，不能用它推定 SSH 认证或 Python 状态。

dev.18 的 worker 准备实际放在 `sharedTerminal.owner` 交接之后，登录完成的激活路径没有触发自动检查／部署。这与用户要求的自然登录流程不符，不是用户缺少额外权限或需要再次认证。

## 最小修改

- 已认证原连接激活后，主进程自动调用服务准备：未登记时首次部署、核验并保存；有登记时验证缓存并复用。仍使用同一 SSH master 的独立服务通道，无新的登录或认证界面。
- 交给 Agent 前等待该连接已有准备结束，再建立／恢复真实对话并交接，避免准备过程中变更对话使原请求失效；失败和未知请求不自动重派。服务准备与 Agent 使用权分别保存，不在登录时扩大项目授权。
- resize 使用视图访问校验，允许人工界面调整 Agent 所持终端的尺寸；原 epoch、Agent scope 和服务协议占用锁继续校验。实际输入仍须持有输入权。前端在交接中暂停远端尺寸更新，并丢弃旧 epoch 的迟到读／尺寸错误。
- 终端仅增加一行服务准备进度；规范与环境指引同步为登录即准备、交接仅授予使用权。
