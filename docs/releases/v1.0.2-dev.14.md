# 1.0.2-dev.14：Agent 读取已登录作业服务

本包保留旧的同一 PTY 服务通道设计，不是新版计算资源规范的完成包。新版要求基础 SSH 连接、人工认证、交互 shell 与作业服务使用独立通道，并分别交接权限；相关实现与验收另行记录，不能沿用下表作为新版规范通过证据。

本代处理真实便携版反馈：服务显示已就绪、已交给当前对话，Agent 仍不能探测当前集群。只读核对本地实际记录后确认两条不同路径：DeepSeek 在没有工作流时被遗留访问规则拒绝；GPT 的服务调用实际成功，但 `list_clusters` 返回空的调度器登记，随后被解释成终端未共享。服务连通、当前对话授权、调度器登记和队列探测必须分别说明。

取消 DeepSeek 对发现和 SSH 工具的过时硬限制，发现不再要求预先新建工作流；保留服务授权、私有 CV、项目、所选输入、环境和运行归属检查。服务对话载入当前资源事实，明确协议终端不提供原始 shell 工具，空调度器登记不表示没有登录。

新增主进程只读工具 `inspect_compute_resource`。它先核对实际选中连接、完整 worker 身份、本次服务实例及当前对话授权；请求队列探测时，由当前已认证桥执行固定、有界的 Slurm/LSF 查询，不新建工作流、不登记调度器、不输入终端、不发起第二次 SSH。超时、输出超限、未知状态、撤权或身份变化不能返回成功事实，也不重发。命令在当前 PATH 不可见只报告 `not_found`，不推断软件未安装；探测结果不代表计算节点 GPU 可用、提交授权或科学验证。

首次创建当前对话工作流、首次补全项目/环境和输入目录，通过受信事务迁移已有服务授权。旧令牌失效，已有非空身份不能换成另一项目、环境或服务；人工收回、新授权、资源/来源竞争会使旧事务失效。私有定义模式不追加不可用的服务探测指引。

保持 worker `57cc5d274c42747e679d`、138 个文件及 Python 3.9 下限不变，不升级用户正在运行的 worker。桥能力是附加的可选协议字段，不修改已有保存格式或项目授权，无需数据迁移。旧桥明确返回 `requires_new_attachment`：用户在连接设置明确返回交互终端、再次连接已登记服务时载入新桥，不自动重连或重复认证登记。

原始证据保存在忽略的 `.studio/dsh-user-failure-20261112/`、`.studio/dsh-tool-read-review-20261112/`、`.studio/deepseek-ssh-audit-20261112/`、`.studio/selected-service-tool-review-20261112/` 和 `.studio/agent-service-release-20261112/`。本代已完成下述本地测试与实际包验收；用户真实集群与模型响应仍须实际试用确认。
