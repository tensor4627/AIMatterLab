# v0.18.6 · 流程自己的部署与恢复

日期：2026-10-28。修复退出软件后部署页丢失计算项目的问题。此前，新建计算项目后的绑定只写入页面内存，只有再点击保存或准备才持久化；恢复时也没有区分作业服务未连接、目录尚未读取与项目确实不存在。

## 本代修改

- 每个流程独立保存计算项目、目标环境、工作目录、资源和时长。编辑立即保留本机草稿并串行保存；退出发生在准备之前也能恢复。草稿持久化不会自动准备、验证或执行计算。
- 创建计算项目时，主进程先保存带稳定标识的创建意图和流程绑定，再向作业服务创建。返回丢失后可核对原请求，避免重复项目；同标识内容冲突时保留现场。已有项目策略和草稿工作区保持原样。
- 从某个流程进入“部署与执行”，直接恢复其绑定会话及原作业服务，无需另选任务或切换全局项目。绑定包含 WSL 发行版与服务根目录，同名项目不能跨服务误用。连接中、离线、读取失败与项目不存在分别显示；恢复原连接后主动重读，避免旧的“在线”标记让错误提示滞留。
- 任务页和最近实验默认使用当前会话流程的明确计算项目绑定，避免输入草稿项目把运行记录筛成空列表。底栏同步该绑定，不再错误提示已绑定流程缺少计算项目。用户明确选择其他项目时保留该筛选；底部队列仍展示全部已读取任务，并区分本地与集群的同名运行标识。
- 部署编辑采用版本检查与保存确认；较新草稿不能悄悄执行旧配置。主进程合并同一流程相同的并发准备/执行请求，拒绝相互冲突的操作。异步返回还要核对流程、版本、作业服务与连接身份，不能覆盖新页面。
- 启动恢复、会话切换和运行页面导航使用选择序号，迟到的旧请求不能抢回已打开页面。输入审阅只针对当前准备产物，重启后仍需重新勾选实际输入复核；未知运行仍核对原作业，不自动重交。
- 部署项目设置收进二级菜单，主区展示当前绑定和常用计算设置；不完整或不合法的目标、目录和资源在准备前提示。

## 保留的失败与边界

科学回归第一次 GPUMD 夹具替换错误造成重复 seed 指令，真实引擎解析拒绝；输入、快照和退出记录保留，修正为单 seed 后用新隔离目录通过。当前通用 `validate` 不等同于完整 GPUMD 命令语法检查。早期界面回归也暴露了旧模拟接口缺失、旧夹具空队列、新默认值归一化及测试导入路径问题；修正后全量重跑，失败日志保留。新增翻译曾与既有键重复，TypeScript 拒绝构建，删除重复后通过。一次打包因下载连接超时失败，最终改用本地已安装且版本匹配的 Electron 44.5.1 分发目录打包，保留下载失败日志；不改变运行时版本。

便携测试首次重开时，程序已正确直接恢复部署页，观察器却只等待计算流程页而超时。截图、首次报告和已保存时长保留；观察器改为接受这两种合法恢复入口，再改一个新时长、完整退出/重开并准备通过。没有为迎合观察器修改产品或重建流程。

本轮桌面测试使用明确标注的合成科学复核元数据，只验证真实准备、绑定和恢复；没有把该元数据当作 AI 科学复核。Codex 仅实际创建/恢复零 turn 线程，未调用模型生成新内容。没有提交用户当前计算。新模型推理、真实新 SSH 提交、全新安装、AOTI、PyDyn NEB 和尚未实现的 TorchNEP/主动学习/外部 DFT adapter 为 `not_run`。

v0.18.5 之前未曾保存的纯页面内存内容无法事后重建。已保存部署和真实运行保留；没有清理会话或改旧项目授权。正常实例 SSH、凭据、8 个环境、2 个旧项目及其策略和真实运行状态已做保护核对。
