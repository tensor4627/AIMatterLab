# 1.0.2-dev.16：恢复交互式登录与服务复用

修复 dev.15 在用户实际配置目录无法打开密码登录终端的问题。本机实证显示 `.config` 及其终端运行副本带 Windows Low integrity 标签，复制到该目录的 Electron 以 Low token 运行，调用 WSL 被拒绝，尚未到密码认证或远端 Python 阶段；普通 Node 与同一保存连接的本地参数检查正常。dev.15 的隔离目录检查通过，未覆盖这条实际运行路径，不能视为用户流程通过。

终端可执行运行缓存迁至独立的用户本地执行缓存，并检查实际执行能力；既有配置目录、凭据、连接、环境和作业不迁移、不改 ACL。登录操作使用原保存的客户端、主机、用户和路由，不因服务能力失败而隐式换连接。

界面按用户指定流程组织：保存连接后在 Studio 终端人工输入密码／验证码；同一登录尝试的认证得到真实确认后自动接入普通 shell。首次服务配置由用户明确执行并保存登记，后续复用原服务；终端操作权与服务调用权分别交接给 Agent。准备认证时不发新的登录，不依据提示符推定成功，不重放未知任务。
