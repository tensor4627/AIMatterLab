# 1.0.2-dev.12 补充：SSH 服务登记与会话交接

本次修复针对交互登录后服务与 Agent 无法交接、返回共享终端后仍无法交接，以及每次登录重复设置的问题。沿用工作目录的 dev.12 版本，不覆盖同代并行的模型 Harness 改动；本记录仅覆盖 SSH 连接流程。

## 操作流程

| 场景 | 操作与实际行为 |
| --- | --- |
| 首次配置 | 在“连接计算资源 → 作业服务设置”中，完成 SSH 登录后首次设置；真实健康状态与工具核对通过才保存该连接的服务登记。 |
| 日常新登录 | 人完成登录/验证码，点击“登录完成，交给 Agent”；已登记服务按原身份、端口和版本复用，并单独授予当前对话使用权。 |
| 服务缺失或环境变化 | 提示需要维护；设置中检查或明确更新，不自动安装、启动或升级 worker。未登记或需要修复的普通终端可交给 Agent 协助环境配置。 |
| 服务已就绪 | 终端仍承载服务协议并保持只读；“交给 Agent / 我来操作”变更当前对话的服务使用权。人工收回不受 Agent 正在回复限制。 |
| 返回交互终端 | 设置中明确断开本次服务通道，经确切停止与恢复确认后恢复原 shell；服务登记、远端 worker 与真实作业保留。同一会话再次交接使用普通终端，设置中可显式接回服务。 |
| 检查与更新 | 当前通道检查只读实际健康状态和工具，不重放 bootstrap；更新是释放当前通道后的单独操作。调度器配置也移入连接设置。 |

终端工具栏移除服务首次设置、停止和调度器表单，只保留交接、状态核对和明确结束 SSH 的入口。保存服务登记不表示本次登录已完成，也不授予项目、引擎或提交作业权限。

## 状态与兼容

- 新增版本化 `ssh-service-registration` 本地登记，包含连接配置摘要、服务身份、固定运行版本、实际端口、核对时间和工具证据。不会保存会话、认证结果、令牌或 Agent 授权。更改环境/路线使登记进入维护状态；仅改显示名称不要求重复设置。
- 旧来源记录只在具备完整身份、实际端口和核对时间且配置版本精确匹配时迁移。缺少证据时不猜测。既有 SSH 连接、凭据、计算环境、授权与真实运行状态保留。
- 新增 `reuse_only` 通道意图。日常复用验证现有缓存和已启动 worker 的认证健康状态，跳过暂存与 bootstrap；改变同一请求的复用意图会被拒绝。连接辅助层缓存仍可按本地版本核对/更新，worker 不因此升级。
- 服务使用权绑定准确会话、尝试、服务连接、提供商与当前对话/任务。未交接、人工收回、切换对话或通道变成 unknown 后，旧工具令牌不能继续调用；迟到结果不能恢复授权。模型工具发现可先完成，实际调用仍要求当前授权。
- 聊天区同时核对当前对话授权与实际工具状态。服务已连通但未交接时提示在终端交给 Agent，不再让人通过重连服务商绕过交接；旧工具状态不能启用发送。人工收回即使未改变资源选择或服务就绪状态，也会使待发准备失效并保留草稿。
- 不再因为接服务而关闭 Agent。交接已有对话先恢复其实际上下文；原生空对话跨终端/服务通道切换时，复用既有、留存迁移证据的空对话恢复流程，保留工作流、项目与环境。不会发起模型回复或重放历史工具。
- 服务代码及最低 Python 3.9 沿用 dev.11；本轮不改变科学引擎或数值执行。内置环境配置指引和逐连接生成指引同步此流程。
