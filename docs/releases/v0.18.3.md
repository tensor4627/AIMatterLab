# v0.18.3 · Codex 空会话恢复

日期：2026-10-26。本代修复 `studio:agent.rpc` 报“此空会话尚未保存，当前进程无法恢复”的会话恢复问题。原始测试记录保存在 ignored `.studio/v0183/bugfix/`。

## 原因与行为

Codex 创建了会话 ID，不代表已经生成可从磁盘恢复的聊天记录。空会话可能只存在于当前 app server 进程中；切换科学工具上下文、应用上下文预算或重启桌面会更换进程。旧版直接按 ID 恢复，收到 `no rollout found for thread` 后统一报成“空会话”，并要求另建会话。模型目录查询还可能提前触发这一失败，阻止连接完成。

协议参考 [OpenAI Docs：Codex app server](https://learn.chatgpt.com/docs/app-server)。创建、发送与恢复是独立操作；此处空会话落盘行为以项目固定版本 `0.163.0-alpha.11.2` 的当前实测为依据，没有升级协议或放宽隔离设置。

现在区分可证明为空与历史不明确的会话：

- 主进程持久化真实原生会话的生命周期。只有明确从未接受消息的空会话，才自动建立新的原生连接，保留已记录的模型选择并继续管理原来的计算流程。
- 首条消息发送前先记录待确认状态。连接中断或结果未知时不能自动重发；观察到真实 turn 后不能重新归类为空会话。
- 旧版本没有生命周期证明，或者已有历史无法读取时，在 Agent 面板显示“重新建立对话连接”。用户点击后为同一流程建立空白聊天连接，保留并归档原本地记录；不伪造或承诺恢复不可读取的聊天历史。
- 模型目录等独立查询不再隐式恢复失效会话。修改上下文预算也经过同一套恢复逻辑。
- 计算流程 ID、参数、输入、人工复核及运行关联保留；旧原生会话 ID 退休，新 ID 通过主进程事务绑定。执行结果未知时先核对原请求，不能借恢复对话绕过核对。

恢复操作不会发送消息、执行计算或改变项目授权。只有原生服务返回不同且明确为空的真实会话，才能进行绑定；保存失败或用户切换到其他会话时不得覆盖新状态。新 IPC 经过发送者和当前会话身份检查，渲染进程与 MCP 不获得额外系统权限。

## 兼容性与限制

新增生命周期记录属于兼容性增补，不清空旧会话或流程。SSH、凭据、已登记环境、项目授权和真实作业均保留；兄弟科学引擎源码不变。不能证明为空的旧会话需要一次明确重建操作；新原生聊天连接不继承无法读取的旧聊天历史。

本轮未发送新的大模型消息，不能据此宣称模型规划质量、TPS 或新账户登录已验证。新 SSH 作业、远程实时调度、全新机器安装、Materials Project 实查、AOTI 及未实现的 TorchNEP/NEPMaker/ActiveMiao/外部 DFT/PyDyn NEB 适配均 not_run。短例只验证限定工程链路。
