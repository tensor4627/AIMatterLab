# 1.0.2-dev.17：认证完成后的终端接入与回执恢复

用户报告 dev.16 在交互式密码输入后返回通用错误。本机只读检查确认原 OpenSSH master 的 PID、启动身份、客户端与参数、私有控制目录和 socket 均匹配，固定本地 `-O check` 返回同一 PID，认证实际已完成；桌面 broker 却仍报告等待认证，没有普通 shell。检查未读取认证内容、执行远端命令或重新登录。

审计与隔离复现确认两个问题：登录完成 RPC 仍使用通用 5 秒预算，而合法的检查与建终端可超过该预算；普通登录还额外强制远端 `printf/id` 的输出及用户名精确匹配，使受限 exec、启动公告或规范用户名差异可能阻断普通终端。旧错误被界面重新包装，未保留原始安全错误码，因此不能从旧报错反推出单一失败原因。

本代普通登录仅依赖严格的原 OpenSSH 本地认证证据；同一 `-O check` 前后重新核对 PID/start/boot、真实 exe/argv 及私有目录和 socket 的 UID/inode，缺失或变化即拒绝。普通终端不要求额外远端 exec，服务仍独立核对远端环境、身份、健康及工具。依据与约束见[普通 SSH 登录认证](../development/ssh-login-authentication.md)。

登录完成预算调整为 60 秒，并以明确的 `terminal_login_unknown` 保留原 broker。新增仅人工界面可用的只读登录状态查询，绑定原 connection/request：迟到完成只能采用原 shell，不重新登录或打开第二个 shell；失败／未知后不自动 POST 重放，明确继续由用户操作同一请求。界面保留安全错误码和动作阶段，资源选中失败与认证失败分别显示。
