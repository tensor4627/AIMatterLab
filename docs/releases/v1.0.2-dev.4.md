2026-11-10，用户实际启动 dev.3 时报告失败。原始日志先记录 worker 资源目录不可用，随后记录同一临时解压目录的前端文件加载失败。dev.3 的包内字节和物理 worker 文件经再次独立核对完整；在新建的隔离配置及 TEMP/TMP 中真实运行旧便携包后，已复现第二次启动使第一个仍存活实例的物理 worker 目录从存在变为消失。此前静态核验没有建立实际启动或多次启动的正确性，不能替代用户失败记录。

## 本轮调整

- 便携启动使用每次启动独立的 NSIS 插件临时目录，避免不同启动器在 Electron 单实例检查之前共用、删除同一个构建级临时目录。
- 根据当前固定 electron-builder 26.15.3 的实际 `buildInstaller` 行为，`portable.unpackDirName=true` 才会不生成固定 `UNPACK_DIR_NAME`，落到 `$PLUGINSDIR/app`；该版本文档对 false 的描述与实现相反。本仓测试调用实际 builder 方法检查 default/false/true，而不修改依赖或复制第三方模板。
- 版本与输出目录统一为 dev.4。保留 dev.3 产物、用户日志及既有 `.config`，不重置连接、环境、授权、登录或作业；不改科学引擎。
- 新的包核验独立检查物理 worker 全部文件、Python/资源/打包闭包，以及与桌面真实资源读取器一致的根目录；另做实际便携启动与连续启动检查。
