## SSH 登录和原连接核验

测试者截图中的 `ssh_master_unavailable` 是主连接不可用的统一提示。在真实回环 SSH 端点保持 A 的密钥终端在线时，0.1.25 会先向交互式 B 提交密钥。测试服务拒绝后，B 未进入密码提示，失败原因也从窗口中消失。修复后优先尝试交互式认证，真实登录失败的输出仅在对应的人类登录窗口中可读。测试者的实际服务端拒绝原因尚待其环境确认。

对于另一个现场错误 `ssh_control_timeout`，一次本机核验超时会保留原登录和终端。需要认证的操作等待同一主连接重新通过核验。独立 Electron 验收中，在 A 保持在线时，B 以原请求完成密码与第二步认证，再切回 A 的原 Shell。[Windows 与 WSL SSH 对照和验收](aimatterlab-ssh-multilogin-unreleased.md)

## 重登后恢复已分配的会话

旧主连接已确认中断时，从原配置成功重登会核对配置唯一标识、实际主机、登录账号和原总工作区。核对一致后，新主连接接替旧连接，各会话分别恢复原有终端或服务权限，并继续使用原工作目录。多个同名配置按各自身份处理。旧版本记录缺少用途时，用户在原会话说“重新申请租约”，桌面可结合唯一的已选资源与可信历史重新核验。

从正常登录入口覆盖了多会话恢复、重登并发、撤权、主动释放、同名异机、账号或工作区变化、桌面重启和旧消息迟到。恢复用例同时检查旧终端输入和作业提交记录。[设计与验收条件](../development/cluster-resource-workflows.md)
