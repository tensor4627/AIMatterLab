# Agent 会话工作区与附件验收

2026-11-22，开发分支 `codex/chat-turn-followups`。本轮沿用 0.1.29 包版本。需求和各阶段验收场景来自[会话优化计划](../development/agent-conversation-ux-roadmap.md)。

## 使用入口

在输入框左下角点击回形针可多选文件，也可拖入文件或粘贴剪贴板图片。点击附件名预览，点击旁边的移除按钮从草稿取下。可以只发附件，也可以在回复进行时把附件排入下一轮。草稿、队列和历史保存附件引用，用户选中的材料保存在本机桌面配置里，发消息时才交给该会话的服务商。

| 材料 | 模型收到的内容 | 范围 |
| --- | --- | --- |
| 文本、CSV、日志、计算输入、源码 | 原文件的可读文字 | 支持 UTF-8 和带 BOM 的 UTF-16。 |
| PDF、DOCX、XLSX、PPTX | 在本机提取的文字、单元格或幻灯片文本 | 扫描 PDF 需先做 OCR 或以图片发送。复杂排版、图表和嵌入媒体需要单独选为图片。 |
| PNG、JPEG、WebP、GIF | 服务商协议对应的图片输入 | 由选中模型或适配器的实际图片能力决定。自定义 API 和 Qwen 模型可在模型配置的「支持图片输入」中声明能力。 |

单条消息最多 8 个附件，图片上限每张 8 MiB，文件经解析后的有效载荷合计上限 16 MiB。单份文档原件上限 20 MiB，每份提取文本上限 256 KiB。超限、缺少文本层或图片无法解码会给出具体反馈。图片输入的核验使用本地模型协议服务。[文件解码](../../frontend/features/conversations/read-chat-file.ts) · [会话附件存储](../../agent/sessions/chat-attachments.mjs)

## 验证方法与边界

桌面整链路在前端构建且 DSH 已准备后运行 `node scripts/native-chat-turn-check.mjs --attachments`。运行使用新的本机配置。已发送的第一张图片在接口端解码为预期的 3×2 像素图。A 等待模型时，用户在 B 输入草稿，A 仍能发送排队的 CSV。停止 A 后续发保留原先的半段回答，随后还可用只有文件的消息开启新回合。原始回执和图片保存在忽略的本地验证目录。

科学证据的历史预览展示选中时的快照。再次发送时核对当前来源和权限。日志缺失开头时无法建立绝对行号引用，界面会说明原因。需要比较的文件或参数由用户在原审阅界面保留基线。分支创建、聊天归档和停止回复均不提交、复制或取消作业。
