## 调整

- 标准 MCP 表单明确没有输入字段时，只展示请求说明、可用的命令信息和接受/拒绝；不再展示空 JSON 编辑框。存在字段、自由输入或无法证明无输入的未知格式继续保留编辑。接受仍提交原有空对象响应，不自动批准，不改变请求所属对话、重复响应或失效处理。
- 普通聊天、流程、SSH/本地终端、私有定义及追加消息都携带本次请求的规划开关，明确覆盖旧讨论、摘要与恢复历史里的旧状态。非法开关值在上下文或 worker 操作前拒绝；界面提交时固定本条消息的模式，不让等待期间的状态变化混入该请求。
- 修复终端路径原先丢掉 `planningMode`、只发送聊天/终端说明的问题。规划已开启时明确说明已开启，不再要求再次打开。能力范围与模式分开：只有三个终端工具时可以讨论设计；正式工作流和科学输入编写仍需用户明确选择有授权的作业服务，不自动切换资源、创建流程或扩大终端权限。
- 界面在终端规划时说明实际能力，并提供显式“连接作业服务”入口。普通讨论后开启规划，在同一对话创建并持续更新同一流程；已有流程关闭开关后仍按原规则讨论和调整，不隐式创建替代流程。
- 同步终端使用指导：本次桌面内分离视图保留终端，正常退出关闭本次交互终端；重开后由用户选择保存项新建。保留 dev.6 的退出关闭、保存项删除，以及 Codex 版本差异仅 warning 的规则。
- 任务规划、终端交接、项目/文件共享与执行批准保持独立；不因此运行 GPUMD、提交 Slurm 作业、改项目授权或触碰科学引擎。
