# 1.0.2-dev.18：登录后一次交接终端和作业服务

用户完成 SSH 密码／验证码登录后，只需点击“交给 Agent”。桌面复用原 shell 和已认证的基础连接，在该人工动作内首次部署、核验和登记 worker；以后复用已校验的缓存。首次 worker 准备放在交接时进行，普通登录仍立即进入可用终端。没有额外服务认证、连接或授权按钮。

`agent/sessions/ssh-terminal-handoff.mjs` 组合既有真实终端交接与主进程服务控制。先核对原终端、创建或恢复真实对话并授予原 shell，再准备独立服务通道，验证后授予同一资源／对话／项目上下文的服务能力并重新绑定工具。一次“我来操作”收回本次组合交接的两项使用权，保留基础 SSH、服务通道、worker 和作业。多个 shell 的组合使用权以最后一次交接为准，旧 shell 接管不撤销其他 shell 的新服务交接。后端仍逐项验证能力，服务协议不占用交互输入。

首次部署保存登记；以后的人工交接使用 `reuseOnly`，不升级 worker，不重传全量 worker。主进程专用 `connectForAgent` 可带 `startCached`：仅在已校验全部缓存代码、私有目录、服务标记及原运行身份，并观察到端口明确拒绝连接时，启动该同版本缓存 worker 一次。超时、错误身份、未知状态及未确认请求不触发启动或请求重放。普通检查／高级手动复用仍保留原只读语义。

Python 或服务准备失败时，已交接的普通终端继续可用，并返回固定服务错误供界面展示；Agent 可通过原终端与逐连接环境指引协助修复。准备期间允许用户接管；后端原会话操作权与上下文核验，以及前端操作序号，阻止迟到结果覆盖接管或新操作。切换资源／对话不能把服务授予新来源。服务工具不扩大项目授权，正式科学执行仍走既有复核流程。

默认终端只保留登录、交接／接管和连接操作，另开／关闭 shell 收入“更多”。移除服务独立操作区；连接列表每个 SSH 只保留一个登录动作，Python 配置和服务维护收入连接编辑的高级区域。已有连接、密钥引用、环境登记、项目授权和真实运行记录均保留，无数据格式迁移。
