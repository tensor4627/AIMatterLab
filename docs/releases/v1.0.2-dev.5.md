# 1.0.2-dev.5：持久终端运行资源与 Codex 能力兼容

2026-11-10，用户在 dev.4 便携包打开已保存 SSH 连接时遇到终端不可用，并报告当前 Codex CLI 0.167.0-alpha.3.2 的兼容检查失败。本代只调整桌面终端运行资源、恢复入口和 Codex 连接校验；不改科学引擎，不清空配置或重新提交作业。

## 调整

- 便携版的后台终端服务曾从 NSIS 临时目录启动。桌面退出后，存活服务丢失按需加载的 PTY 工作文件；本代将经过完整内容校验的 Electron-as-Node、终端服务与 PTY 依赖闭包放到配置目录中的稳定、按内容版本化目录。只发布完整资源，不删除仍可能被存活终端使用的旧代目录。
- 保留旧 `broker.bin`、原会话和未知连接尝试；新增加密的 `brokers-v1.bin` 版本 1 索引，为每个会话保留所属服务。正常打开不会自动重开状态不明的连接。界面可刷新状态，或由用户明确选择“保留原会话，另开新连接”；同一明确请求不会重复创建终端。MCP 仍只能使用已交接的终端，不能打开新连接。
- Codex CLI 版本与协议生成参考版本不同，只显示 warning，不要求升级或降级到指定版本，也不据此禁用连接或发送。实际 initialize、有效配置、技能、MCP 与模型能力上限检查仍保留；检查失败给出分阶段诊断，不自动重连或重发消息。
- 当前 CLI 失败的实际原因是全局配置含有桌面版新增字段，整份配置严格解析在握手前退出。本代继续严格校验 Studio 自己的配置，使用 CLI 的正常外部配置读取，并回读实际生效的限制；不修改用户 Codex 配置、授权或模型缓存。
- 沿用 dev.4 每次启动独立解压目录的修复和此前四项问题修复；旧包与旧证据保留。此版为未签名便携测试包，不代表正式公开发布完成。
