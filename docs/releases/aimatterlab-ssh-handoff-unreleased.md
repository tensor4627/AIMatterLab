# SSH 终端交接修复

2026-11-17 · 已在 0.1.7 标签后的源码验证 · [更新日志](../../CHANGELOG.md)

## 现场与复现

实际观察到的 Windows 窗口显示 0.1.6、SSH 已连接、终端由 Agent 操作，右侧已经收到模型回复。错误详情标明「调整终端」和 `terminal_context_changed`。在 0.1.5 标签上用该版本的尺寸请求也能稳定复现同一错误。

发送消息会更新本轮请求的序号。旧版用同一序号判定终端显示是否仍属于当前对话，导致跨过这一步的尺寸请求被误判为切换了对话或计算资源。前端随后把后台布局错误显示成了操作失败。另一个可复现的时序问题是，交接前发出的状态读取晚于交接回包时，能够把桌面记录的操作方改回旧值。

## 交接流程

1. 登录成功后，主进程核对 SSH 连接、配置及版本，并选定计算资源。选择失败时可在原终端重试。
2. 空白对话可以预留当前终端。发送第一条消息后，只有对应的新对话能接管它。在这段时间取消交接会撤销预留。
3. 终端显示跟踪会话归属、资源和终端操作权版本。同一对话的新消息可以与尺寸同步并行。切换资源、收回或关闭终端会使对应的旧请求失效，迟到的回包无法倒退操作权。Agent 读写仍需当前对话和终端的有效授权。
4. 作业服务在回复期间就绪时单独显示等待状态。回复结束后再核对原终端授权、服务身份及连接请求。用户已经取回终端或服务时，延后的交接失效。
