# 1.0.2-dev.11：Python 3.9、作业服务环境与接入恢复

本代降低作业服务的 Python 下限，补全本地／集群接入指引，并修复本地未分发的接入被误判为 Python／停止通道未知的问题。保留 SSH 登录、凭据、项目授权、科学引擎和真实作业。原始证据位于忽略目录 `.studio/ssh-user-failure-20261111/` 和 `.studio/python39-compat-20261111/`。

## 功能与兼容

- 独立实际 CPython 3.9 环境验证后，worker 安装声明与 SSH loader 的下限由 3.10 降至 3.9。服务解释器与科学引擎登记仍独立，未降低各引擎依赖要求。
- 每条保存的 SSH 连接可选择已有 Conda/venv/module 环境的 Python 和激活命令。保存为版本化本地配置，生成不包含激活脚本、主机或凭据的专属 `SKILL.md`；后续明确接入服务时在原 SSH 会话应用配置。
- 原 SSH 空闲时，仅修改服务环境可承接原会话和选中资源版本；保留进程、会话和操作权版本，撤销旧 Agent 授权。活动、未知或待分发服务阻止承接。主机、路由或客户端变化不能走此路径。
- 激活脚本按受限长度的 shell 输入分段，解释器路径独立引用；激活或解释器启动失败有固定诊断，必须收到完整退出与新 shell 输出证明才恢复输入。
- 本地确切未发送的失败保留具体错误并让终端可用；已发送／不明请求继续保留未知状态。取消只针对确切原会话、broker 和接入请求，不因切换资源而误发到新会话。
- `studio-compute-workflow` 新增本地／集群作业服务接入参考，区分登录、环境激活、服务身份／工具就绪和计算项目授权。

Python 安装声明属于 worker 文件指纹：当前新服务为 `57cc5d274c42747e679d`。已明确绑定的旧 `62034ec6cfc1428aaa4d` 服务可按原始完整文件哈希重建其已发布载荷（唯一差异为 Python 安装元数据），保持旧工作流来源，不假称字节相同或自动改绑。仅服务环境更新时承接版本化的运行资源偏好，不修改任何任务或项目授权；主机／路由变化不承接。未经验证的旧版本拒绝替代；没有原绑定的新连接默认使用当前版本。
