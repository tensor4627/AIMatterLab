# 1.0.2-dev.27：真实对话、原终端与作业服务链路

dev.26 的验证没有覆盖完整的真实模型对话。此次在用户实际学校连接上通过正常界面发送对话，复现了终端工具能执行，但作业服务报 `terminal_service_active`，随后输入排队超时、错误恢复收回操作权，以及发送消息时旧读屏报上下文变化。原始失败和真实工具回执保留，不将工具目录可见等同于模型已经成功调用。

真实 ConPTY 还捕获到同一帧半行覆盖的擦除计数表示“原行可见尾部长度”，并非总是完整 500 列；仅接受同一前缀被准确扩展、擦除覆盖完整最终帧且总计不超过 500 列的重绘，再进行原始帧、摘要和响应核验。修复前后原始失败均保留。

本代只改这条链路的十个生产模块，不更改科学引擎或 worker Python 源码：

- 作业服务的 shell 就绪计数标记使用零宽 OSC 提示元数据，避免窄终端折行丢失确认；显示过滤和返回原 shell 的屏障识别只处理本会话生成的准确标记，计数与 fresh resume proof 仍核对。
- 排队的普通终端输入、尺寸、操作权和关闭请求使用与串行服务交换匹配的有界等待；未确认结果保留原 broker，不因为五秒等待就删除健康连接并自动收回操作权。未知请求仍不重发。
- 同一对话中正常消息更新版本时，过期的人工读屏／清单观察丢弃并重新读取一次；真正的对话、资源、来源或操作权变化继续使旧操作失效。Agent 工具授权检查不放宽。
- 同一 SSH 资源的重复附加只核对当前状态，不递增资源选择版本、不撤销既有服务与 MCP 凭证；真正切换／清空仍撤销原能力。
- 切换到作业服务后，先完成原生 Codex 对话恢复，再授予服务操作权。主进程核对的空白对话替换跟随原人工交接重新绑定同一终端；真实对话／资源切换和伪造恢复继续拒绝。服务传输的上下文与本次真实授权同步。
- 原登录尚在选择计算资源时，交接按钮继续等待，避免已显示的 shell 先于连接绑定被交接。
- 无任务、尚未获得对话 ID 的真实 MCP 初始化租约只发布已分类的接口定义，不先读取需要该对话授权的远端隐私策略，消除初始化循环。实际工具调用、已有私有任务的清单和项目权限继续核验；未知接口不发布。
- 本地提前拒绝的权限／上下文请求、被取消的旧状态观察不制造远端故障；真实未确认交换仍保持 unknown，绝不重发。
- 已明确交接的终端写入免除原生桥接的重复确认，执行时仍由 Studio 核对原会话和操作权。原生文件、命令、外部 MCP 和动态工具的隔离规则不变。
- 原生线程的工具名可来自缓存；`runtimeStatus` 不为 connected 时单独显示 warning，不把缓存名当成实时可用证明。
