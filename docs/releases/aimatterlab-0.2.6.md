# AIMatterLab 0.2.6

2026-11-25 · GitHub 源码版本 `v0.2.6`，基于 0.2.5（`563a8c5`）。本轮改进以 [模型对比](aimatterlab-0.2.0.md#真实用例)、[现场问题](aimatterlab-0.1.31.md)和 0.2.5 源码复查为依据。

## 改进顺序与验收

1. **先恢复执行与审批。** 普通聊天和任务规划使用同一审批设置。用明确委托、同轮准备回执及实际项目授权确定一次提交。对照提交前拒绝、需要用户处理和已派发但结果未知三类回执，分别验证可执行的恢复动作。
2. **让 SSH 故障可恢复。** 刷新失败时保留原连接观察，明确显示需要核对的能力。验证新服务失败时仍可从原流程继续，以及同一已登录资源可正常复用。
3. **缩短常用入口。** 从窄窗、收起侧栏和运行记录页验证新建计算，从工作台标题直接进入项目选择。
4. **验证 Agent 续做。** 用「探测已有队列」「保存计算草稿」「明确委托一次短测」作为后续双模型对照。按读取、准备、提交和实际结果分别记账，并记录重复确认和可继续步骤。

[审批模式及作用范围](../development/developer-compute-access.md)

## 内置指导复核

逐份核对 11 个内置技能入口及 26 份引用，包括计算资源、安装、流程创作、路线图、数据、MD、NEB、训练、CV/Bias 和 OPES。科学功能目录的 41 条路线、16 个引擎及 17 项本地源码引用对应当前声明。对照普通聊天、已有工作流、恢复会话和显式共享终端的实际工具及参数、结果和权限边界。

更新计算工作流技能与作业服务参考，使用当前审批设置、继续原连接、状态核对、作业服务和准确的执行回执名称。更新 Slurm 和 LSF 的 Worker 源码引用摘要与范围。其余技能材料及基础运行指引已复核。逐轮提示补充继续可执行步骤与按实际回执汇报的要求。
