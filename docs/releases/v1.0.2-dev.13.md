# 1.0.2-dev.13：交互式集群作业服务流程与便携测试包

本代将当前工作目录中的服务登记、连接管理、Agent 交接和聊天授权修复封装为 Windows x64 便携测试包。完整流程见 [SSH 服务登记与会话交接](v1.0.2-dev.12-ssh-service.md)。同时包含 [dev.12 的模型 Harness 与提示词更新](v1.0.2-dev.12.md)，没有从旧 dev.11 安装包回拷替代当前源代码。

首次登记保存在连接设置，日常登录完成后核对并复用；Agent 服务使用权与协议终端所有权分别管理。明确返回终端后可继续交接普通 shell，未知状态禁止自动重连或重发。内置环境配置指引同步此流程。最低 Python 3.9 与 worker 指纹沿用 dev.11，不改科学引擎、注册环境、项目授权和真实作业。

封包前真实终端复验还修正了 Windows ConPTY 显示填充兼容问题：冷传输确认及暖复用阶段回执可能在完整帧末尾附加显示空格。接收层只接纳当前通道完整 V2 帧外、整行不超过保留的 500 列的纯 ASCII 空格；内容、状态、序号和停止确认继续严格校验，最终停止还必须取得独立的 shell 恢复证明。取消期间的已排队回执只消费、不继续上传。此修改只在连接层，不改变远端 worker 版本。

## 单文件封装修正与构建证据

旧 7z 封装虽然离线字节检查通过，实际 Nsis7z 释放时缺少四个 ARM64 组件；其后 `CopyFiles` 还会复制整份程序，180 秒时仍未结束。该候选保存在 `failed-native-7z/`，没有作为交付结果。最终使用当前 electron-builder 支持的 `portable.useZip=true` 分支：对 portable 目标实际是 `APP_DIR_64` / NSIS `File /r` 直接嵌入文件，不再使用 Nsis7z 与二次 CopyFiles；并非简单更换一个 ZIP 解码插件。

固定 NSIS 编译器也受绝对源路径长度和构建库硬编码四分钟上限影响。构建复用了已经核对的目录包，通过临时、空闲且归属已核对的 W 盘映射和 `--prepackaged W:/win-unpacked --win portable` 缩短编译输入路径。编译进程在内存中仅对准确的固定 NSIS 编译器延长有界时间，保持参数、脚本、环境、原启动函数和 `checkMakensisOutput` 后置校验；没有修改依赖文件或应用源码。最终编译实际约 102 秒、退出 0。W 映射已撤销后才进行最终完整性与原生启动验收，应用没有 W 盘运行依赖。前后 1,265 个源/生成输入哈希一致，摘要为 `d6deea7ccd64847734d5ea00197d0c1b55938e1633d85a2538a5bb5dce02be11`。

原验证工具为 limited 7za，不支持 NSIS handler，失败另存；没有降低字节验收标准。验证阶段从 [7-Zip 官方下载入口](https://www.7-zip.org/download.html) 取得完整只读解包工具，安装程序未执行、未全局安装、未进入产品包。实际 `Type=Nsis / NSIS-3 Unicode / Deflate / Solid=-` 的列出、测试、解包与全字节比对均通过。另有一次调试观察连接未及时断开、阻塞进程退出的夹具失败，修复观察器生命周期后两个启动器均自然退出，旧失败未改写为通过。
