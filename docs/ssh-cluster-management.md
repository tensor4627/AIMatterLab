# SSH 集群管理链路

## 托管 SSH 的日常用法

1. 从计算资源管理入口保存 SSH 连接。Windows OpenSSH 使用本机的 `ssh.exe`，无需 WSL。主机指纹、密码和二步认证都在私有终端处理。遇到网关菜单时，由用户选择资产和登录节点，等进入节点命令行后点击「登录完成，交由 AIMatterLab 管理」。然后核对远端工作区。
2. 可直接请 Agent 查看分区或空闲 GPU。它会选择、租用目标并通过同一连接的会话命令通道或作业服务读取调度器。若有多条候选，回复目标连接名称即可继续。自有、付费、账户和 QOS 依据用户确认的私有配置，空闲量依据调度器实查。
3. 可在同一对话请求环境或工作目录配置。每个会话有独立的命令租约和当前目录。需要交互时可另外打开终端。命令、终端和作业服务沿用已有连接与项目授权。
4. 可在普通聊天明确委托一个独立作业。经授权的作业服务使用原项目、登记环境与输入快照提交，记录实际 run ID 和调度器作业号。用户明确委托按现场脚本提交时，Agent 核对脚本和资源限制后可使用自己的命令租约，并读回调度器作业号。多步骤、需审阅或可复用的计算适合用任务规划和部署页面。

升级后从原保存配置打开或刷新连接。仍存活的 SSH 终端按原通道恢复，尚在认证时继续原登录。主机校验、密码及验证码由用户在该次登录的私有终端处理。核验等待或超时表示结果待确认。原托管连接确认失效时，可在原配置中选择「重新登录」。桌面核对实际主机、账号和已登记的总工作区后，恢复各会话在原资源上仍有效的租约。作业和未确认的操作继续按原标识核对。

使用「交给 Agent」是明确共享某个可见终端的入口。托管连接的对话租约由聊天工具取得。断线后按原作业标识核对状态。SSH 登录、调度器观察、队列或项目授权及科学结果各有独立凭据。[当前计算规范](software-specification.md#计算资源)

## 本机 WSL worker 管理远端调度器

下述流程适用于由本机 WSL 作业服务管理远端 LSF 或 Slurm 的入口。模型和技能编排保留在本机，已有集群账号连接到调度器。该服务路径使用已安装的 OpenSSH、Python、调度器和登记的科学引擎。人工认证、隧道和原有流程恢复按实际入口核对。[连接引导实施契约](design/compute-connection-hil.md)

## 设置和协作

1. 先连接本地 WSL 作业服务：选择已安装发行版，只有一个时会预选并展示。服务目录与端口放在高级设置；从已有计算流程进入时恢复该流程的原来源。连接后发现并复用已安装环境，不自动安装科学软件。[WSL 命令说明](https://learn.microsoft.com/en-us/windows/wsl/basic-commands)
2. 进入“SSH 集群”，导入本机已有连接，或填写主机与明确的远程用户名。优先复用已有密钥、SSH agent 或外部转发入口。应用只把所选连接的必要字段填入表单，不复制全量记录；地址、端口和密钥引用默认遮蔽。客户端和密钥引用须属于对应的 Windows / WSL 命名空间，不自动转换路径或复制私钥。[OpenSSH 密钥管理](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_keymanagement)
3. 选择 LSF 或 Slurm。已有入口和内部 Slurm 登录节点可以建立两份配置，后者填写内部跳转 Host。内部跳转使用集群已有认证；AIMatterLab 不额外启用 agent forwarding、不复制密钥。既有密钥模式沿用原客户端配置，新受控人工认证模式显式禁用 agent forwarding。
4. 需要二步验证时选择「交互式登录」。如果验证后还有网关节点菜单，请使用 Windows OpenSSH，在私有终端选完节点后点击交接。保存配置时核对当前客户端所在环境的密钥引用；更改认证模式会保留已有客户端。首次登录请从可信渠道核对主机指纹，由用户亲自完成密码、口令、验证码或设备确认。SSH 登录与调度器及科学环境各自核验。
5. 已认证连接足以执行批处理时无需额外隧道。确需转发时，在私有认证界面的可选区域审阅目标与回环监听，再明确启动自有转发。AIMatterLab 不接管外部入口；“监听已建立”不表示目标服务已验证，也不表示目标 SSH 已认证。[OpenSSH 转发与连接复用说明](https://man.openbsd.org/ssh_config)
6. 保存连接与“允许当前项目使用此连接”是两个动作。SSH 配置、集群资源上限和项目授权只由用户在设置窗口修改；认证和连接检查不改变授权。Agent 只能提出配置草稿。
7. 执行只读探测，确认命令可用性、队列 / 分区和注册的 Python / 引擎路径。登录节点没有 GPU 不等于计算节点不可用；发现 Python 或调度器也不等于科学模块通过验证。
8. 让 Agent 协作检查 modules、虚拟环境、CUDA / LibTorch、引擎路径、队列策略和资源数量。调用 draft_cluster_setup 提出修改，在“提交 Skill”页审阅后保存。
9. 配置每次保存生成新版本和实际 SKILL.md，位于本地 worker 的私有运行目录。read_cluster_skill 可读取已授权项目对应的版本。已准备作业绑定环境快照与版本；配置变化后必须重新准备并审阅。
10. Agent 使用 present_task 填写中央流程、参数和缺失信息，再使用 prepare_cluster_run 准备未提交的模块草稿。

认证过期或连接失效后，从原任务 / 运行页选择“核对原作业连接”，按该运行保存的连接版本重新认证，不改用当前新配置。恢复仅继续核对和监控，保留原作业身份与最后观察状态，不自动重新提交；关闭认证或隧道也不取消已提交的集群作业。

同一服务商的 CLI 登录供其关联项目复用；本版记录项目默认服务商，不声称提供多个同服务商账户的并行隔离登录。

## 提交和状态

准备阶段只在本机复制输入、计算哈希、生成批脚本，不执行 SSH 上传或调度提交。用户打开远程任务页，查看参数和完整脚本。修改参数时先保存新的不可变草稿并预览其脚本，第二次点击提交才执行。

本机输入检查通过后，worker 在发送调度请求之前先持久化“提交结果未知”。随后上传作业自己的输入与小型验证辅助脚本，调用调度器，记录远程提交标记、作业名称和 Job ID。辅助脚本位于各自作业目录，属于单次运行产物；不会安装远程 Agent 服务。

Slurm 使用 sbatch 的机器可读 Job ID，监控 squeue 和 sacct。LSF 使用 bsub 的提交回执，监控 bjobs 长格式中的完整 Job ID、名称和状态。没有取得提交回执时，核对远程标记和唯一作业名；不自动再次调用提交命令。[Slurm 提交文档](https://slurm.schedmd.com/sbatch.html)、[LSF 作业生命周期](https://www.ibm.com/docs/SSWRJV_10.1.0/lsf_users_guide/job_lifecycle_lsf.html)。

调度器显示完成不直接证明科学成功。应用核对属于本任务 nonce 的进程退出收据、执行节点验证报告与产物。收到明确进程退出码后更新真实状态；断线、身份不符、缺失收据或无法确认时显示 unknown。

取消前必须核对完整作业身份，只取消本任务已确认的 Job ID。连接恢复和应用重开只恢复监控，不重提 unknown 作业。集群调度器拥有计算进程，因此关闭桌面或停止本地 worker 不会停止已提交远程作业。

## 资源与科学边界

- 队列、CPU、GPU、内存、时限受保存的集群上限及当前项目授权检查。
- 默认单节点。LSF memory_mb 表示作业合计预留：按 slot 的站点会按 CPU 数均分，按 job 的站点使用合计值。必须与用户确认真实站点策略。内存限制显式携带 MB 单位。[LSF 内存单位](https://www.ibm.com/docs/en/spectrum-lsf/10.1.0?topic=o-m)。
- 两个调度器都避免继承提交端的模型代理或密钥环境。只显式传递登记的加载变量、仓库路径和经过审阅的初始化脚本。
- 科学验证在已分配的执行节点运行，保留调度器的 GPU 映射，记录 Python / CUDA / 仓库版本。采样复用真实 pyGAS 序列化产物、邻居和导数检查；显式 AOTI 不兼容时失败，不替换后端。
- 执行节点验证失败时不会启动科学引擎。批脚本对验证和引擎执行设置总时限。
- 初版主要面向单节点 MD、增强采样与训练。复杂 MPI、多节点训练、作业数组、依赖调度和远程断点续算仍需单独适配与验收。

## 文件和保密

“远程文件”只读取用户登记的根目录，拒绝路径越界和符号链接逃逸；内容分块返回。下载由主进程写入用户选定的文件，核对大小和 SHA256 后完成。

连接信息保存在应用的私有配置 / worker 状态中，不进入 Git、发布说明或默认报告。MCP 的集群列表不返回地址、端口和密钥引用；传到集群的验证输入也不携带这些字段。验证摘要使用脱敏路线标识，不公开实际连接值。

## 初始版本验证范围（历史记录）

实际既有连接的两条路线已通过本地及 WSL worker 的只读检查，分别确认 LSF / Slurm 可用；没有提交真实集群作业。调度器生命周期由本地测试服务检查，包含真实上传包解压、验证辅助脚本和进程退出收据。它们是基础设施证据，不是实际集群科学计算证据。
