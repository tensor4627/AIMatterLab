# GPU Sampling Studio：以任务为中心的交互设计

日期：2026-10-25。状态：联网调研后形成的第二轮设计基准；下述目标布局与验收标准尚未全部实现。第一轮修复独立验收，不以这份设计文件代替运行证据。

## 产品的中心

Studio 帮助用户把科学意图变成可审阅、可执行、可追溯的计算。用户的主要工作是描述目标、确认重要科学选择、查看进展与结果。环境探测、工具衔接、输入生成和提交准备由 Agent 与确定性服务协作承担。

界面统一三个概念：**会话**记录目标与交流，**计算流程**保存可修改的方案，**运行记录**对应一次实际执行。“任务”页汇总运行记录。同一会话通常管理一个流程，一个流程可以有多次明确执行后的记录；草稿保存不能显示成计算已完成。

页面空间和操作便利性按这个顺序分配：**当前对话与计算流程 → 最近的工作与任务状态 → 任务所需资产与工具 → 环境及偏好配置 → 技术诊断。** 这是一项产品决策，来自用户的使用目标，并非要求所有科研软件遵循同一种布局。

## 空间与导航

左侧上部保留项目切换、一个带文字的“新对话”和搜索。侧栏的主要高度用于最近会话，按项目组织；选中一条会话时同时恢复它的对话、当前流程和相关运行记录。重命名、归档、删除进入条目的更多菜单，并支持键盘操作。

“任务”是始终可见的一级入口，显示运行中、排队和需要处理的数量。进入后统一查看本地与集群作业，用筛选切换位置，不为每个引擎另建一套监视页面。队列未连接时保留最近观测和时间，并明确状态未知。

工具仍可被直接访问，但聚合在一个“工具”入口；MD、增强采样、训练、主动学习、数据、查看器和算力管理进入其二级分类。任务页中的相应步骤也能直接打开所需工具，不要求用户先学会工具树。常用工具可以固定，但固定和搜索不能替代清楚的默认导航。

主工作区围绕当前会话。对话与当前流程可以并列，并提供明确的“对话优先 / 流程优先”切换；记住用户选择，避免在回复过程中突然交换位置。没有流程的普通对话不展示一大片空参数表。首次使用可以给出少量任务示例；存在历史工作后，优先恢复工作，不反复展示欢迎页。

设计起点是让对话与流程合计占可用工作区约四分之三以上；这个比例用于原型比较，不是硬编码要求。窄窗和大字号下采用有状态的单主面板切换，保留对话、流程和任务入口，避免把全部内容挤成小字。

底部默认只显示紧凑任务摘要。日志、终端、GPU 细节在用户展开后占用空间；存在需要处理的问题时显示有意义的提示，不自动弹出大面板盖住正在编辑的参数。

| 高频意图 | 入口与结果 | 目标操作成本 |
| --- | --- | --- |
| 继续与 Agent 对话 | 当前会话输入框 | 直接输入，无设置前置 |
| 新建对话 | 侧栏带文字按钮 | 1 次点击 |
| 查看或调整当前流程 | 对话旁的流程面板/固定切换入口 | 1 次点击，仍是同一流程 |
| 找回以前的工作 | 侧栏会话列表与搜索 | 选中后一起恢复聊天和流程 |
| 查看本地或集群任务 | 一级“任务”和运行摘要 | 1 次打开列表，再 1 次打开详情 |
| 修改工具或环境设置 | 工具二级页、项目菜单或分类设置 | 不占据日常主工作区 |

## 从自然语言到可执行流程

自然语言请求 → Agent 检查已有结构、模型、环境和软件契约 → 在同一流程页填好建议 → 用户确认关键选择并微调 → 复核当前保存版本 → 用户点击执行 → 持续查看状态和结果。

各步骤是同一个工作对象的不同阶段。编辑一个参数不重新创建流程，不要求复制 JSON 回聊天，不丢失已确认文件。仅在用户明确要求新流程时新建。

历史切换、字段保存、任务状态查询和日志读取由界面直接调用确定性服务，不必等待一次新的模型回复。Agent 负责理解意图、规划、补全和解释；已知软件规则由结构化契约检查。这样把模型耗时留给需要推理的工作，并减少简单操作中的工具选择错误。

流程首屏应回答：算什么体系、达到什么目标、使用哪个模型与方法、选择哪些关键条件、在哪运行、现在还缺哪一个重要决定。优先展示结构预览、简洁步骤图和关键参数摘要。

参数按用户决策的重要性组织：

- **基础参数**：结构/模型、目标、温度或压力、方法、关键 CV、采样或 NEB 的主要设置、计算规模。结合任务决定其必要性，不把所有模块的字段同时展开。
- **细节参数**：输出频率、数值容差、容量、优化器细项等，使用原软件名称、单位、默认值与说明，按功能分组折叠。
- **技术信息**：哈希、版本、内部 ID、原始 JSON、协议消息，放在文件信息或诊断详情中。

科学选择优先保留用户明确输入与已确认手工修改；未指定时采用对应软件/skill 的适用默认值，或提供有来源、可修改的建议。原子数、CV 维度、文件单位、环境版本等事实必须来自实际文件和探测，不能被过期的手工值覆盖。选择与事实冲突时解释原因，并引导调整选择或输入文件。关键科学条件没有依据时必须讨论，不能为了表单全绿而编造。

参数层级随当前任务变化：原本折叠的容差、容量等细节一旦缺失、越界或影响执行，就提升到当前待处理事项，点击可直接定位。折叠用于减少干扰，不能隐藏阻塞条件。

CV 优先从 pyGAS 原生库与已有模板组合。已有类展示真实参数；确需新 CV 时先讨论公式和参数，再保存自定义定义及数值测试。该科学契约保持稳定，界面简化不改变它。

## 默认可用、按需配置和恢复

内置工具默认可调用，新建计算项目默认启用已实现引擎。用户不需要逐项点击“允许工具”。项目只在实际需要计算资源时确认登记环境、输入目录与限额；可确定的值提供可修改建议，已有项目设置不被静默扩张。

安装、SSH/WSL 接入和队列适配属于初始化流程。完成后复用已登记配置和运行环境记录；日常计算不重复阅读安装说明，不让用户反复提供路径或调度命令。账户与模型在 Agent 的清楚入口选择，路径等高级项进入设置。

主流程以“零可预防阻断”为验收目标。缺失技术字段、错误对象 ID、未保存输入、失效版本应尽量在调用前通过实际上下文检查发现。网络或集群不可用时，保存输入、保留会话并允许继续规划；只停止受影响的操作。

失败提示采用“发生了什么 + 当前保留了什么 + 下一步”的结构。给出一个最相关的恢复入口，技术详情默认收起。可安全重复的只读查询可做有界恢复；写入或提交结果未知时先核对原记录，绝不自动重复提交。运行中、待补充、失败、状态未知使用文字与图标共同表达，不只依赖红绿点。短任务运行通过与科学收敛继续分开显示。

## 统一的视觉表达

每个阶段突出一个主要动作，例如发送需求、复核当前参数或执行；保存、返回、详情使用较轻的视觉权重。入口采用“新对话”“查看流程”“任务”等具体短词，图标辅助识别。内部对象名、工具数量、协议名和授权术语不承担日常导航。

正文、字段说明、状态和按钮都遵循全局字号下限；大字号用重排和滚动保持可操作，不缩小关键说明。相关字段用邻近和间距分组，强调色主要用于当前选择和主要动作，告警色只用于需要处理的状态。深浅主题与中英文共用同一层级，长标签不得挤掉保存或执行按钮。

## 第二轮的实施与验收顺序

1. **先重排主工作区**：会话列表与新对话前置；一级任务入口；工具归组；折叠常驻大终端/队列；保留已选布局。
2. **再缩短流程编辑路径**：同一会话连续更新同一流程，关键摘要前置；细节分组；缺项点击直接定位；从运行记录可回到所属会话。
3. **再打通恢复路径**：连接失败说明、字段预检、保存状态、断线重连与原任务核对；错误必须有下一步，其他区域仍可用。
4. **最后做视觉一致性**：统一组件、字号层级、间距、主次按钮、图标和中英文术语；在真实窗口及大字号下验收，不靠缩小字体容纳更多菜单。

验收按真实意图记录，而非仅统计按钮数：新对话、历史恢复、自然语言规划、手工调整后续填、本地/集群状态查询、网络断开后恢复。记录路径长度、耗时、需要用户输入的字段数、无下一步的阻塞数及是否丢失上下文。

第二轮的目标门槛：高频入口一到两次操作可达；普通对话不要求先配资源；不复制 JSON；手工参数不被悄悄覆盖；离线仍能浏览已保存工作；相同提交不重复产生作业；必要外部故障可解释、可恢复。若关键路径仍有阻塞，不能以截图美观或测试数量宣布界面改进完成。离线规划与只读查询的有界恢复属于第二轮待验证设计，不代表第一轮已实现。

实施时复用已有会话、流程和作业身份，避免为新布局另建状态副本。收起终端或切换窄窗面板应保留连接、未保存编辑与流式请求；用户已有的布局偏好继续恢复。新的紧凑默认布局只作为未设置偏好的初始值。
