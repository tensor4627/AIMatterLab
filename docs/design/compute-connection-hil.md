# 算力连接与人在回路

状态：开发中的实施契约。已有 WSL 环境发现、密钥引用和集群批处理继续保留；本文件不表示新增向导、人工认证或隧道已经通过真实集群验收。实现、软件测试、原生界面验证和真实认证分别记录。

## 用户路径

| 场景 | 首屏必要选择 | 软件完成 | 需要用户参与 |
| --- | --- | --- | --- |
| 恢复已有计算流程 | 确认该流程保存的计算来源 | 核对原服务，必要时启动同一服务，读取现有环境 | 原始来源不完整时选择可证明的来源，不猜其他项目 |
| 首次连接本地 WSL | 已安装发行版；只有一个时预选并展示 | 启动作业服务，发现并登记已安装软件 | 缺失 WSL 时按提示安装；已有软件不重新安装 |
| 集群密钥或 SSH agent | 已登记连接、明确的集群用户名 | 非交互连接检查、调度器和环境检查 | 选择密钥引用、解锁密钥或核验首次主机身份 |
| 已有 SSH 转发入口 | 选择现有入口 | 检查入口与目标认证，保留原端口及密钥引用 | 外部隧道需由其拥有者维护，不接管陌生进程 |
| 需要二步验证 | 选择连接及支持的本地 SSH 客户端 | 准备私有认证终端，核验认证会话，复用该会话 | 用户直接完成密码、口令、OTP、设备确认或管理员要求的步骤 |

“已连接作业服务”“SSH 已认证”“调度器可访问”“执行节点环境已验证”分开显示。连接成功不清空科学缺项，不代替序列化 bias、GPU、模型和短例验证。

## WSL：最小设置与流程归属

1. 使用只读发行版清单提供选择，不自动安装 WSL、发行版或科学软件。根目录和端口位于高级设置。
2. 从已有流程进入时，主进程按持久化流程身份解析原发行版、服务根、端口及服务来源；渲染进程不能给这个流程任意替换地址、令牌或根目录。
3. 首先尝试复用经过核对的原服务。需要启动时，在用户确认的原来源内调用现有部署与启动流程，不先让用户去全局设置切换环境。
4. 缺失旧端口时，只能从相同来源的主进程持有记录恢复；没有证据就提示补充，不能用当前全局默认值代替。
5. 连接后复用已有环境发现与登记逻辑。发现失败显示部分完成：服务可以已连接，而引擎或 GPU 检查尚未完成。
6. 计划、进度和结果携带请求与来源范围。关闭向导、切换流程或来源后，迟到结果不能覆盖另一个流程，也不能杀死已有作业服务和计算。

已有来源的发行版缺失时保留原选择并说明原因。只有没有绑定计算流程的用户，才能明确选择“其他本地来源”，重新审阅后连接；不能把新来源写回已有流程。已连接但实现版本不同或尚未核对的服务，继续显示真实状态，并提供“按原来源更新作业服务”。普通连接只复用服务，不隐式更新；更新后重新核验实现版本，失败不循环重试。更新可能短暂中断监控，已有独立作业不因此重新提交。

部署保存时记录实际服务端口。历史记录缺端口时，先核对同任务、同发行版与目录的唯一端口证据；仍缺失才由用户单独确认。新确认的连接位置经过真实身份核验后单独登记，恢复和工具修复共同使用，不修改旧输入快照或全局默认。存在冲突证据时保持阻塞并说明核对项。启动前检查同目录控制进程与候选端口，健康请求在同一已核验 socket 上发送令牌；连接关闭后不重连到替代监听者。

WSL 连接向导不修改项目授权，不新建替代计算流程，不重提交未知运行。普通无流程对话也可以连接本地服务，但不会因此默选一个计算项目。

发行版清单和状态读取依据 [Microsoft WSL 命令说明](https://learn.microsoft.com/en-us/windows/wsl/basic-commands)。安装指导与运行时环境记录保持分离，日常运行使用已登记环境与其验证回执。

## SSH：配置、认证与路由分层

连接中分别保存：连接引用、客户端及其命名空间、主机及明确用户名、端口、密钥引用、跳板或转发方式。私钥内容不进入项目、工作流、Agent 上下文或发布包。Windows 与 WSL 的密钥路径不可无提示混用，也不自动复制私钥。

默认复用已有密钥、SSH agent 或已有入口。Windows 密钥可使用系统账户对应的 agent；系统服务设置及密钥解锁由用户按提示完成。[Microsoft OpenSSH 密钥管理](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_keymanagement)

必须区分以下路由：

- `ProxyJump` 是本地 SSH 客户端建立的跳板连接。
- 既有 `via` 表示历史的远端嵌套 SSH，不能默默改写为跳板。
- 已有转发入口可能由外部程序或管理员维护，Studio 不按端口号终止它。
- 新建的本地转发由 Studio 明确拥有，默认只绑定回环地址。
- HTTP/模型 API 代理不自动等同于集群 SSH 路由，也不注入计算作业环境。

主机身份必须核验，后台连接不自动接受陌生或变更的主机密钥。Agent 可准备脱敏配置草稿，真实连接及认证由独立界面审阅；认证或连接检查不经过会同时授权项目的保存入口。

“保存连接”与“允许当前项目使用此连接”是两个明确动作。首次设置可以先保存和认证连接，再根据计算流程进入现有的项目使用范围设置；连接检查不改变项目权限。基本区域只保留连接名称、主机、用户名和认证方式；客户端、端口、跳板、转发及超时等放入相应高级分组。已经保存且未修改的连接可直接认证；表单有未保存修改时，先提示保存或恢复，不用旧配置冒充当前填写的配置。

选择私有交互认证后，在认证方式旁展示 WSL 原生 OpenSSH 要求和显式客户端选择；点击仅修改待保存表单。已有 Windows 客户端、密钥和路由不因切换认证方式而自动改写，WSL 密钥引用须由用户确认所属命名空间。需要自定义可执行文件时使用高级设置。

新认证模式及新增跳板设置需要具备相应能力的作业服务。连接到旧版或版本尚未核对的服务时，仍可查看记录和使用原有密钥连接；新增设置必须先由用户按原来源更新服务，不保存后让旧服务默默忽略。旧构建及其直接 MCP 接口不实现新增租约规则，不能宣称受到新策略保护；开发阶段不支持用旧服务或主动降级后的服务管理新增认证配置。既有连接、授权和运行记录不因此清空。

## 二步验证：专用终端与认证会话

首条受控实现路径使用具备实际能力的 WSL OpenSSH 与 Linux 标准库 PTY。Windows 原生客户端的交互和连接复用能力需单独验证，不能因为设置 `-tt` 就称为支持人工认证。

认证界面只向用户展示认证过程。输入仅传到所属 PTY，不写入 SQLite、运行快照、日志、遥测或 Agent 消息；认证输出使用有界临时缓冲，不进入通用 Agent 诊断。Agent 只获得脱敏状态和可打开的人工操作入口。

会话必须绑定集群记录版本、明确的路由和用户、所选客户端、作业服务及随机拥有者身份。控制目录位于 Linux 文件系统的应用私有目录，不在公共目录、项目输入或 DrvFS 中。取消和清理只作用于已核对身份的自有进程及套接字。

只有以下核验都通过，才能显示已认证可用于批处理：

1. 自有主进程仍存活，控制端点身份和配置范围一致。
2. 控制命令确认该 master 可用。
3. 通过同一连接成功执行有界、只读的随机标记核验。

普通 `ControlPath` 连接在 master 消失时可能尝试新连接，单独提前检查仍有竞态。受控批处理从属命令必须在缺失 master 时失败：使用固定失败代理阻断网络回退，不重新附加跳板或历史远端嵌套链。初始认证的 master 已拥有审阅过的路由。[OpenSSH 配置语义](https://man.openbsd.org/ssh_config#ControlMaster)、[控制命令](https://man.openbsd.org/ssh#O)

首次主机身份确认由用户在专用终端直接完成，并提示从集群管理员或可信渠道独立核对指纹；程序不自动输入确认，也不忽略已变更的主机身份。未完成认证时切换流程、来源或配置会作废该次尝试；已核验并保留的连接只属于原连接版本和作业服务，可继续监控原作业，不会替新流程建立使用权限。

新增受控人工认证模式只使用已审阅的显式主机、用户、端口、密钥引用和跳板，计划与 master 均隔离常规 SSH 配置文件。原因是 `Match exec` 在配置求值时可以执行本地命令，单独使用 `ssh -G` 或禁用 `LocalCommand` 不足以保证只读预检查；客户端默认字段应按实际语义核验，不因某版本省略 `RemoteCommand=none` 的输出而误判不兼容。[OpenSSH Match 配置说明](https://man.openbsd.org/ssh_config#Match)。既有密钥模式继续保留原连接语义；新增模式不会静默迁移别名或路由。

现有本地 OpenSSH 的缺失 master 负向测试已经验证固定失败代理不会连接监听端口；这只证明该负向点，不代表人工 MFA、有效 master 或集群策略已经验证。

会话过期或连接丢失后显示需要人工重连；保留原作业 ID 和最后观察时间，不重发提交。集群若禁止连接复用、转发或所需的批处理通道，说明管理员支持条件，不承诺自动托管，也不绕过二步验证。

### 从原任务恢复认证

dev.18 已实现原运行关联的认证入口与恢复流程，以下是实现契约；真实集群认证仍待单独验收。当前连接设置改为新版本后，原作业仍使用其不可变连接快照；不能让用户去第一条连接或当前新版本反复登录。任务/运行页的人工入口携带原运行身份，直接审阅该作业原本使用的集群、版本、用户和路由。作业服务从自己的运行记录解析来源，重新检查项目使用范围和身份；渲染进程不提供历史连接内容，也不重写当前配置或运行快照。

计划、开始认证、输入、随机标记核验、保留与后台监督须持续使用同一原运行来源。普通当前连接的待认证会话仍检查当前设置是否变更；原运行恢复不因无关的新配置而失效，但原运行、来源、拥有者或使用范围不再匹配时必须停止。独立运行详情可以恢复自己的连接，不要求切换到一条无关会话；从计算流程进入时则核对其任务、运行和计算来源的关联。

认证恢复不创建作业、不重提请求，也不把 unknown 改成尚未提交。监控保留原作业 ID、nonce、输入和最后状态，另给出脱敏的“需要人工认证”操作提示，即使尚未取得 Job ID 也不能丢失这个入口。原运行恢复界面不新增转发；需要新转发时明确在当前连接设置处理，不能悄悄采用新版本或外部入口。源码与软件检查通过不替代旧认证失效后的真实重连验收，也不把仍存活的旧连接当成该项证据。

## 本地隧道引导

先判断现有入口是否已经足够；能够直接使用已认证连接时，不强迫用户建立额外隧道。确实需要时展示：入口引用、转发用途、目标服务、回环监听和生命周期；真实值仅在本地配置界面可见。

隧道状态至少区分：未启动、等待人工认证、监听已建立、目标服务已核对、已失效、已关闭。监听成功不表示目标可达，转发 SSH 端口也不表示目标 SSH 已认证。`ExitOnForwardFailure` 不能替代目标检查。[OpenSSH 转发说明](https://man.openbsd.org/ssh_config#ExitOnForwardFailure)

新建隧道记录所属会话和进程；只关闭自己创建的转发。外部入口只做可达性与目标认证核对。关闭隧道或认证会话不取消调度器中的作业；监控无法继续时显示未知及最后观察，不显示虚构空闲或失败。

## 验收与未验证边界

- WSL：单/多/缺失发行版，已有服务复用，原来源恢复，明确启动，发现部分失败，关闭/切换/迟到结果，原项目和作业保留。
- 密钥：已有配置和 agent、明确用户名与非默认端口、客户端路径命名空间、主机身份失败、错误密钥与解锁提示。
- 人工认证：真实 PTY、有界输入输出、无秘密落盘/入模、成功及错误认证、取消/超时/重连、来源变化和会话失效。
- 连接复用：真实有效会话，以及 master 在检查后消失的失败边界；不能回退直连或复用另一来源。
- 隧道：仅回环监听、端口冲突、目标不可达、失效和自有清理；不接管外部隧道。
- Agent：仅可请求脱敏状态或提出草稿，不能输入验证码、改变认证配置或项目授权。

模拟和本地夹具只覆盖各自的软件范围。没有可用二步验证集群、主机指纹或凭据时，真实 MFA 与目标环境验收记为 blocked / not_run，不能以成功创建进程、监听端口或保存表单替代。
