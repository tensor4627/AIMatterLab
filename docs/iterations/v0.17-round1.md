问题：无项目的会话仍可生成流程页，但作者工具要求有效project ID；空项目列表和只读shell历史使模型退回把Python放在表单里。旧验收预先提供ID/完整graph，没有覆盖普通自然语言路径。

实际改动：桌面在推理前建立/修复仅供输入编写的会话草稿项目，持续绑定同一task/conversation；以当前真实项目、候选环境、已保存输入替换旧renderer上下文。draft的engines和clusters均为空，MCP不能创建项目或改变授权。结构文件仅按用户当轮显式路径复制，不授予父目录读取；部署时由桌面复制草稿输入至明确选择的计算项目，保留目标授权。

新增结构拓扑建议，在真实结构上推导peptide phi/psi候选、原子编号与ASE参考角；自动补dtype、输出格式、按步数/pace推导历史容量，保留用户温度和已有选择。公开 studio-workflow-authoring skill 将真实文件保存、技术事实归属、原地续填和人工执行门槛固定下来。

验证：Node148、worker125、界面47、TypeScript/Vite passed；22原子示例由实际坐标推导出phi=[4,6,8,14]、psi=[6,8,14,16]（零基），这是该结构的几何解释，不是任意同名分子的映射。A已完成本轮独立core22项和native2项，引擎基线与UI用户链分开记录。

A/C 首次实际验收为 rejected，保留全部失败：Agent 对图定义试错两次才保存；原 nested 输入无法回读更新，只好另存顶层文件；driver/config 缺少文本检查入口。PyDyn 已经通过人工按钮执行成功，但不能由此宣称输入审阅合格。其余四条 UI 尚未完成时被打回。

返修增加 read_project_input，读取既有授权范围内的 UTF-8 文本、SHA 与文件大小；二进制模型仅提供元数据，不反序列化。write_project_input 支持受限子目录、原子保存与基于读回 SHA 的并发覆盖检查；MCP 对已有不同内容必须提供匹配 SHA，人工编辑器仍保持显式保存边界。授权不扩展到外部目录。

第二次真实验收发现快速点击项目与会话时旧 resume 回包覆盖新选择，续填写进错误流程。返修为每个恢复阶段校验选择序号及服务商，恢复完成前阻止发送和 Enter；App 的 conversation.select 同样丢弃迟到响应，并处理跨服务商连接和初始化配置迟到。新增三项逆序回包回归。错误会话的 ready 草稿保留未提交，未自动重试。Python 子进程统一禁止生成源码字节码，已核对兄弟仓库与初始指纹一致。
