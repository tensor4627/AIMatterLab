# v0.18.5 · 草稿工作区与计算项目的部署衔接

日期：2026-10-27。修复 `studio:task.deployment.prepare` 报 `Engine is not authorized` 的当前根因：部署配置引用了 `authoring_only` 草稿项目，后者按设计没有计算引擎权限。v0.18.4 登记了已有算力，但没有补齐计算项目的创建与选择链路。

## 本代修改

- 部署项目列表只展示计算项目；旧流程引用草稿工作区时，就地说明原因，保留原会话、流程和输入。选择计算目标后，仅当存在唯一匹配的已有计算项目时提出该选择，不替换用户已明确选择的受限计算项目。
- 在部署页提供“创建计算项目”，按当前流程预填名称、已选环境或集群、GPU、时长和原输入目录。工具默认全部可用，细节仍放在折叠设置中。用户点击创建才保存新项目；不会升级旧草稿或扩大已有项目权限。创建过程中切换流程，迟到的返回不能绑定新页面。
- 项目缺少当前引擎、目标环境/集群、GPU 或时长范围时，准备和执行按钮提前阻断，并提供具体说明及现有项目设置入口。删除或未登记的计算目标同样先提示。
- 主进程从 worker 读取当前项目策略，在写入准备请求、复制输入或创建运行草稿之前检查。查询失败不放行；读取期间流程、部署或复核状态变化时拒绝旧请求。worker 仍保留最终权限、输入和执行检查；MCP 没有新的授权能力。
- 新计算项目沿用已有输入接管机制，按实际内容哈希复制至目标项目拥有的输入目录。作者工作区保持原身份；准备不等于执行，实际输入审阅及执行按钮继续独立。
- 中英文提示一并更新。没有数据迁移或破坏性兼容变更。

## 保留的失败与未运行项

最初 Node 检查因旧模拟 worker 不支持新增只读项目查询而失败，之后补齐夹具；一次测试导入别名修正后全量重跑通过。首个实际桌面夹具缺少 pyGAS 必需字段，被原有科学契约正确拒绝；补齐合成元数据后成功准备。后续观察器在异步准备完成前读取记录报错，失败与运行草稿保留，改为主机端有界读取后在新隔离根完整重跑通过。最终执行门检查还正确阻断了合成跨目标夹具未登记的集群，补齐该测试的明确登记和范围后通过；包核对器的 Windows ASAR 分隔符问题亦修正并重跑。这些失败记录均未作为通过证据或真实 bias 验证。

本轮不提交用户当前计算，不改原有项目策略、SSH 连接、凭据或科学引擎仓库。新模型推理、真实新 SSH 提交、全新机器安装、AOTI、PyDyn NEB 及尚未实现的 TorchNEP/主动学习/外部 DFT 适配为 `not_run`。本次功能不自动授权任意旧项目；已有明确限制仍需在项目设置中由用户调整。
