# v0.13.1 · 实际集群验收与预检修复

2026-10-18。第三轮后的真实短测修复版。v0.13.0 的包和标签保留；本版仍为开发版。发布后继续核对原排队作业，现已补齐两个引擎的实际计算与结果回收；包与既有标签不变。

## 本次改进

- 按所选引擎导入 SDK；同次、同解释器的真实 PyDyn 探测结果可复用，不接受参数或历史缓存充作验证。保存 artifact、manifest/hash、CUDA ABI 与有限差分门槛保持。
- 预检保留阶段日志、真实退出码、stderr首尾、阻塞栈、进程限制与原生模块来源。冷启动探测120秒有界；超时或崩溃继续失败。支持显式OpenBLAS/NumExpr线程设置，不把该设置冒充已证明的根因。
- Git仅作元数据，缺失/非checkout/超时分别记录blocked/not_run/unknown，commit/dirty不伪造；命令8秒有界，SDK实际来源另记SHA。缓存按引擎与完整环境区分。
- 原生ELF在目标环境先检查库/版本并记录二进制SHA；每次本地和远程validate均重新检查，provenance失败或旧缓存不能放行。普通ldd检查60秒有界，不声称懒加载符号、GPU或模型已通过。wrapper/static/无检查工具明确not_run。
- 默认回收原生PyDyn的CV、步号和hill日志，沿用路径隔离、传输/本机SHA与资产登记。公共迁移skill补充已有wheel、GPU原生扩展架构及登录节点/计算节点系统库差异；私有配置继续ignored。

## 发布后原作业完成核对

原兼容GPUMD作业最终离开活动列表；未据此直接判断失败，而是交叉核对LSF accounting的DONE、nonce匹配的exit0、原Run/调度身份与原输入快照。原桌面复核、上传、PEND及关窗恢复记录保留；后续0.13.1打包桌面恢复同会话/流程，完成计算产物回收与预览。没有换队、重复提交或安装引擎。

两条路线现均通过“本地Studio→已有环境探测→参数复核/输入审阅→SSH/LSF→真实GPU短算→关闭后恢复→哈希核对回收→结果预览”的工程验收。GPUMD的validation.json仍保留scientific_status=not_run：ABI/有限差分与短算成功不等于生产科学有效性；restart.xyz与PyDyn checkpoint回收也不等于已执行重启。DeepSeek真实推理/TPS、FES与生产收敛继续not_run。
