# v0.18.9 开发记录（未发布）

本轮按实际原生界面观察修复问题。完整控件验收、工作流使用次数统计、菜单层级调整和最终视觉审阅仍在进行；当前发布基线仍为 v0.18.8。已生成 `0.18.9-dev.4` 隔离内部测试包，并保留较早内部包及失败记录；不表示通过正式发布验收。

## 已确认的问题与修改范围

- 英文预览中的首页统计标签和说明绕过了翻译函数；账号入口、当前增强采样说明缺少精确词条。已修复这几个主要界面的漏译，保留科学软件名称、实际数值和未知状态。
- 原生界面中，同一会话的参数编辑与自然语言续填保留了流程身份；但重新加载渲染器会丢失未发送的消息。现已加入按服务商和会话保存、恢复输入草稿：只有发送获得确认且对应草稿未被继续编辑时才清空，旧请求不能覆盖新输入，恢复不触发自动发送。
- 新会话在本地登记完成前保留原草稿；会话恢复改名、删除及服务商来回切换按各自身份处理。存储写入失败不会阻断输入，迁移先保存目标，再清理源；删除时同时清理该草稿的迁移备份。
- 补充代码复核发现并修复了“切换会话并预填 CV 讨论内容”覆盖旧会话草稿的问题：预填在目标草稿选定后才应用，校验服务商和会话，旧请求不会在后续切换时再次覆盖文字。
- 修复渲染器刷新后丢失 WSL 连接显示：通过只读 `worker.status` 核对当前已绑定服务的健康与身份后恢复界面，保留未知状态；不重新启动、安装或连接服务，不关闭 Agent，不提交任务。接口沿用主进程发送方校验，只返回状态和观测时间，不返回凭据或连接地址。迟到响应不能覆盖新连接、设置或当前流程归属。
- 修复从计算会话切到普通已保存会话时隐藏对话区：无流程的会话明确显示聊天面板，返回原流程时保留原参数、独立草稿和已有布局。

本轮尚未批准基于按钮使用频率的菜单调整。SSH、凭据、既有引擎注册和真实作业保持原样；后续仅在隔离测试配置中新登记完整源码环境。

## dev.3：原生短例发现的环境门槛漏洞

dev.2 中通过真实界面准备并提交的独立 Ag32 十步 PyDyn MD 短例失败，日志为 `ModuleNotFoundError: No module named 'pydyn'`。所选解释器存在，但注册没有绑定源码；此前普通 MD 的校验只检查输入和可执行文件，没有把模块导入失败作为执行门槛。此失败记录保留。原生关闭并重启后，同一会话、流程、计算项目、失败运行及日志恢复；提交前 draft 重启仍待单独验证。

- 普通 PyDyn MD 每次验证重新探测当前注册环境，检查 torch、CuPy、ASE、PyDyn 导入和显式 PyDyn 源码位置；不再把旧探测缓存当作当前可执行依据。探测失败保持草稿并禁止入队，校验不执行用户的 `run.py`。
- 普通 MD 不要求 `pydyn.sampling` 可用；导入通过不代表模型兼容、GPU 实际计算或数值正确。采样与其他引擎保留各自的验证规则。
