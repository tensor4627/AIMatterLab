# AIMatterLab 代码架构

产品要求见[软件规范](software-specification.md)。当前实现和验证范围见 [AIMatterLab 0.1.0 发布说明](releases/aimatterlab-0.1.0.md)。

AIMatterLab 继承 GPU Sampling Studio 1.0.1 确立的前端、后端主进程、Python worker 和 Agent 分工，以及既有的数据兼容和版本化迁移约定。第三方工具通过开发者交付包接入，主进程登记版本并管理快照，worker 在用户选定的环境中执行已有适配支持的操作。架构沿革见[原软件重组记录](v1.0.md)。

## 源码入口

```text
frontend/
  app/                    React 入口、工作台装配和导航
  features/               会话、流程、工具、计算、工作区、运行和专业编辑界面
  api/                    renderer 的类型化 IPC/worker 客户端
  ui/                     通用组件、文本、主题和展示辅助
backend/
  main/
    tools/                工具包、Git 版本、流程定义和来源
    compute/              连接、配置、执行协调、终端和 worker 传输
    workspace/            桌面索引、草稿、资产、审阅及流程实例协调
  worker/
    studio_worker/
      tools/              引擎适配、测试判据和工具操作
      compute/            环境登记、运行与调度生命周期
      workspace/          输入快照、文件布局、产物与流程事实
      transport/          HTTP/MCP 的认证、路由和序列化
      infrastructure/     Store、文件、进程及独立资源清单
    tests/                worker 工程测试
agent/
  providers/              模型服务适配
  sessions/               会话、请求生命周期和后端事实到会话的组合
  context/                模型上下文装配
  skills/                 指导选择、受限读取和封存策略
  tools/                  对后端和共享终端的受限调用
  builtin-skills/         AIMatterLab 自带公共指导
contracts/                DTO、schema 与无特权的跨边界验证规则
desktop/                  main/preload 启动和桥接
  platform/               原生进程、凭据、对话框和系统适配
developer/                外部作者的独立接入 skill 与交付说明
installation/             安装与环境就绪检查
tests/                    frontend/backend/agent/contracts/integration 工程检查
```

旧 `src`、`shared` 和一次性内部转发入口已由实际消费者替换。Python 保留 `studio_worker` 包名及必要的旧模块/CLI 入口；它们转发同一实现和模块命名空间，避免破坏独立服务、既有进程协议及测试注入。

## 请求与状态归属

前端只拥有展示和未发送的编辑状态，通过 `frontend/api` 请求主进程。`desktop/main.mjs` 保留启动装配、可信 sender 校验与 IPC 注册；业务委托对应后端或 Agent 所有者。原生能力通过宿主适配器传入，后端不反向引用前端或 Agent 提示词。

桌面 Catalog 保存会话、任务草稿、版本引用和索引。worker Store 保存权威 Run、不可变输入、配置和流程事实；JSON 镜像可重建，不能代替 Store 判定作业状态。关闭桌面不会结束已提交任务；未知运行只观察和核对，不自动新建尝试。交互式 SSH/本地终端属于本次桌面生命周期，正常退出会有界关闭；保存的连接配置保留，下一次建立新终端。旧终端缓存仅作历史诊断，不用于恢复本次操作权限。

当前所选 SSH 服务的只读运行索引与会话／任务的执行来源分开。主进程只在健康及身份核对后公开稳定 `sourceId` 和本次 `connectionId`；前端在读取前后确认同一来源，并用选择修订隔离迟到结果。未绑定项目的聊天可以查看已授权服务的运行历史，不能因此恢复或替换任务来源、扩大执行权限。相同来源的旧索引保留时间与 warning，其他来源的记录明确标识。SSH 健康观察默认预算为 15 秒，本地为 3 秒；仅观察既有传输，不自动重连。

会话分组删除通过桌面的类型化 `conversation.deleteGroup` IPC 和原有请求来源校验进入 Catalog 事务：将会话移至未分组，再删除分组并记录删除身份。迟到的会话记忆请求不得恢复已删除分组；重复删除幂等。只改变分组元数据，不删除会话、流程、运行或计算权限，不改变当前会话身份与草稿。

首次连接与只读恢复共用 WSL stdio relay：每个请求先证明 Linux 已接受的连接属于同用户、同 root/port 的 worker，再在同一 socket 发送原权限令牌；桌面不向未经证明的 Windows localhost 监听者发送 worker 凭据。连接接受前核对 name/root/runtime/execution_policy；relay 失效清理桥接、来源与 Agent 租约，不停止 worker 或作业。

本地启动通过 Store 的 compare-and-set 在创建 supervisor 前保存唯一 `launch_claim`，未确认启动使用既有 `unknown` 状态。`compute/launch_protocol.py` 为 supervisor 提供排他认领、持久化身份/载荷校验及取消与子进程创建的 SQLite 排序门。恢复先核对既有启动证据，不重新派发；旧格式任务与回执保持兼容，数据库 schema 及公开状态枚举不变。

集群提交在归档后于共同 Store 锁内重新核对当前授权、输入和本地/集群并发数，持久保存 `unknown` 占位后才发送 SSH 请求。独立校验和草稿修订不能把已提交父任务改回可提交状态。本地启动最终认领时检查项目修订号，授权变更后留待重新校验。集群查询使用可选的观察标识拒绝旧回复和旧错误，终态与完成回执不因迟到查询或提交回复退化；旧记录按首次新查询获得标识，不扫描或迁移真实作业。

已保存的交互 SSH 资源使用独立的 OpenSSH master 持有本次认证。`desktop/platform/terminal-service/ssh-connection.mjs` 与本机标准库辅助程序严格证明原客户端进程与私有 socket，并在本地 `-O check` 前后重新核对身份；普通登录不依赖额外远端命令或精确 stdout。私有认证 PTY 仅向人工界面提供输入输出，不进入 MCP、SQLite 历史或模型。支持的 Linux/WSL OpenSSH 从同一 master 分别建立普通 shell 和私有服务通道；从属进程设置固定失败代理和批处理认证，master 缺失时失败，不回退为新 SSH 登录。服务的远端身份与健康单独核验。未证明具备复用能力的客户端或历史嵌套路由显示明确限制，由用户审阅配置，不自动改写既有连接。

基础连接、shell、服务通道、远端 worker 与作业各有生命周期。shell 可在服务期间继续交互，关闭 shell 不关闭服务；停止服务仅关闭私有通道及其本地代理，不停止 master、shell、远端 worker 或作业。明确结束整个连接撤销其临时通道和 Agent 租约。服务失败不等于独立 shell 失败；基础连接失联则各子通道分别失联。旧单 PTY 协议输入锁保持，仅供兼容诊断，不能用解除锁定伪装新架构。

认证区在同一终端视图接收人工密码、验证码和主机信任确认。human-only `completeLogin` 绑定原始登录请求，先观察本地 socket 就绪，再核对原本地连接证明并幂等建立普通 shell；页面往返恢复原请求，不另开认证。终端明确关闭后不自动重建。普通 SSH 登录另有明确入口，服务能力不被推定或隐式回退。

本地 Python 启动身份帧使用同一随机 nonce 的起止界定。ConPTY 视图缩放可能在帧内加入物理换行，解析器只在完整有界帧到齐后解码，仍执行规范 base64、PID／启动时间／boot 以及后续实际 SSH 进程和 socket 核验；不以扩大错误容忍代替身份证明。

Windows 可执行运行缓存存于独立的用户本地执行缓存，配置与凭据仍在原目录。准备阶段核验源、复制目标与已缓存可执行副本的实际完整性级别；内容摘要相同不能证明 Windows 执行权限相同。Low 副本被拒绝，未知执行能力单独报告，不更改原目录 ACL、不提权或绕过核验。

资源引用的 schema 2 保存 profile/version/connectionId，不把可独立开关的 shell ID 放入连接授权身份。旧 schema 1 记录保留；用户明确选择已核验新连接时，保存版本化迁移历史，不从旧终端缓存提升认证或租约。连接配置的不可变版本快照保存实际曾存储的内容；既有记录只回填当前真实版本，不虚构缺失历史。新登录核对最新版本，已有已认证连接继续绑定原快照。环境配方单独更新时，以 broker 的确切连接修订锁和回执完成同步；保存配方不等同活跃连接已采用新版本，未知提交不重发。

`backend/main/compute/ssh-connection-service.mjs` 按连接保存服务实例、登记及未知尝试，选中的连接只挂接一个本地科学 MCP 代理；切换资源保留后台连接与服务。Terminal MCP 与服务代理按工具检查分别核验 shell 输入权、服务调用权和当前 provider/thread/task/project/environment/inputRoot；收回或切换上下文永久作废旧租约和迟到回复。文件访问明确按现有项目范围核验；认证、服务登记、项目授权和科学执行批准互不替代。

`agent/sessions/terminal-handoff.mjs` 与 `service-handoff.mjs` 分别协调 shell 输入权和服务调用权：没有真实 thread 时调用既有会话入口创建空会话，不发送模型消息。主进程校验 provider、连接与能力实例、终端 epoch 或服务尝试、资源及会话修订；前端采用返回的真实会话并保留未发送草稿。终端节点及 PTY 在面板切换时保留。宽屏首页与普通会话不再强制隐藏内容栏。

明确更新已连接服务时，主进程核对 `expectedAttemptId` 并从 broker 的真实服务记录取得原 shell 的内部凭据，关闭旧服务传输后在同一 shell 更新。该凭据不由 renderer 选择，不转移操作权，不回退到新 SSH 通道；未知回执保持在原尝试。仅仍然有效的确切原授权可迁移到新服务尝试，人工接管及编写上下文授权撤销不能被迟到完成回调恢复。组合交接在主进程保留原终端与授权来源，服务更新后收回原终端仍撤销对应组合权限，独立重新授予的服务权限不被误撤销。服务登记只在完整配置和服务身份一致时保留曾测量的完整缓存指纹。短暂协议占用只影响当前可输入性，不改变真实操作方。

终端服务同时按字节和输出块数分页。主进程验证旧终端服务返回的完整响应，再向 renderer 和 Agent 交付最多 512 个原块及最后一块的序号。前端另行保存读取诊断，以连接、shell 和操作权版本匹配恢复回执。读取与写入各自报告错误。

服务已确认断开时，显式维护更新继续走既有服务通道入口，核对原认证 master 后选择当前随软件交付的 worker。该分支不继承 Agent 使用权；活跃、连接中、停止中或未知服务不能以省略预期尝试身份绕过原更新事务。

DSH 在公开事件与历史读取时，将显示条目标识按会话、轮次、条目类型和原始标识组合；原生 SDK 调用／回复及审批标识独立保留。历史归一化作用于读取副本，避免重用的轮内计数覆盖旧消息，不重写既有历史文件或重放模型请求。

DSH 发布资源使用 `studio-sdk-v2` 依赖投影：保留官方 CLI／profile-boot、插件实现、包声明及许可证原字节，仅对精确审计版本的 CLI 与 SDK app 两个 bundle carrier 选择 Studio 正向 profile 所用依赖；其它实现包继续验证完整必需依赖、peer、目标平台 optional 与文件哈希。未启用的独立 Web、Office、语音及实验 profile 不属于 Studio 的模型服务入口。manifest 记录投影身份，变更投影会重新 staging，升级 carrier 版本须重新审计；开发审计仍可显式请求完整闭包。真实 SDK 启动、MCP 权限、恢复和取消按原链路执行。

科学指导统一走 `ScientificSkills`／`ScientificSkillRouter` 与渐进读取策略。旧的、应用已无消费者的 pyGAS eager-attachment 实现已移除；当前服务仍保留明确 provider 同意、读取上限、链接拒绝、撤销再验证和已归档资源禁读。桌面 Catalog 在每个数据库实例复用固定 SQL 语句，绑定参数与事务／损坏记录保全语义保持一致。随包 worker 指纹在首次需要真实服务版本比较时求值并固定，不在未连接桌面首屏扫描源树。

Agent 从后端取得结构化事实，再生成模型上下文。MCP 和模型回复不能修改授权，也不能将计划、安装说明或推断变成真实运行结果。执行依据已有项目授权、准确的输入快照和实际运行条件；AI/人工复核记录是独立证据，用户明确要求审阅后执行时仍按该委托边界处理。

外部 Agent CLI 的版本探测、能力检查、隔离初始化、正式启动及登录使用统一环境白名单，保留系统、用户目录、语言、代理及证书配置；服务商配置和当前 MCP token 只通过该服务商的显式字段传入。Codex 保留已有登录目录。任意宿主环境变量、其他服务商密钥和代码加载开关不再隐式继承；此行为不改写已保存凭据或登录文件。

## 工具、配置与流程

工具包保留作者 Git 仓库布局，交付说明和重定向位于外层 `工具名-package`。包登记、安装验证和实际执行分别记录；新版本采用独立快照，旧任务保留原版本。开发者入口见 [developer](../developer/README.md)。

用户配置依据已登记环境及工具声明执行安装、探测和测试，分别记录实际结果，并绑定具体版本与环境的执行 skill。未验证的候选可在授权内尝试，不通过虚构检查回执获得资格。日常选择、手动读取、MCP 和引用展开共用封存规则；精确故障修复或重新安装读取所需前置材料。

工具组定义包含端口、依赖、参数默认值和最终产物，并保存精确不可变版本。工作空间选定组与配置后，worker 建立流程/执行/步骤/Run 目录。准备产生真实草稿与输入回执，在已有授权内提交同一个 Run；状态查询和作业返回导航不会推进步骤。检查发现与运行终态分别保留。

新的完整配置与逐步执行参考路线目前限定固定串行 CPU `installation.check` 工程示例。通用资源边执行、其他第三方工具安装及现场科学适配需要各自实现和验证；既有引擎路线继续保留其真实支持范围。

科学联用配置的责任位于 AIMatterLab：从开发者交付的 `aimlab-tools` 接口声明和使用指导解析所选组，区分产物阶段与同进程运行组件，为每个必须共同运行的完整依赖闭包配置兼容的版本化环境，并验证实际产物及完整组合。预置接口类型覆盖已声明支持的力场—MD 和增强采样—MD 联用；三者组合须有对应的完整组证据。这是待实现的通用配置能力，不改变上述固定 CPU reference 的当前边界；开发者声明、skill 文本和单工具测试都不能直接激活科学组。详细要求见[依赖组审查](development/tool-dependency-groups.md)。

## 分发与证据

源码 worker 位于 `backend/worker`，目录包继续映射到 `worker` 并解包，以保持已部署启动协议。宿主向源证据读取器传入实际 worker 资源根；固定清单之外、缺失或错误来源均拒绝。公共指导从 `agent/builtin-skills` 单独映射到 `studio-skills`；私有工具包、配置、凭据和运行证据不进入发布源。

引擎和工具 JSON 契约由 `contracts` 维护，构建同步到独立 worker；安装器、运行时标识、独立 wheel 和桌面包核对相同资源。源码迁移不搬用户数据库、连接、环境、授权或真实作业，也不改兄弟引擎仓库。

工程测试按实际变更层选择。`pnpm test` 递归发现 Node 工程测试，`node scripts/test-node.mjs --list` 只列清单；worker 测试从 `scripts/test-worker.mjs` 进入。原生验收与科学检查使用独立显式入口，保留 `passed / failed / blocked / not_run` 及原始证据，不将组件夹具或工程 CPU 进程当作科学验证。

交互式登录的正常使用从 dev.18 起收敛为“登录 → 交给 Agent”。`agent/sessions/ssh-terminal-handoff.mjs` 组合既有真实终端交接和主进程服务控制：先交接原 shell／建立真实空对话，再按保存登记首次部署或复用独立服务，验证后赋予同一上下文的服务使用权并重新绑定工具。收回操作会撤销本次组合授权；迟到准备不可越过操作权、资源或对话变更。Python 或服务准备失败不撤销已交接 shell，未知请求不重放。人工交接可在连接明确拒绝且缓存全文与身份校验通过时启动同一 worker 一次；普通服务检查仍只读，既有作业不重提。

dev.19 把作业服务准备前移到交互登录完成后的原连接激活：主进程自动核验缓存、首次部署并登记或后续复用，不等待 Agent 交接。交接先等待同一连接已有准备请求结束，再建立真实对话并授予使用权，防止对话建立打断准备或重复启动。人类界面的尺寸调整是视图操作，不要求人工持有 shell 输入权；仍核对原 epoch，Agent 调用仍须匹配其 scope，协议占用锁保留。迟到的读／尺寸错误不覆盖新的交接状态。

dev.21 按当前交互要求移除 dev.19 的登录激活自动准备钩子：登录只建立普通终端，远端服务探查／部署／复用仅在原终端交给 Agent 且真实对话确定后启动。准备期间复用交接保护，消息在修改对话上下文前被拒绝，避免同一对话的新消息让接入因 serial 变化中断；授权后将临时路由切换到服务通道，工具绑定完成后释放保护。进度区覆盖 connecting、unknown 与 connected 但工具未就绪；缺少服务使用权不能显示 Agent 已就绪，失败原因不因其他通知而隐藏。
