# 集群交接、工具配置与计算流程开发计划

本文记录本次开发的设计和验收条件。实现以现有多资源 SSH 托管、工具配置、会话流程图和四步新手引导为起点。桌面维护资源与会话索引，远端作业服务（worker）维护运行、调度与产物回执。[产品规范](../software-specification.md) · [开发版验收记录](../releases/aimatterlab-cluster-workflows-unreleased.md)

## 首次交接时选定总工作区

1. 用户在原终端完成登录。首次点击「交由 AIMatterLab 管理」时，在同一次交接中显示资源名称、远端账号、可编辑的目录和「确认并交接」。首次使用建议该账号主目录下的 `AIMatterLab`；用户可以选择站点的项目盘或其他可写位置。远端解析实际绝对路径，在写入前展示目录树预览。允许使用已有目录，只创建需要的子目录，保留已有内容；同名目录项确有冲突时指出具体位置。用户可稍后交接，回到原登录终端。
2. 路径选择通过已认证 SSH 完成，不依赖 worker、Git、队列或科学工具。桌面将用户确认的路径、实际主机和账号绑定到稳定的资源登记。普通重连沿用原选择；资源指向另一主机或账号时重新确认。旧版基础工作区可作为候选，先展示原路径。后来更换总工作区只影响尚未绑定的会话，已有流程继续沿用原记录。
3. 交接成功后自动走同一连接的作业服务传输、解释器与 SQLite 探测、启动和健康核验。UI 分开显示 SSH、终端、作业服务状态。若 Python 不够，点「让 Agent 配置」打开原资源会话，复用或配置解释器，再从失败步骤重试。升级后的首次复用比较随包与远端清单，差异可查看，用户点击后更新；原运行仍可查回。服务代码、内部状态和凭据的存储与用户选择的工作目录分别管理。

### 会话和软件的实际目录

```text
<用户确认的远端总工作区>/
├── workfile/
│   ├── 2026-11-20/
│   │   ├── task-1/        会话甲在该资源的工作目录
│   │   └── task-2/        会话乙在该资源的工作目录
│   └── 2026-11-21/
│       └── task-1/        新一天首次执行流程的另一会话
└── software/
    ├── git/               需要时安装的用户级 Git
    ├── gpumd/             由 AIMatterLab 从零配置的工具
    └── <其他工具名>/
```

- **分配时机。** 同一会话在该资源首次确认执行计算流程时，按用户当时的本地日期创建 `workfile/YYYY-MM-DD/task-N`。同一远端总工作区每天从 1 开始编号。聊天、阅读教程、浏览队列和编辑草稿均可先进行；草稿输入在执行准备时按冻结版本落入实际工作目录。
- **并发与找回。** 远端以稳定会话和资源标识幂等认领目录，原子分配当日编号，跳过已占用的目录；重试先按原请求找回，跨午夜沿用首次认领日期。桌面保存会话、资源身份、工作区登记及远端返回的绝对路径，worker 将流程、运行和该工作目录关联。新流程及重跑在同一会话目录内使用独立运行子目录。提交脚本的工作目录、输入、输出与日志都落实在这里。重启、重连、改显示名后可用「本次计算文件在哪？」查询；离线可显示上次确认的路径及时间，在线再核对。一个会话使用多个资源时分别记录，已有任务按原绑定恢复。
- **软件与 Git。** 从零配置的工具装入 `software/<工具名>/`，可并存不同版本。资源使用一个本地 Git 管理仓统一记录工具来源、版本锁定、提交模板和最小测试；各工具的上游源码保留独立历史，闭源程序记录获取方式、版本及文件摘要。大模型文件、可执行环境、许可证、私有凭据和任务输出不纳入管理仓。优先使用资源上可用的 Git（含站点 module）；缺失时为用户在 `software/git/` 配置适配目标平台的轻量 Git，并让后续实际拉取、登记和更新都使用该入口。已有工具可以就地登记。若需推到外部 Git 托管，另按用户指定的远端与授权执行。

## 三种工具接入与运行时指导

| 用户的起点 | Agent 行为与成功回执 |
| --- | --- |
| 从零安装 | 读工具交付指导，在目标集群先尝试拉取指定版本；网络不佳则在桌面下载适配集群的同一版本，再通过原连接分块续传；两条自动路径均失败才请用户选本地文件或给出远端位置。核对摘要，查找依赖，配置环境，生成提交模板，在目标队列跑最小测试并检查输出。 |
| 已有脚本 | 只读扫描用户指定的目录，按工具、环境和调用方式归类，逐类展示代表脚本和依据，让用户确认、改选或跳过。可核对同一资源、模板版本、环境和预期产物的历史回执时复用，缺证据才提交短例。 |
| 自定义软件 | 从用户提供的本机或集群脚本、手册及公开资料整理清单，落实五项工具定义：输入输出、环境、最小测试、操作接口、程序来源。支持合法取得的二进制。通用执行器完成实际测试后可作为流程节点，记录为本地私有配置。 |

扩展现有只支持固定 CPU 参考用例的配置器、执行适配与调度路径。配置成功按确切资源、功能、版本、环境和模板激活；联用模式核对实际组合。worker 持有实测回执；保存用户 skill 失败时可由已有回执补写。旧配置保留原证据。采用原生联网能力的服务商可直接搜索或读取公开网页，AIMatterLab 也提供各服务商共用的公开资料检索。来源与适用版本随配置草稿记录。

在 `agent/builtin-skills/` 随包提供连接与服务修复、工具配置及自定义接入指导，更新科学技能索引、引用和逐轮提示。给用户技能接口添加 `scope=resource`，按稳定资源与远端账号隔离。成功后写入并读回执行 skill，包括环境、入口、模板、输入输出、工作目录查询和故障处理。运行时 [AGENTS.md](../../agent/context/AGENTS.md) 按场景给出索引：首次配置读对应指南；日常执行读当前资源的用户 skill；找文件查会话工作目录；修复或升级时再读相关前置指导。安装修改与包内实际读取回执同步验收。

## 普通终端和整图执行

- 普通会话可直接完成被委托的只读查询、向工作区内复制、区内编写运行脚本及独立作业提交。应用按操作的实际影响判断权限，预装程序的位置本身不会触发区外写入确认。区外写入或在外部目录执行，需用户明确要求并在输入区确认列出的资源、路径及整组步骤。托管和手工交接给 Agent 的终端均执行此规则，远端子进程及计算节点侧分别约束；破坏性操作展示具体影响。用户切换目标、拒绝或撤权时不派发旧请求。
- 一张流程图绑定一个资源，可跨该资源的环境和队列。按目标倒推输入和参数，缺工具时在原对话提示「让 Agent 配置」或「稍后」。配置完成后回到同一草稿，保留手工参数。确认整图后冻结输入与配置，worker 调用实际 Slurm 或 LSF 适配，按节点交接产物并持续监控。断线按原身份恢复，提交结果未知先查原作业。终态或出错时在原会话提醒一次，列出产物、日志、失败节点和验收入口。[现有流程契约](workflow-io-roadmap.md)

## 在原对话继续规划

1. 用户先在项目对话中讨论目标、检查材料或查看集群，然后开启「任务规划模式」，请 Agent 按已讨论的条件制定计算流程，并在当前委托允许时安排执行。当前聊天的提供商、会话和项目继续作为授权依据。首次发出规划消息创建这个会话的流程草稿，之后更新同一份草稿。开关本身只改变后续消息的工作方式。
2. 当前会话、项目及资源身份一致时，继续使用原先已取得且仍有效的终端或服务检查通道。会话记录已确认的目标和实际核对过的通道用途。从断线或程序重启恢复后，以原记录定位目标，重新确认资源身份、当前权限及新通道的真实回执。仅浏览列表只提供候选信息。尚待用户回答的资源选择、输入区批准和在途操作保留各自的原轮次。新目标、新项目、撤回授权和明确排除的资源按当前指示重新核对。
3. 托管资源的 Agent 使用 `read_session_workspace` 获取同一会话在原资源上已确认的 `<总工作区>/workfile/YYYY-MM-DD/task-N`。已有目录继续用于新流程；执行核对可直接引用该目录，并在发出整图前再次核对原路径。未分配时由首次确认执行分配；预览、编辑草稿、切换模式和加载历史都无需分配。工作区归属沿用提供商、会话和稳定资源标识，远端按首次认领日期返回实际路径。
4. Agent 把已知内容、实际输入引用、缺项与产物依赖保存到该会话的流程图。有本轮执行委托时，在原授权项目和目标内准备并进入相应的核对与派发。整图仍由用户确认冻结快照后执行。仅规划、先不执行及拒绝的要求在相应步骤停止。若原会话仅持有终端或服务检查权，申请提交正式作业时仍需独立核实现有 worker 项目和队列权限。

回归用例从普通对话的同一资源通道进入任务规划，核对草稿、原路径和原终端，另覆盖服务检查、跨日查回、切换项目或会话、明确拒绝、撤权后的晚到回执及未经批准的派发。

## 新手引导中的集群实操

沿用「欢迎 → 助手 → 算力 → 开始」四个入口。在「算力 → 远程 SSH」串起首次交接；在「开始 → 配置我的第一个科学工具」和现有流程示例接续后两课。每一步说明要做什么、点哪个真实控件、成功后会看到什么，遇到缺项时就地给出恢复动作。教程可跳过、随时重开；交接与执行所需的确认留在实际操作中。新增资源时也可从该资源卡重开相应课节。

| 课节 | 用户在真实界面完成的操作 | 可见结果与分支 |
| --- | --- | --- |
| 登录并交接 | 选择已有 SSH 或添加连接，在终端完成登录，点击交接；查看资源、账号、绝对路径和两类子目录用途，更改或采用建议位置后确认。 | 在资源卡看见已确认的总工作区。取消留在原终端；重连显示原登记，切换资源打开该资源自己的进度。 |
| 检查作业服务 | 看传输、Python 探测及服务状态。缺环境时点击「让 Agent 配置」，在可编辑草稿里看清目标资源；配置后点击重检。 | 以健康回执显示就绪。重用连接时演示如何看版本差异及主动更新；等待或失败时展示当前步骤与可恢复入口。 |
| 配置第一个工具 | 提供「安装新工具」「我已有提交脚本」「接入其他软件」三个生活化入口。按选择分别引到工具来源与安装位置、脚本分类确认、或私有工具清单。 | 从零路线显示 Git、下载回退、模板及测试进度；用户只需学习自己选中的路线。通过后在该资源查看已激活功能与执行 skill，失败可回到原测试。 |
| 第一次用终端或提交流程 | 用可编辑草稿练习读文件和写工作区，区外操作展示确认内容。用示例展示补齐输入、缺工具时续接配置、审阅整图、确认、看进度和结果。 | 分配后显示真实会话绝对路径，支持复制。引导用户在对话里问「这次任务的文件在哪？」并对照返回路径。尚无作业时显示相应空状态。 |

扩展现有 SetupAssistant、工作页聚焦和「返回引导」机制，补资源身份、课节和所选工具路线的恢复状态。覆盖点击、键盘、Esc、返回、重开及桌面重启。阅读教程或点「下一步」本身不会发送消息、安装或提交。实现中同步修正旧引导里与首次自动准备服务或新目录契约不一致的文字。

## 对话选择框以 Codex 桌面实现为模板

已对照本机 Codex Desktop `26.1111.9664.0` 中实际处理 `requestUserInput` 的组件及调用入口，并回看 AIMatterLab 0.1.24 的原生集群选择截图。Codex 的随包参考位于 `app.asar` 下的 `webview/assets/async/512950.f240411157.js` 与 `722374.78bd218290.js`。改动前的 AIMatterLab 使用带边框的单选框、常驻「其他回答」和「提交回答」，多道题一起展开。下面的要求针对普通选择；总工作区交接、区外操作授权与提交整图仍需用户明确点击写有动作的确认控件。

| 核对项 | 实现与验收 |
| --- | --- |
| 位置和层次 | 在输入区内显示一张紧凑问题卡，一次只显示一道题。问题标题、编号选项、推荐标记和次要说明依次可辨。多题显示「当前题 / 总题数」及前后切换；宽时并排显示简短说明，窄时自然换行。采用 AIMatterLab 的主题色和字号设置。 |
| 点选和自填 | 首项获得导航高亮；点击普通选项或用数字键选择即进入下一题，末题提交一次。允许自由回答时显示输入入口，有内容时显示「下一步」或「提交」。可跳过的题允许跳过；缺少目标的流程回到等待选择。受保护的确认即使首项已高亮，也只有明确确认才能派发。 |
| 键盘和恢复 | 上下移动高亮，左右切题，Enter 确认；在文本框编辑时保留光标操作，中文输入法选词时的 Enter 不提交。保持自由回答、保密字段和原聊天草稿隔离。切换会话再返回可恢复题目与答案，重复点选、过期问题或迟到回执均不得影响其他请求。 |
| 谁来验收 | **主 Agent 亲自做原生窗口并排对照。** 用同一组普通问题比较 Codex 与 AIMatterLab 的默认、选中、推荐、自填、多题、窄窗及键盘操作，核对布局、间距、换行和完成一题的操作次数。再单独用总工作区、同名集群和区外操作场景验证目标与授权。保留可复现的隔离截图和操作记录，差异修正后复查。 |

## 实施与验收

执行阶段分派三个 GPT‑6.2 Sol max 子 Agent，主 Agent 先统一接口并做集成与最终验收。第一组负责资源交接、总工作区、会话目录分配和终端边界；第二组负责工具获取、Git、配置、激活和用户 skill；第三组负责真实前端页面、会话选择框和新手实操引导。接口稳定后并行接通远端整图、服务商联网和端到端联调。

- **运行与恢复。** 用隔离资源覆盖首次交接取消及重进、并发会话同日领取不同编号、请求重试及跨午夜找回、跨资源同名工具、更改总工作区后访问旧流程。检查计算进程的实际工作目录及输出位置。演练缺 Git 的轻量安装、三种下载结果、三种工具接入、区外写入批准及拒绝，并用两节点自定义工具流程核对产物交接和断线恢复。
- **前端。** 主 Agent 在实际 Electron 窗口从新配置走通交接和首个流程，另走已有脚本、自定义工具、服务修复、跨对话恢复。检查中英文、深浅主题、1366 × 768 常用窗口、1024 × 768 放大字号、630 × 720 窄窗。沿用原生新手引导已有的聚焦、键盘和草稿验收。[既有引导验收范围](../releases/aimatterlab-setup-guide-unreleased.md)
- **证据。** 做相关 Node、Python、原生交互以及开发所需的有界调度短例，分别记录夹具、目标集群及真实软件实测范围。发布时按现有规范核对指导源文件、打包结果及真实读取回执，维护变更日志与版本文档。
