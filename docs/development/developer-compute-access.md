# Agent 操作审批与集群工具测试

在「设置 → Agent → 操作审批」中选择模式，点击「保存设置」。选择保存在当前桌面工作区。普通聊天和任务规划使用同一组权限规则。

| 模式 | 使用范围 |
| --- | --- |
| 手动审批 | 默认设置。需要额外确认的操作由用户决定，已获准的读取和常规操作可继续。 |
| 自动审批 | 在现有的资源和项目授权内，自动批准可核实的操作。SSH 上可以原子替换已验证工作区中的指定文件，前提是目标支持 Linux 文件系统隔离。 |
| 完全权限 | 选择一个已托管并核对账号、主机和路径的 SSH 工作区。该工作区允许受限的读写、执行、明确的工作区内删除，以及已有的冻结脚本测试通道。旧版已选定的开发工作区沿用此模式。 |

完全权限绑定登记的资源、远端身份和工作区。原资源重新登录并重新核对后沿用同一选择。Agent 从计算资源清单的 `developerWorkspace` 字段识别当前工作区，按资源 ID 申请通道，并读取已激活工具。结构化提交和取消沿用本轮委托、作业服务的实际项目、队列、配额和原作业身份。

两种自动模式可跳过原生 Codex 对已列明的 AIMatterLab 托管工具的重复询问，配置在连接更新时生效。工具调用仍经桌面核对，工作区外写入、影响无法约束的命令、首次 SSH 主机信任和交互认证仍需用户处理。真实提交结果未知时沿原请求核对。降级或切换工作区时，桌面作废由旧设置产生的授权和待确认操作。
