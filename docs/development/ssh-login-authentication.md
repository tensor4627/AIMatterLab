# Ordinary SSH login authentication

On Windows native OpenSSH, the original login stays in a private terminal while the user completes host-key verification, passwords, additional factors and any gateway menu that opens before the selected login shell. AIMatterLab waits for the user's handoff before sending a shell nonce. It checks the standalone reply on the same SSH stream. The application launches its channel relay only when an operation needs it, using the selected shell. The relay runs short commands over pipes and opens a PTY for an explicit terminal or service. A relay launch failure leaves the verified parent connection available for review and a retry.

WSL and Linux OpenSSH verify the original master locally. Prompts in the SSH authentication exchange stay in the private terminal. This transport opens separate SSH channels through the master and does not run a post-authentication gateway shell menu. For a site that requires menu selection in that shell, the Windows native private login supports keeping the same stream. The local proof requires the original PID, process start time and boot identity, exact executable and argv, saved destination digest, a private control directory and the same owned socket inode. A local `-O check` must return the original master PID. Process, executable, argv and socket ownership are checked again after that response. Slave channels use a fixed false proxy and noninteractive settings to prevent replacement login.

The local startup wrapper encloses its process identity in matching random-nonce delimiters. Windows ConPTY may insert physical line breaks when the authentication viewport is resized before startup completes. Decode only the complete bounded envelope after removing terminal framing; require canonical base64 and a valid PID, start time and boot identity. A partial envelope stays pending, and foreign, duplicated, malformed or oversized frames cannot authenticate a connection. This framing repair does not replace any of the subsequent process, executable, target or socket checks.

The startup envelope can share a ConPTY read with a large gateway menu, terminal controls and authentication prompts. Apply the 4 KiB limit through the end of the envelope. Preserve the subsequent terminal stream in the human-only replay buffer and split it at UTF-8 character boundaries so even a small page can advance. Authentication input stays on the original connection.

In interactive mode, both OpenSSH clients prefer keyboard-interactive and password among the methods the server offers. The configured identity, remaining authentication methods, host-key policy and jump arguments still apply. On a proved pre-authentication exit the original login panel can read its bounded, private output with input disabled. Successful authentication and explicit close discard it.

This boundary follows the OpenSSH 8.9 implementation. In [`ssh.c`](https://github.com/openssh/openssh-portable/blob/V_8_9_P1/ssh.c#L1575), `ssh_login` completes before `ssh_session2` starts the multiplex listener at [`muxserver_listen`](https://github.com/openssh/openssh-portable/blob/V_8_9_P1/ssh.c#L2012). [`ssh_login`](https://github.com/openssh/openssh-portable/blob/V_8_9_P1/sshconnect.c#L1478) performs `ssh_userauth2`; failure does not return to start that listener. The [`alive control handler`](https://github.com/openssh/openssh-portable/blob/V_8_9_P1/mux.c#L458) answers over the local socket with the master PID and does not open a remote session. A terminal prompt or a live authentication PTY is insufficient evidence.

Login completion has a 60-second main-process transport budget for the bounded proof and confirmation. `terminal_login_unknown` retains the broker and the original login. The human-only status GET observes the same request. It does not check the host, open a channel or replay input. Native mode submits the first shell proof only on an explicit handoff. Subsequent terminal, workspace and service operations have independent results.

On returning to the panel, read the original connection and request ID. A read-only status observation can recover a completed handoff while an earlier response is outstanding. A failed status read is retried as an observation. Once an issued completion has an unknown result, keep observing its outcome until it resolves or the user explicitly continues. An explicit shell request can be retried once a slot is available.

A bounded proof timeout leaves the original login and any established shell intact. In-flight checks can be shared by callers on the same connection generation. A changed master identity or control socket invalidates that connection and its channels. On either transport, workspace confirmation needs its own receipt. A workspace error opens directory review on the authenticated connection.

Regression evidence is kept in ignored runtime directories. The changed-layer tests cover exact ownership rejection, socket replacement, pending and late outcomes, original request identity, no remote exec prerequisite and transport refusal handling. Isolated password/MFA protocol fixtures establish the application transport behavior; they do not establish compatibility with a particular site's MFA policy or scientific execution.
