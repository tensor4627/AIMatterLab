# Ordinary SSH login authentication

Ordinary terminal login proves the original human-authenticated OpenSSH master locally. It does not require a remote exec channel, a fixed remote login-name response, or a particular shell banner. Job-service host, Python runtime and health checks remain separate service requirements.

The local proof requires the original PID, process start time and boot identity; exact client executable and argv; saved destination digest; a private owner-only control directory; and the same owned Unix socket inode. A local `-O check` must return the original master PID. Process, executable, argv and socket ownership are checked again after that response. Slave channels retain their fixed false proxy and noninteractive settings, so an absent master cannot fall back to a new login.

The local startup wrapper encloses its process identity in matching random-nonce delimiters. Windows ConPTY may insert physical line breaks when the authentication viewport is resized before startup completes. Decode only the complete bounded envelope after removing terminal framing; require canonical base64 and a valid PID, start time and boot identity. A partial envelope stays pending, and foreign, duplicated, malformed or oversized frames cannot authenticate a connection. This framing repair does not replace any of the subsequent process, executable, target or socket checks.

The startup envelope can share a ConPTY read with a large gateway menu, terminal controls and authentication prompts. Apply the 4 KiB limit through the end of the envelope. Preserve the subsequent terminal stream in the human-only replay buffer and split it at UTF-8 character boundaries so even a small page can advance. Authentication input stays on the original connection.

This boundary follows the OpenSSH 8.9 implementation. In [`ssh.c`](https://github.com/openssh/openssh-portable/blob/V_8_9_P1/ssh.c#L1575), `ssh_login` completes before `ssh_session2` starts the multiplex listener at [`muxserver_listen`](https://github.com/openssh/openssh-portable/blob/V_8_9_P1/ssh.c#L2012). [`ssh_login`](https://github.com/openssh/openssh-portable/blob/V_8_9_P1/sshconnect.c#L1478) performs `ssh_userauth2`; failure does not return to start that listener. The [`alive control handler`](https://github.com/openssh/openssh-portable/blob/V_8_9_P1/mux.c#L458) answers over the local socket with the master PID and does not open a remote session. A terminal prompt or a live authentication PTY is insufficient evidence.

Login completion has a 60-second main-process transport budget covering its bounded local readiness, confirmation and shell-opening checks. An unknown response is reported as `terminal_login_unknown`; it does not discard the broker or start another login. The human-only status GET reads the original request outcome without checking the host, opening a channel or replaying input. A positive pending response may continue the same completion transaction; an unknown or failed response requires read-only observation or an explicit human retry.

On returning to the panel, read the original connection and request ID. A read-only status observation can recover the completed shell even while an earlier completion response or job-service status call is outstanding. A failed status read is retried as an observation. Once an issued completion has an unknown result, keep observing its outcome until it resolves or the user explicitly continues. If capacity rejected a shell before dispatch, an explicit continuation after a slot is freed can open that shell under the original request ID.

Regression evidence is kept in ignored runtime directories. The changed-layer tests cover exact ownership rejection, socket replacement, pending and late outcomes, original request identity, no remote exec prerequisite and transport refusal handling. Isolated password/MFA protocol fixtures establish the application transport behavior; they do not establish compatibility with a particular site's MFA policy or scientific execution.
