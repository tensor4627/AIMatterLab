# 从用户要取得的产物规划计算流程

以“得到 300 K、10 ps 的 MD 轨迹和热力学序列”为例，完成条件有两个。轨迹要覆盖所需时段和结构信息，热力学序列要包含用户关心的量。一次 MD 调用可以产生两者。若用户只说“跑 MD”，Agent 可以提出这两个候选交付物，并说明哪些选择会改变输入或输出，例如是否保留速度、要记录哪些热力学量、采样间隔及单位。已明确的温度、时长和已委托的默认选择可以直接复用。

## 现有设计的判断

| 对象 | 现有实现与职责 | 对规划的影响 |
| --- | --- | --- |
| 工具功能 | 工具包给出必需和可选端口、类型、格式、默认行为、参数、环境及操作。原生适配器另有引擎契约。 | 可以倒查候选生产者。具体引擎模式、输出开关与实际文件仍需核对。 |
| 工具组 | 编译器按精确包版本解析端口，检查格式、必需性、未知来源、环和最终产物，保留冻结定义。 | 可复用的连接有机器依据。`depends_on` 还允许表达纯先后约束。控制顺序可使步骤进入拓扑序，只有资源绑定能证明两步交接了某项产物。 |
| 会话流程 | 原有 `steps` 是表单分组。`parameters.engine` 与 `parameters.files` 描述当前阶段。五个界面阶段描述填写、复核和运行进度。 | 用表单标题或显示顺序画连线会把“设置温度”“选择资源”画成程序，也无法区分重复运行、分支或多个最终交付物。 |
| 工作区与运行 | 工作区组织输入与产物，已支持的执行路径绑定项目、配置和输入快照。worker 保管运行身份、状态与产物。 | 图中“需要轨迹”是规划事实。下游实际读取哪一份轨迹，必须落实到对应运行和产物身份。 |

工具、工具组与持久化运行的分工适合保留。过去的缺口在会话目标与可执行工具组之间，尤其是“为什么需要这个文件”“它由哪次调用提供”“某个交付物是否还有缺口”。引擎输入契约的覆盖范围也不对称，例如 `gpumd.md` 声明必需输入，实际轨迹和热力学输出还取决于保存的控制文件。[工具声明](../../contracts/tools/tool-package.schema.json) · [工具组编译](../../contracts/tools/tool-group.mjs) · [引擎契约](../../contracts/tools/engine-contracts.json)

## 同一套资源关系如何支持两种方向

每份初始输入、中间产物和目标产物在流程内有稳定的资源 ID。每份资源可用 `requirements` 保留可核对的要求，例如单位、列名、采样间隔和时间覆盖。节点详情和会话确认草稿会带上这些要求。每次程序调用有独立的步骤 ID，并通过具名端口引用这些资源。同一产物可以同时交付给用户并被多个分析步骤读取。重复调用同一个程序使用不同的步骤 ID，新生成的产物也有独立身份。输入文件同名不能证明它们来自同一次运行。

- **倒推用户还要提供什么。** 从每个目标找到其唯一生产者，递归访问该步骤所有输入。到达边界时检查当前参数绑定。缺值、缺少生产者、待确认的推测、与目标脱节的输入或步骤分别显示。用户可以先保存部分图。环、重复生产者、重复端口和不存在的资源引用会使整次修改被拒绝。
- **正推调用顺序。** 同一个遍历结果给出可重复计算的先后关系。假设同一轨迹进入 MSD 和 RDF 两次分析，两个分析都依赖 MD，彼此可以独立。汇总报告要等两份结果。运行顺序相邻不会自动添加产物边，领域分析能力须来自所选工具声明。
- **处理实时耦合。** MD 过程每步调用受力模型或在线偏置时，在 MD 调用框的上下中点标注同次运行内的组件。独立训练、模型导出和偏置构建各自有产物端口。用已导出的模型做 MD 时，模型文件走左侧输入，运行时的加载与求力留在框内。
- **跟随用户修改。** 初始资源引用当前表单字段。共享文件列表可按确切 basename 绑定，重排列不改变来源，多个同名候选需要消歧。推测的目标可在图中定位并回到原会话确认。用户改参数后，图与下一轮上下文按最新值重新判断缺项。

版本化 `roadmap` 通过原 `present_task` 保存到同一任务。只改表单时可以省略该字段。路径在表单中有唯一匹配即显示为已填写，文件内容仍由输入快照和消费者检查。图中的确认按钮把具体产物或输入写入原会话的消息草稿，用户可以修改后发送。旧草稿显示已知的当前引擎和文件，并提示补充目标。选中冻结的工具组后，总览也可直接查看该版本的原始端口连接、默认输入和固定值。[数据契约](../../contracts/workflows/roadmap.schema.json) · [按目标追溯](../../contracts/workflows/roadmap.mjs) · [Agent 规划 skill](../../agent/builtin-skills/studio-workflow-roadmap/SKILL.md)

## 规划完成后怎样交给确定性执行

对 MD 示例，目标约束先落实到实际控制文件的输出命令和采样间隔，再绑定结构、势模型、控制文件和选定引擎。若控制文件由 Agent 编写，现有文件工具负责保存和读回。用户只需提供已有材料、物理意图及需要自己决定的选择。在输入快照冻结后，适配器可以从同一版本生成调用，worker 记录作业与文件。涉及随机初始化或续算时，种子或重启状态也属于输入。用户要求只交付轨迹和热力学序列时，两项均需与实际产物逐项对应。

| 转换 | 已实现的行为 |
| --- | --- |
| 目标 → 规划图 | 每个目标保留原始文字要求，可附样本数、时间覆盖、字段与单位等机器判据。Agent 从目标反查初始资源和中间端口。 |
| 规划图 → 冻结调用 | “按流程图执行”显示原始需求、节点版本、调用命令、参数、原生 MD 控制命令、环境及输入来源。确认时 worker 核对快照摘要并保存初始文件副本。未来的输入锁定生产步骤与输出端口。重复确认同一快照返回同一次执行。 |
| 上游产物 → 下游输入 | 本地 worker 从 SQLite 恢复流程，沿资源边调度独立作业。绑定运行的退出回执和实际文件通过检查后，登记输出端口的路径、字节数、SHA-256、实测特征和生产 run ID。下游据此复制并校验。数密度程序在解析轨迹的同一读取流中计算哈希。 |
| 运行完成 → 交付 | 每个目标和原始要求各有结果。已满足要求、条件不达标、产物缺失、文字要求待人工判断均可分别显示。执行回执保留原始文件位置、消费证据与实测值。 |

本地 GPUMD 原生 MD 与 CPU 逐帧原子数密度分析已接通，可以为两个节点选择项目内不同的登记环境。其他工具组可复用图调度、输入快照、产物交接和逐项验收。选用已保存的组时，定义版本、步骤、包版本、实际命令和端口绑定都须吻合。重复调用和纯先后约束各自保留。

托管 SSH 整图执行绑定原作业服务、项目和所选 Slurm/LSF 队列。确认后，各节点使用冻结的调用和输入，在已分配的会话目录执行。已激活的资源私有工具可通过 `private.<id>` 参与。作业被队列接受时记录提交回执，计算完成后另有退出回执。隔离调度命令测试已覆盖两种队列的成功、计算失败和提交答复丢失后恢复。真实站点的队列策略、计算节点环境和科学结果需在目标资源上独立验证。[集群图执行器](../../backend/worker/studio_worker/workspace/roadmap_cluster.py) · [原验收范围](../releases/aimatterlab-cluster-workflows-unreleased.md) · [本次复核](../releases/aimatterlab-workflow-repairs-unreleased.md)
