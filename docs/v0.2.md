# v0.2：对话、审阅和设置改进

更新日期：2026-10-05。新版便携程序为 `release/GPU Sampling Studio 0.2.0.exe`；旧 v0.1 文件仍保留，使用新版才能获得以下改进。

## Codex 对话设置

右侧「Effort」从实际 `model/list` 的 supportedReasoningEfforts 获取选项，切换模型时校验支持范围，随 turn/start 发送所选 effort。模型与 effort 偏好保存在本应用中。

「上下文」可填 token 预算和自动压缩阈值。留空继承默认配置；压缩阈值必须小于明确设置的预算。点击应用会重新启动本应用自己的 app server 并恢复当前会话，不修改全局 config.toml、账户登录或独立计算作业。

实际有效窗口及当前用量来自 thread/tokenUsage/updated。本机真实测试设置 131072、262144 tokens 后，服务分别回报 124518、249036 的有效窗口；不能把配置值当作模型容量或实际窗口。

相关接口依据 [app server 官方文档](https://learn.chatgpt.com/docs/app-server) 和 [配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)，固定协议版本仍为 0.160.0。

## 任务审阅流程

1. Codex 准备输入文件并调用 prepare_run / resume_run，返回未执行草稿。
2. 工作区自动打开对应 MD、Bias、增强采样、NEP、HotPP 或分析模块的独立标签。
3. 检查名称、注册环境、GPU、时限、科学参数 JSON，以及真正要执行的输入文件。文本输入可在 Monaco 修改；模型等二进制输入显示 SHA256。
4. 点击「确认并执行」，生成新的不可变快照，重新验证，并仅在验证通过后提交。
5. 日志和结果在同一任务标签继续显示。后续依赖任务同样需要单独审阅。

旧草稿保留审计记录，标记被新的审阅版本替换，并可以跳转到新版本。修订的幂等标识绑定原任务和修改内容；已提交或未知任务不会修改输入或自动重复执行。

MCP 不再公布 validate_run / submit_run，并在服务端拒绝旧会话缓存中的这两种调用。草稿准备与项目输入写入可以在原项目授权内自动完成；模型的 shell/unified_exec 关闭。权限依然由服务端检查，Agent 不能修改授权。

重新连接时按 runtime 哈希升级本应用同根目录的作业控制服务；仅核实并替换控制进程，独立 runner 与已提交作业继续运行。

## 分类设置

| 分类 | 内容 |
| --- | --- |
| 外观 | 深浅主题、界面字体、界面字号 11–20、代码字号 10–28、终端字号 10–24 |
| 语言 | 简体中文、English，界面即时切换 |
| Agent | Codex 路径、工作目录、对话设置和人工执行规则说明 |
| 计算连接 | WSL 发行版、服务目录及端口 |
| 技能目录 | 原位置 SKILL.md 的附加发现目录 |

外观立即预览，保存后保留。Monaco 与 xterm 各自应用字号；界面文字随界面字号缩放。用户输入、文件内容、引擎日志及科学标识保持原文。连接设置保存后重新连接 WSL 生效。

## 本轮验收

- 6 项 Node 测试，22 项 WSL 服务测试。覆盖 MCP 不能验证/提交、输入修订、不可变来源、重复请求与已提交任务边界。
- 真实模型调用：所选 effort、两种上下文预算、会话恢复、MCP 输入写入与草稿创建。模型停止后任务仍 draft / not_run；旧 submit_run / validate_run 请求被拒绝。
- 桌面交互：实际模型创建的草稿作为数据，通过模拟工具完成通知测试自动路由；点击按钮前未运行，修改 seed 后点击按钮得到真正 succeeded 作业及日志。这一小任务仅测试 CPU 托管，不能称为新的 MD 科学验证。
- UI：分类设置、中文/英文切换、界面字体、三个字号保存、实际模型目录、上下文设置应用、Monaco 输入审阅、xterm PTY、科学图片及两个窗口尺寸。
- 本轮不改动科学引擎或其现有分支。原 23 项科学短任务证据见 [v0.1 验收](acceptance.md)，没有重新训练模型或扩大科学结论。
