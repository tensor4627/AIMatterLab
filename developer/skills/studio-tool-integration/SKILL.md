# GPU Sampling Studio 工具接入

与软件开发者协作，在指定工作空间生成 `工具名-package`。包内保留原软件的 Git 仓库，并在原仓库之外生成交付 skill 和测试重定向入口。`工具名` 为占位名称，不指某个特定软件。

本 skill 是接入指导，产出的包根 `SKILL.md` 是指导后续 Agent 安装、使用和测试该工具的交付 skill。接入判据仍为：五项工具定义齐备，能够完成安装并通过测试用例；包目录存在不代表 Studio 已具备对应运行适配器。

工具接入面向开发者，验证工具在声明流程中的可用性。工具配置面向用户，在其真实环境中安装、配置、测试后生成执行 skill；本接入流程不预造用户环境的执行 skill 或配置通过结果。

编写交付材料时，阅读 [交付指南](references/deliverables.md)，使用其中的包结构、交付 skill 内容、重定向约定和结果记录格式。示例中的包外层约定不约束原仓库内部布局，也不是 Studio 已实现的注册协议。

## 明确软件和功能范围

读取目标仓库的开发约束、源代码、公开接口、安装说明及已有测试，确认实际版本、Git 提交和本次接入范围。记录已有接口、文档、测试和资源的真实路径，优先引用原有材料。

列出本次工具声明提供的各项功能及其实际入口，建立“功能 → 输入输出 → 环境 → 调用方式 → 原测试位置 → 包内测试入口”的对应关系。范围不明确时，与开发者确认需要纳入的功能；不能默默删掉失败功能来制造接入通过。声明功能均须有实际实现和最小测试。

接入不改写或重排原仓库的源码目录，不往其中添加 Studio 接入材料。保留未提交修改、已有配置和真实任务。仅要求设计或准备材料时，将实际安装和测试记为 `not_run`；原程序缺陷或缺失功能单独报告，不通过修改源码把接入工作扩大为软件开发。

## 构成交付包

在开发者指定的工作空间创建 `工具名-package`，包含原软件 Git 仓库、包根交付 `SKILL.md` 和 `工具名-tests`。已有包内仓库可直接复用；首次获取仓库时保留其原有结构，不移动或覆盖开发者正在使用的工作树。

将补充说明、薄封装和补充测试写在包内原仓库之外。它们以包根为基准定位原文件；不要要求原作者把文档或测试搬到指定源码路径。

交付包包含实际需要的源码和测试资源，不能仅引用原开发者机器上的另一个目录。安装环境和任务输出由所选计算资源和工作目录管理，不要求随源码打包。

## 定义输入输出及参数优先级

按功能明确必需输入、可选输入、必需输出和可选输出，说明适用的类型、格式、单位、约束及依赖关系。每个可选项须有可执行的默认值或明确默认行为；可选输出也须说明默认是否生成及保存位置。

说明输入资源如何导入或引用、输出如何定位和保存，以及工作目录、命名和覆盖规则。交付 skill 和人类操作说明均须包含一致的输入输出契约；可以链接原仓库已有说明，并在包外层补齐缺项。

根据参数重要性、更改和调整频率确定展示优先级，标出优先向用户展示的参数，以及放入二级菜单的参数，并简述划分依据。核对已有软件默认值的实际来源；无法合理给定默认值的必需科学选择应明确列为必填。

## 声明环境并提供程序获取方式

声明各功能所需的平台、软件和依赖版本、CPU/GPU 要求、并行能力及最小运行配置。区分必需条件、可选能力和已验证范围；仅在相关时列出 CUDA、驱动、模型格式或工具链约束。

将实现全部声明功能的原仓库纳入包内，说明其来源、对应提交，以及实际获取、构建和安装方法。不能依赖开发者机器上的隐含路径或预装文件。需要构建时使用外部构建目录或隔离源码副本，避免将生成物写回包内原仓库。

开发者接入验证使用已有授权范围内的验证环境，记录声明功能和流程的实际覆盖范围。用户使用的计算资源、队列及真实安装配置由后续用户配置阶段确定。不要自动切换其他科学引擎的分支或改写已有环境登记；显式选择的后端不兼容时报告失败，不静默降级。

## 生成交付 skill 和操作说明

生成可独立使用的包根 `SKILL.md`，按 [交付 skill 内容](references/deliverables.md#交付-skill-内容) 填写真实工具名、用途、软件提交、接口与文档定位、环境、安装、输入输出管理、测试和失败处理。不能用本接入指导原样充当交付 skill。

交付 skill 及其配套材料必须可迁移：使用相对于包根的资源定位、通用依赖与安装步骤，并将目标设备和输出目录写为调用时选择的配置。开发者的绝对路径、主机、队列、账户或凭据不固化到交付 skill；实际验证结论只保留其范围和证据说明。

人类操作说明可保留在原仓库的实际位置，并由交付 skill 定位；缺少内容时在包外层补充。说明应覆盖用途、安装、输入准备、参数设置、运行、输出读取和错误处理，并能找到包内最小测试入口。

交付 skill 可以调用真实 CLI/API；若软件提供 MCP，则按其实际实现说明启动、参数和返回。它须足以选择功能、准备输入、调用程序、定位输出、判断完成或失败及执行测试。相对路径及调用所需工作目录必须明确，不能只写一组文档链接或编造尚未实现的接口。

接口应受其已有项目和资源授权约束；接入材料不授予额外文件访问或计算权限。需要接入 Studio 的实际接口时，检查当前实现再编写适配，保留其人工审阅和正式作业执行边界。

## 建立测试重定向入口

在包内提供 `工具名-tests` 总目录、整套测试介绍 Markdown 及各功能测试子目录。该目录是统一入口，可以将测试流程重定向到原仓库中作者实际放置的位置。详细结构见 [测试包要求](references/deliverables.md#测试包要求)。

每个功能子目录提供最简说明及必要的简短脚本或重定向入口，明确原测试、输入资源、工作目录、命令、预期输出和通过标准。优先薄调用已有测试；缺少检查时可在包外层补充测试或输出断言。不要复制维护同一套原测试，也不要仅打印固定成功文本。

测试代码、模型、数据、结构、配置和参考文件可以留在包内原仓库的任意已有位置，测试入口通过包内相对路径定位。需要补充的资源可以放在测试入口旁。完整性边界是整个 `工具名-package`，不要求资源集中在 `工具名-tests`；指向包外私有文件或只有下载地址的重定向不满足完整交付要求。

最小用例用于检查工具的输入输出契约、安装和环境配置。按功能和声明的执行方式设置有界规模及资源，不以一个 CPU 用例证明 GPU 或并行方式可用，也不以短例证明科学精度、收敛或生产适用性。

## 开发者接入验证

在已有授权范围内，按交付 skill 和测试入口完成安装及逐功能测试。检查整个包移动后重定向仍可解析，实际调用与包内仓库版本相符。若原测试会写回源码目录，优先配置外部输出或在隔离副本运行，记录实际使用的源码和测试身份。

对声明的计算流程核对从最初输入到最终产物的实际调用和资源匹配；复用已有最小用例完成相应流程验证。只验证了单工具功能时，按该范围记录，不据此声称未检查的工具组合可用，也不自动运行无关的完整科学矩阵。

使用新建且受 Git 忽略规则保护的运行目录保存实际输入快照、日志、输出和测试记录。检查接入前后的原仓库状态，确认未因生成接入材料或测试而改动源码。运行输出及私有连接信息不混入公共交付材料。

逐项记录安装和功能测试的版本、实际环境、命令、退出记录、输出检查、判定和证据位置。使用 `passed / failed / blocked / not_run`：实际检查通过才记 `passed`；执行或输出检查失败记 `failed`；缺少必要条件记 `blocked`；没有执行记 `not_run`。所有非通过项说明原因及下一步，不能用历史证据冒充本次测试。

修复后只重跑受影响的安装或功能测试，保留首失败和修复后的记录。作业状态未知时核对原任务，不自动重提。接入多个功能不意味着需要运行未受影响的 Studio 全套软件或科学测试。

## 保持仓库版本和重定向一致

在交付 skill 中记录包内原仓库对应的提交，以及安装、接口、说明和测试路径映射。在开发者授权下同步包内仓库版本后，核对这些映射；路径、接口、依赖或通过标准变化时更新包外层材料。

源码和原有测试随原仓库同步，生成的交付 skill、重定向入口和测试结果须绑定本次实际版本。仓库同步成功不等于安装或测试通过。已有任务引用的包和环境保持原版本，在候选包或隔离副本中验证升级，不原地改变它们依赖的代码或程序。

## 向用户配置阶段交付

交付 skill 说明如何在用户选择的真实计算资源上安装、配置并完成对应测试。用户配置成功后，由该阶段的 Agent 根据实际环境生成执行 skill，收录正常操作所需的实际入口、环境、软件版本、输入输出、参数、命令和失败处理。

执行 skill 是该环境的日常工具入口。它生成后，之前的交付 skill、安装 skill 和配置指导由用户配置流程封存，保留版本与记录，不再自动读取。只有发生 bug 需要修复，或软件更新需要重新安装时，才重新使用所需封存指导并更新执行 skill。交付 skill 不应要求日常任务重新读取本接入指导或整套安装材料。

## 交付和接入判定

交付 `工具名-package`：保留原仓库布局、生成独立交付 skill 和测试重定向目录，并补齐五项工具定义。原有文档、接口和测试通过明确路径复用，额外接入材料位于包内原仓库之外。

同时交付逐功能对照和安装、测试结果，指出剩余缺项。只有五项定义满足，实际安装、所声明功能及流程的测试均通过，才能按本次明确的功能、流程、版本和环境范围报告接入通过。材料完成而环境或测试未通过时，报告材料完成及具体缺口。

若任务还包含 Studio 内部注册或适配，另外报告其实际实现和验证状态；工具包检查不替代运行适配器、前端或共享接口变更的验证。
