# Choose a method from the requested result

First identify the physical quantity the user wants, their available inputs, and how the result will be used. A question about a tool or method can be answered before connecting a compute resource. Follow the selected function for file formats, model classes and execution details.

| Requested result | Inputs and scientific choices | Route and evidence to inspect |
| --- | --- | --- |
| Trajectory, thermodynamics or atomic number density | Check species, cell, periodicity and potential compatibility. Specify the ensemble, timestep and output cadence. | `md.pydyn` or `md.gpumd`. Check the actual frames, timestamps and thermodynamic fields. For `analysis.number-density`, the observable is atom count divided by cell volume. Mass density additionally depends on atomic masses. |
| Free energy along a collective variable | Define the observable, atom groups, units, periodic domain and sampling temperature. Identify the specific bias method and what history or weights were recorded. | `pygas.cv` / `pygas.bias`, then the selected sampling engine. Use `analysis.wtmetad` for well-tempered metadynamics and `analysis.opes` for OPES. Report sampled support and stability over time before drawing a free-energy conclusion. Estimating physical rates from biased trajectories requires a separately justified kinetic method. |
| Minimum-energy path or barrier | Initial and final structures, atom correspondence, cell convention and a potential applicable to both endpoints and the intervening geometries. | `neb.gpumd`. Inspect image energies and optimizer convergence along the path. A finite-temperature free-energy barrier is a different observable. |
| Interatomic potential for simulation | Check units and conventions for the reference energies, forces and any available virials. Split structures into independent sets, accounting for correlated frames. | `training.nep` or `training.hotpp`. Evaluate the held-out structures and report errors with units and normalization. Test the exported model in its intended consumer before deployment. |
| Electronic Hamiltonian or band structure | Identify the representation, orbital basis, reference electronic-structure data and target output. Check data/checkpoint compatibility. Band comparisons additionally require consistent energy alignment and k-path. | Look up HotHam through `software.catalog`. Use the pinned delivery's specific dataset, training, prediction or bands guide. A force-field training loss measures a different target. |
| DFT labels or active-learning candidates | Preserve structure identity and parent dataset. Specify the labeling method and which configurations require new data. | `external.dft`, `learning.nepmaker` and `learning.activemiao` expose planning guidance. Record which labels were actually computed and imported before evaluating a retrained model. |

Use evidence at the level the user asked for. A source or manifest describes a supported procedure. A successful environment probe identifies an executable or import. A bounded case shows that specific inputs produced the checked outputs on the selected target. Scientific claims additionally depend on the reference, sampling, convergence or validation data relevant to the observable.
