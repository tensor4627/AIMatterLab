# Recover an SSH connection or channel

When a resource lists `developerWorkspace: true`, the desktop user selected its verified SSH workspace under **Settings → Agent → Action approvals → Full workspace access** (**设置 → Agent → 操作审批 → 完全权限**). Use its exact `resource_id` for workspace tool and terminal tests and read the command receipt. Effects outside the workspace or effects that cannot be verified require desktop confirmation. Structured submit and cancel operations still follow the current human request and the worker’s registered project and target.

A submitted option such as **Use “Lab” (ssh:profile-id)** selects that listed target for the current conversation. Continue the requested acquisition with its resource ID and access. The same rule applies to the dedicated resource picker. An answer that only requests a plan leaves the terminal unopened.

If a terminal request returns `terminal_unavailable`, use the reported `code` and `leaseStatus`. Follow its `retry` with `access: "service"` on the same resource when the requested operation can use the service. A failed or unconfirmed terminal attempt provides no shell. Preserve unknown state and avoid repeating the same terminal attempt. If no safe retry or suitable granted channel remains, report the actual tool failure. A channel failure alone calls for checking the original capability. Use the current tools when old chat messages or guides describe a different route.

On the original saved SSH profile, **继续原连接** opens a live SSH terminal. Reopening a live SSH terminal restores the same verified channel. Use **核对原连接** when the last observation is awaiting verification. If the original sign-in is pending, continue that attempt. The user can view its prompts and enter authentication responses only in the private terminal. Waiting for authentication or a timed-out check leaves the outcome unconfirmed.

While the SSH terminal shows **等待登录回执**, the desktop looks for the terminal with that sign-in request ID. The user can choose **重试** to retrieve the same attempt. If the hosted connection is confirmed lost, the user can choose **重新登录** in the SSH terminal panel for the same saved profile. The desktop verifies the remote host, account and workspace and restores eligible leases for their original conversations. Read the current resource and terminal receipts. If the user explicitly requests renewal, use the verified selection saved for this chat. Reconcile an unknown attempt or existing job using its original run and scheduler identities before any further execution.

Manual sharing applies only when the user explicitly shares an existing visible terminal. Use `list_shared_terminals`, `read_shared_terminal` and `write_shared_terminal` within that actual grant. For explicit service setup or repair use the `cluster.connection-setup` route for [job-service-connection.md](job-service-connection.md).
