# Observe recorded runs without resubmission

For an acquired worker-managed resource, prefer `read_compute_run_status` and `read_compute_run_log` with its exact returned resource and run ID. For a site-native job, observe the original scheduler ID on the same resource. The standalone script below covers recorded cluster runs on its supported worker interface.

Use `scripts/cluster-reconcile.mjs` from a source checkout to inspect an existing manifest. A portable desktop distribution provides the same standalone file at `<resources>/studio-tools/cluster-reconcile.mjs`, beside the public `studio-skills` directory. Use that physical file when no checkout is present; it uses only Node built-ins. It never creates, prepares, submits, cancels or registers a run. A disconnected or unknown run keeps its recorded identity. A successful collection is a file-transfer result, not a new scientific validation.

The manifest is a private JSON object with `schema_version: 1` and `runs`. Each run has its recorded `run_id`, optional pinned `job_id`, optional `names` containing exact relative output names, and optional `previews` containing the selected text results to verify independently. With explicit `names`, every requested preview must be among those names. Without `names`, the worker's bounded default output allowlist applies. No connection, account, path-to-credential, queue, token or executable fields are accepted.

Import `reconcile({manifest, request, timeoutMs, pollIntervalMs, requestTimeoutMs})`. The request adapter is `request(method, target, data, {signal})`; a local controller can implement it with the existing typed `worker.request` IPC. Only POST `/api/cluster/status`, `/api/cluster/collect` and `/api/cluster/result` are called. Observe the same run and scheduler identities; disagreement fails visibly. Collection occurs only after an actual terminal state, followed by exact UTF-8 byte-size and SHA-256 checks for the requested text previews. Binary or oversized previews are reported `not_run`, never silently replaced by another file.

For an optional standalone controller, pass an explicit manifest file to `node scripts/cluster-reconcile.mjs --manifest <private-manifest.json>`. Set `STUDIO_WORKER_URL` and `STUDIO_WORKER_TOKEN` in that caller's environment. The URL must be a loopback worker origin; credentials cannot be supplied in the URL or CLI arguments. No endpoint, port, account or token is embedded in this tool. The HTTP adapter refuses redirects and bounds response bytes. Do not copy environment credentials or this private manifest into a release or remote job.

Observation defaults to a bounded one-minute window, adjustable with `--timeout-ms`, `--poll-ms`, and `--request-timeout-ms`. Connection uncertainty and observation timeout return `status: unknown` while preserving the last actual `run_status`; an unverified collection stays `not_run`. The CLI emits only structured status codes and redacted file identities/hashes, not response bodies, paths, text or transport errors. Exit code 0 means the selected observation/collection/preview scope passed, 2 means uncertainty, and 1 means an explicit failure. A later observation reuses the same manifest; it never resubmits the job.

Raw evidence and manifests belong to ignored runtime storage. The user or local controller still decides when to observe and where to keep the report. Missing scientific evidence must remain missing; the script preserves the worker's scientific-validation status separately.
