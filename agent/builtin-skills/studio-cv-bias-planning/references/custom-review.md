# Private CV definition and review

## Missing CV

When the catalog and compatible approved user library cannot express the observable, explain the precise gap. A capability or formula-discussion question uses the `pygas.custom-cv` route and the actual catalog; do not preload the full PLUMED reference index. Before constructing or comparing a concrete CV/bias composition, explicitly load the matching pygas.cv or pygas.bias functional guide, including its bounded PLUMED reference, and verify actual source semantics. Research and propose a formula with symbol meanings/units, atom groups/order, PBC/domain, reducer, differentiability and singularities. Ask for the user's explicit formula confirmation before generating its implementation. A model-written `approved:true` is not human approval.

Present the confirmed formula and its own typed parameter list. Keep implementation in the AIMatterLab-managed private custom-CV library, outside sibling engines and release code. Never edit an engine branch or add a native MD force hook. Only the approved CV primitive may extend the existing pyGAS graph; pyGAS still owns procedures, bias, history and deployment ABI. If the installed AIMatterLab version lacks the custom-library tools, state that exact limitation instead of inventing a tool or bypassing the framework.

For this private custom CV, obtain formula approval for the actual mathematical spec, schema, domain and semantics. Review the concrete implementation and immutable snapshot before approving the build or numerical checks for that revision. A revision records formula/schema/code hashes, dependencies, output metadata and target/source identity. Changed formula/schema/domain invalidates formula consent; changed code requires implementation review and new numerical evidence. Adjusting parameters within the agreed definition preserves formula consent but invalidates affected parameter-scoped numerical/artifact/prepared-run evidence. Do not repeatedly ask the user to approve an unchanged formula. Reuse by immutable revision and display the original validation scope; listing metadata never imports or executes its code. Private user-library source has its own explicit provider sharing boundary.

## First-definition numerical evidence

Prepare bounded tests and use the actual private-CV execution approval for the selected revision and target. Check applicable reference or analytic-limit values, shape and finiteness, neighbors, PBC and coordinate symmetries. Check autograd against finite differences away from singularities and test strain and virial when used. Verify serialization and real target reload. Store actual reports tied to code, parameter, structure and environment hashes. Missing or failed evidence remains `not_run`, `blocked` or `failed`.

Derivative coverage needs an exercised response: nonempty history or nonzero energy can still produce zero or cancelling forces. Record actual force/virial magnitudes alongside FD errors, tolerances, sampled atoms and the strain convention. If a regression specifically claims nonzero-response validation, select a versioned synthetic validation input distinguishable from zero at those tolerances; keep the definition, artifact and tolerances fixed and retain weak cases. Validation history is separate from restart history. Compare the serialized artifact's actual target response with an independent reference; analytic fixture design alone is not execution. Physically valid zero forces are not a universal failure.

Offer a separate representative stable-phase/reference comparison when useful. Explain the objective, expected discrimination, required structures and cost, and let the user decide whether to run it. Do not invent a phase or call a local finite-difference check physical validation, universal suitability or FES convergence.

## Current custom-definition review flow

When a saved graph exists, call `read_pygas_workflow(workspace_id=studioTaskId)` before changing it. This reads the current canonical pair and its exact CAS receipt. Do not reconstruct it from old chat summaries or old run controls. Generic file access is limited to the selected conversation and actual permitted files; a permission error is not evidence that the project is missing.

For a scientifically missing/non-equivalent CV, use `propose_custom_cv` to save a formula DATA draft in this conversation. Include `spec` (formula, allowlisted expression, symbols/units/domain, actual zero-based atom_selection, fixed output_size, typed parameters, PBC, invariances and singularities), `values`, and `library_review` (the actual public catalog source_files, 1..8 inspected CV names, and the precise non-equivalence). This tool never approves, generates implementation code, checks numerics or executes. If this conversation already owns a custom entry, update that same ID through the main-derived current CAS; do not create another entry to avoid a conflict or missing sharing.

Use the task's custom-CV panel for formula confirmation after the typed draft has been saved. A request limited to discussing a formula can end in chat. Only then does AIMatterLab generate deterministic inspectable PyTorch primitive code, which receives a separate human code review. Typed value changes preserve unchanged formula/code consent but clear numerical readiness and current-version provider sharing. Formula/schema/domain changes clear all affected approvals. The private library has its own Git history outside engine and release sources; never copy it into an engine or public skill.

The human then confirms one exact CPU check in the native dialog: selected registered interpreter/runtime receipt, actual structure, formula/code/value hashes, sampled derivative atoms, independent reference, 60-second and output limits. Exact pair distances on supported orthogonal geometry may use the separate ASE reference. Other formulae need a separately justified `.cv-reference.json` asset with schema_version=1, kind=independent_cv_reference, cv, structure_sha256, spec_sha256, parameters_sha256 and provenance {kind:declared_independent_method, method:...}. Explain the independent method; an AI-generated file is not human-supplied or automatically audited. The native confirmation adopts its exact values/method/hash. Missing reference means self-consistency only and blocked reuse.

After actual saved/reloaded numerical and reference checks pass, the human may attach the primitive to this SAME graph. A new primitive is initially unwired; explicitly connect actual runtime pos/cell/side_array ports and the ordered collector using pyGAS's graph compiler. If the conversation has no canonical graph yet, the human may create an empty CV-only graph in the task panel; this creates no bias or artifact and is not a replacement for Agent planning. The same graph can then receive the approved primitive. The advanced graph controls expose only current compiler-supported modes and input/collect/output/reduce nodes. Mode changes preserve nodes and values, invalidate review, and require explicit compatible connections; they do not convert a graph automatically. For a hand-built graph, add the actual catalog Neighbor node and its source-declared required parameters even when the custom primitive does not read neighbor outputs. A reduce node needs an explicitly selected operation before source rendering. The optional managed output-name action fills only a missing pt_path with an AIMatterLab technical default and creates no file; format, target preflight and execution gates remain unchanged. Preserve bias, history and deployment inside pyGAS. Full-bias build/reload, target CUDA ABI, force/cell derivatives and actual engine execution retain separate evidence; serialized artifacts must be checked in the actual target. The current source-proven private cell route is one fixed-size scalar primitive directly collected into the reviewed MetaD-family/fixed-wall graph; unknown, mixed, OPES or AOTI private routes remain explicitly blocked pending their own reviewed contract. Never select a legacy/zero-bias fallback to call them validated.

`read_custom_cv` returns only this conversation's current exact definition after the human enables sharing with the selected provider. A current-definition checkbox does not authorize old code/parameter versions, old runs or other project files. After revocation, stop new reads and explain that provider history already shared cannot be erased by AIMatterLab. Human local review/edit/cancel remains available without provider sharing. Stable-phase discrimination and physical suitability are optional separately discussed experiments, never a green badge inferred from finite differences.
