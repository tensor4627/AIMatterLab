# Fixed umbrella sampling and tagged coordination

Define the observable first. For tagged atom \(i\) and selected ligand atoms \(L\), a dimensionless coordination is \(s(\mathbf R)=\sum_{j\in L}w(r_{ij})\). Use image-aware distances in the actual periodic cell and the declared directed center→neighbor convention. Check that the tagged index survives the input atom order. Count each intended neighbor once and exclude self pairs. For molecular ligands, record whether the quantity counts marker atoms, whole ligands, or centers.

## Match the source example to the observable

The public `build_umbrella_cn.py` uses `PCVectorLB`, `CoordNum(n_atoms, LessThanCubic(...))` and `.mean().reshape(1)`. Its one scalar is the mean over all centers from the supplied edge list. It uses a fixed harmonic `FlexibleWallBias`. The demonstration has no species selection or volume component. Check the named example and the exact revision before describing its observable. The separate examples for other CVs have their own graphs. [Release-pinned umbrella example](https://gitlab.com/tensor4627/pygas/-/blob/ba5787380181304a0e4c75578c2ecff736737e18/agents/skills/pygas-build-bias-model/assets/build_umbrella_cn.py), [audited public snapshot](https://gitlab.com/tensor4627/pygas/-/blob/49bbead1df075e87df16149da475cec5b2d92845/agents/skills/pygas-build-bias-model/assets/build_umbrella_cn.py).

For a tagged CV, keep directed edge rows with `edges[:, 0] == tag` and the requested ligand selection at `edges[:, 1]`. Compute the vectors from those same rows with the neighbor module call `neighbor(pos, cell, edges)`. Call the `CoordNum(n_atoms, switch)` module with `(vectors, edges)`. It scatters by center index into a vector of length `n_atoms`, including zero entries for centers without selected edges. Even after filtering all edges to the tagged center, a mean of the vector divides the tagged value by `n_atoms`. Use `cn[tag:tag+1]` from that vector as the length-one CV with the original atom indices. The number of matching edges can vary with the frame and cutoff. Check that the graph can express the selections and gather operation. Discuss an explicit formula if the catalog lacks a suitable composition. [Pinned neighbor call](https://gitlab.com/tensor4627/pygas/-/blob/ba5787380181304a0e4c75578c2ecff736737e18/base/neighbor.py#L21-L47), [pinned per-center accumulation](https://gitlab.com/tensor4627/pygas/-/blob/ba5787380181304a0e4c75578c2ecff736737e18/base/colvar.py#L47-L76).

Use the tagged center–ligand distance distribution or conditional RDF to place the taper relative to the intended shell. A compact \(C^1\) choice is the pinned `LessThanCubic(d0, dmax)`, with \(t=\mathrm{clip}((r-d0)/(dmax-d0),0,1)\) and \(w=1-3t^2+2t^3\). Its value and first derivative join the plateaus at both ends. Choose \(d0<dmax\) from data and cover the support with the real neighbor list. A raw rational \(w=(1-x^n)/(1-x^m)\) has the finite limit \(n/m\) at \(x=1\), so forcing it to zero there jumps. Verify value and gradient at the implemented cutoff and check a known coordination, a periodic image crossing, and a force finite difference. [Pinned CoordNum](https://gitlab.com/tensor4627/pygas/-/blob/ba5787380181304a0e4c75578c2ecff736737e18/base/colvar.py#L47), [pinned cubic switch](https://gitlab.com/tensor4627/pygas/-/blob/ba5787380181304a0e4c75578c2ecff736737e18/base/switch.py#L45).

## Choose and validate the windows

Use \(U_i(s)=\tfrac12 k_i(s-c_i)^2\). The referenced pyGAS implementation uses equal lower and upper bounds \(c_i\), equal constants \(k_i\), and zero step and growth terms. Its fixed bias is independent of the supplied history. Record which values are baked into the artifact and which inputs set them. Check the energy and force \(-k_i(s-c_i)\nabla s\) of the reloaded artifact on the authorized target. Work at the intended temperature and ensemble and record the structure, potential, CV and version identities. [Pinned bias-model contract](https://gitlab.com/tensor4627/pygas/-/blob/ba5787380181304a0e4c75578c2ecff736737e18/agents/skills/pygas-build-bias-model/references/bias-model-contract.md).

Use short pilots to find the relevant CV range, window means, widths and overlap. Near a locally quadratic stable window, \(\mathrm{Var}(s)\simeq k_BT/[F''(s)+k_i]\) when the total curvature is positive. At a fixed target width, negative PMF curvature calls for higher \(k_i\) than the flat-landscape estimate. Use observed overlap and force stability to refine centers and stiffness. Preserve equilibrium samples under each fixed bias with the correct window labels. Keep per-window inputs, seeds, outputs and restarts in distinct directories. If a native bias driver writes scheduled snapshots with this static model, use the equilibrated CV observations and static bias definitions for the PMF.

In the reviewed GPU-Sampling build, load the fixed bias via one `GASMD` declaration per window process. Write the associated `GAScfg.yaml` using one flat `key: value` setting per line. The pinned parser skips lines without a colon. [Pinned parser](https://github.com/bigd4/GPUMD/blob/bd719b98f1608e25477c63238c1f42d9a63d3bd1/src/main_sampling/gas-metad.cuh#L62-L90). Consecutive `run` blocks in that process keep the mounted potential. Reissuing `GASMD` appends another potential in sum mode and applies the bias twice. Measurement output commands such as `dump_thermo` are cleared after each block, so request those again for each segment that needs them. The CV log attached to the bias uses the active model and its configured cadence. Each independent process reads its own input and mounts its own bias once. For a fresh process continuing a fixed window, use the corresponding structure or restart and the same verified window model, and preserve segment and equilibration labels in the outputs. [Pinned run/parser](https://github.com/bigd4/GPUMD/blob/bd719b98f1608e25477c63238c1f42d9a63d3bd1/src/main_sampling/run.cu#L319-L350), [force finalization](https://github.com/bigd4/GPUMD/blob/bd719b98f1608e25477c63238c1f42d9a63d3bd1/src/force/force.cu#L338-L342), [measurement finalization](https://github.com/bigd4/GPUMD/blob/bd719b98f1608e25477c63238c1f42d9a63d3bd1/src/measure/measure.cu#L73-L92).

## Budget and reconstruct

Compute occupancy from the actual requested layout. With one window per physical GPU, one window needs its retained duration divided by its measured per-device rate. Sum occupied device time for all windows to obtain GPU-minutes. For identical windows, the ideal elapsed time is \(\lceil n_{\rm windows}/n_{\rm devices}\rceil\) times one window time. A changed per-device rate changes occupied time and elapsed time. Check peak memory against each assigned GPU separately. Equilibration, pilots, startup, I/O, unequal tails, retries and queue wait need their own evidence or estimates.

Use WHAM with equilibrated per-window histograms and bias functions, or MBAR with reduced potentials evaluated for each retained configuration under every window and the target state. A common unbiased energy cancels in the differences if temperature, Hamiltonian and ensemble agree. Obtain \(F(s)=-k_BT\ln P(s)+C\). Assess time correlation in the CV and slow orthogonal variables. Use decorrelation or a block/replica uncertainty analysis that respects the equilibration and correlation structure. Check overlap connectivity, block or replica agreement and sampling support before reporting relative PMF differences. For a gap, add or reposition a window, redesign a stiffness or collect more equilibrated data. Disconnected components have independent additive constants. Fixed-window PMF uses equilibrium reweighting with the static bias, while a time-varying WTMetaD history uses its own estimator. [WHAM method](https://doi.org/10.1002/jcc.540130812), [MBAR method](https://pmc.ncbi.nlm.nih.gov/articles/PMC2671659/).
