# AIMatterLab installation and existing-machine readiness

For a packaged desktop, start with its setup guide, **计算资源** and **账号与 API** for the part the user requested. For an explicit source installation or `reuse-existing` audit, read `INSTALL_AGENT.md`, `installation/manifest.json`, `installation/config.example.json` and `docs/one-prompt-install.md` in that checkout and use its actual installer interface and fixtures.

Discover available local runtimes, WSL distributions, explicit scientific environments and SSH aliases read-only. Keep discovered paths, account/connection references and detailed probe receipts in an ignored private configuration. Never request API keys, passwords or SSH key contents in chat. Try the selected existing provider with an actual model sentinel; missing account metadata or advisory auth flags cannot substitute for that capability check. Record account metadata availability separately from model access. When actual access requires authentication, the user completes login inside the isolated AIMatterLab profile; never copy another profile's credential files.

## Local Agent CLI discovery and optional installation

Use optional CLI discovery for Kimi or an explicitly selected legacy ACP installation that exposes it. Preserve a valid explicit CLI path, check the corresponding environment override and local Windows `PATH`/`PATHEXT`, then reuse a verified AIMatterLab-managed installation. Check the observed version and real ACP initialization. Resolve supported npm/pnpm shims to their declared JavaScript entry. For a compatible version difference follow the actual capability check and warning.

When the selected CLI is missing or incompatible, use AIMatterLab's login/connection entry in the same profile as the generated launcher. It presents **Recheck**, **Choose local CLI**, **Download compatible version**, and **Cancel**. Only the user's download choice starts the pinned official npm downloads. The main process verifies integrity, extracts without installation scripts, installs into the profile's own versioned cache, and reports real download/verification/installation/interface-check progress. Preserve valid manual paths, existing usable generations, credentials and local CLI configuration. Cancellation or failure is not successful installation; CLI readiness does not establish login or model access. The user completes authentication and the normal provider check separately. Do not install Agent CLIs on the cluster.

The `reuse-existing` audit remains download-free. If its selected provider is unavailable, record `blocked` and offer the separate user-facing installation flow; rerun the audit after the user has prepared the CLI. Do not silently enable downloads inside the audit or claim that dependency installation was exercised there.

For an authorized existing-machine audit, select the named `reuse-existing` action with fresh, separate ignored controller-state and Linux worker-root directories and `bootstrap.enabled=false`. Keep the private config outside both new audit roots. Unknown nonempty directories, root aliases and ownership-marker mismatches must block before any Service, registration or error receipt writes. This action enforces skipping downloads, environment configuration and dependency installation, even when ordinary desktop installation defaults enable them. Run its real target probe, selected bounded smoke cases and actual desktop/provider check. Save its isolated launcher and explicit source-summary scope; a model sentinel needs no scientific source context. Preserve the normal AIMatterLab profile, registered engines, branches, project grants and production jobs.

Treat target probing as observed interpreter/module paths and versions, CUDA availability, executable file identities and registered source revision/dirty state. An existing executable is not proof it can load a model, run CUDA, or satisfy a scientific contract. Never run an unknown native engine's `--version` just to probe it. Selected smoke cases must complete with actual process exits and asserted output receipts. A reference ASE MD case cannot validate PyDyn, GPUMD, sampling, NEB or training.

Installation handoff must use the same worker root and desktop profile as the generated launcher. Before declaring it ready, query the launcher's actual `list_environments` / `compute_readiness`, confirm the selected interpreter and native executable registrations exist there, and check the exact selected engine with `probe_environment`. A disposable acceptance worker's registrations do not configure the user's normal worker. Preserve existing registrations and project grants; add versioned environments rather than replacing CPU authoring or switching a PyDyn source branch. Register actual execution paths and retain runtime receipts for ordinary use. First connection also performs bounded discovery of existing local installations; absence from that search is a discovery limit, not a reason to reinstall. Ask about cluster use and import the chosen existing SSH reference, record SSH/scheduler discovery separately, and keep compute-node short cases blocked until the user reviews their queue/resources and submission. Never copy private addresses or credentials into the public installation prompt or repository.

Review selected case coverage without silently removing unavailable fixtures. Preserve `blocked` or `not_run` for missing environments, models or adapters. Keep the independently requested all-route scientific matrix separate from the installer's shipped fixture set. Never count historical runs or mock tests as current scientific runs. Preserve queued/running/unknown jobs and reconnect to their existing identities rather than resubmitting.

Report `reuse_readiness_success` only for the selected current checks. In reuse audit mode keep `dry_run=true`, `installation_success=false`, and explicit download/install/configure skips. A true fresh-machine install uses the regular configure/probe/smoke/desktop/finalize gates instead. Every invocation must really probe the selected environment and verify the provider. Completed smoke evidence is historical on re-entry: only an explicit `--reuse-smoke-receipt` choice may retain it with `cached_evidence=true` and its original observed time, and only with unchanged observed environment identity and clean registered sources. A new development round uses new controller and worker roots with no cached checks. Changed source/config fingerprints or observed environment identity require fresh roots; never overwrite markers or reuse active/unknown jobs to manufacture a fresh run. Audit receipts cannot later be promoted to fresh installation success by finalize.

The final public report contains only selected modules, statuses, evidence scope and limitations. Detailed paths, credentials, SSH/proxy endpoints and private logs stay private. Do not equate a built package, visible window, account record, or model-directory response with a real model reply or completed scientific calculation.

## Proxy and Electron download diagnosis

Read the selected checkout’s `docs/network-and-electron-install.md`. System Proxy, Rule/Global routing, and TUN are distinct. Startup now reuses explicit proxy variables first, otherwise reads enabled Windows static system HTTP/mixed proxy settings. Source Launch and the Python desktop installer prepare this environment before dependency/Electron downloads. Desktop Chromium and Agent children use the selected proxy, with loopback always bypassed. No system settings or credentials are persisted. PAC-only system discovery is reported explicitly; Chromium can handle PAC, while CLI/install subprocesses need an explicit HTTP/mixed proxy. For the locked @electron/get 5.1.0, enable ELECTRON_GET_USE_PROXY with HTTP_PROXY/HTTPS_PROXY and preserve loopback NO_PROXY. Discover the actual local HTTP/mixed port; never assume one, alter global proxy settings, expose credentials, or disable TLS/checksums. Verify the selected Electron version and effective mirror overrides before diagnosing the URL. A successful developer-node HEAD request does not validate the user machine, a complete download, or model access.
