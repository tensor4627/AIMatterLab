# Author a pyGAS graph

For enhanced sampling, follow the real pyGAS workflow, specialized CV/bias/OPES skills, catalog modules and graph renderer. Save the canonical graph and framework-generated Python, then build and reload the serialized artifact at its reviewed stage. Do not bypass pyGAS by hand-writing a native CV, bias, direct engine force hook or standalone PyTorch equivalent merely because it seems easier. Native/custom bypass requires an active explicit user request; a missing catalog capability instead needs a clearly scoped pyGAS extension decision. Even an explicitly requested alternate implementation must have a real supported consumer and its own validation; the request does not fabricate an adapter.

For molecular phi/psi, inspect the actual topology and the installed pyGAS torsion API. Report the selected ordered atoms and indexing convention. A molecule name is insufficient evidence for indices or sign; a coordination/distance example is not a torsion implementation. If topology yields competing assignments, preserve the candidates and ask about the scientific ambiguity.

For pyGAS graphs, read `inspect_source_project.graph_contract` before assembling the graph: `_mode`, `_node_ports`, `_edge_endpoint`, then `validate_graph`. These are hash-bound excerpts from the registered renderer, not a remembered schema. Use its node kinds, required input/output/neighbor/collect nodes and structured node/port endpoints; use the actual class catalog for CV and bias signatures. Do not guess a graph shape, retry `type` in place of `kind`, or invent ports from Python argument names. The concrete `render_pygas_workflow` result is the graph check; source inspection alone never claims the graph or serialized model is valid. If graph_contract is blocked or unavailable, report that limit and inspect the explicitly registered source instead of inventing compatibility.

Before a graph build, use `inspect_source_project(symbols=[...])` for the exact public CV classes when behavior or output rank is unclear. It returns bounded actual method bodies, including helper methods, from fixed registered catalog files; do not use `read_project_input` on a source repository. Read `_reduce_expression` and collector shape semantics. A source-confirmed zero-dimensional scalar must reach Collect as a length-one vector through explicit `reduce` operation `identity`; output_size=1 alone does not prove rank one. Read the actual class definition: PairwiseDistanceMean is a mean nearest-neighbor observable, not an arbitrary selected-pair distance. Never automatically choose `first` or silently reduce a vector to fix a shape error. Per-atom/vector CVs require an explicitly intended supported mean/sum or a source-verified fixed-shape adapter. Repair the same saved graph and regenerate matching source; do not replace a failing graph with unrelated handwritten source.

The AIMatterLab render wrapper also needs `graph.settings.atoms_path` for the actual authorized structure and `pt_path` for the selected artifact. It uses immutable run basenames and `workflow_path=workflow.json`; include the graph, source and structure in the task files. For version 2 TorchScript-only, set `artifact_formats=['torchscript']` and `deployment_backend='torchscript'`. Explicit AOTI or dual artifacts retain their selected formats and require actual compatible target/toolchain preflight, with no fallback. Rendering/source inspection does not prove serialized artifact load, tensor ranks or scientific correctness; the reviewed build and artifact checks remain separate.

Use the versioned public interface and upstream parameter names for the selected software. For a concrete CV or bias choose `pygas.cv` or `pygas.bias` in `read_scientific_skill`. For a missing CV definition choose `pygas.custom-cv`. Read the needed document by its advertised ID. Verify PLUMED equivalence against the selected pyGAS source. The custom primitive has separate formula, code and bounded numerical review.
